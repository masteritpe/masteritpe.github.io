## 1교시형 문제 풀이

<b>1. 다크 팩토리 (Dark Factory)</b>

* <b>개념:</b> 로봇, AI, 센서 등 디지털 기술을 활용해 사람의 개입 없이 24시간 완전 자동화되어 '불이 꺼진 상태'에서도 가동되는 미래형 스마트 공장입니다.  
* <b>핵심 요소:</b> 디지털 트윈(Digital Twin), 5G 특화망, 자율주행 로봇(AMR/AGV), AI 기반 머신비전.

<b>2. ATAM (Architecture Trade-off Analysis Method)</b>

* <b>개념:</b> 소프트웨어 아키텍처가 시스템의 품질 속성(성능, 보안, 가용성 등)을 얼마나 잘 만족하는지 평가하고 타협점을 식별하는 검증 기법입니다.  
* <b>주요 평가 요소:</b> 민감점(Sensitivity Point), 타협점(Trade-off), 위험(Risk), 비위험(Non-Risk).

<b>3. PMC와 PMO 비교</b>

| 구분 | PMC (Project Management Consultancy) | PMO (Project Management Office) |
| --- | --- | --- |
| <b>주체/성격</b> | 외부 전문 컨설팅 업체 (대행) | 조직 내부의 전담 상설 조직 (지원/통제) |
| <b>핵심 역할</b> | 발주자 대신 특정 프로젝트 총괄 및 감리 | 전사적 프로젝트 관리 역량 내재화 및 방법론 표준화 |

<b>4. 페이즈드 어텐션 (Paged Attention)</b>

* <b>개념:</b> 대형 언어 모델(LLM) 추론 시 발생하는 메모리 병목을 해결하기 위해, 운영체제의 가상 메모리 페이징 기법을 차용해 KV(Key-Value) 캐시를 비연속적인 블록에 할당하는 최적화 기술입니다.  
* <b>기대 효과:</b> 메모리 단편화 제거, GPU 메모리 효율 극대화(vLLM의 핵심 기술).

<b>5. ASIC (Application-Specific Integrated Circuit)</b>

* <b>개념:</b> 범용 칩(CPU, GPU 등)과 달리 비트코인 채굴, AI 추론 등 특정 기기나 응용 분야의 목적에만 맞춰 맞춤형으로 설계 및 제작된 주문형 반도체입니다.  
* <b>특징:</b> 성능과 전력 효율이 극도로 높으나, 초기 개발 비용(NRE)이 크고 범용성이 없습니다.

<b>6. CI/CD (Continuous Integration / Continuous Delivery, Deployment)</b>

* <b>개념:</b> 코드 통합부터 테스트, 릴리즈, 배포까지의 과정을 자동화하여 소프트웨어 배포 주기와 품질을 향상시키는 DevOps의 핵심 프랙티스입니다.  
* <b>구성:</b> <b>CI</b> (지속적 통합, 빌드/테스트 자동화) + <b>CD</b> (지속적 제공/배포, Staging 및 운영 환경 자동 반영).

<b>7. 서버리스 컴퓨팅 (Serverless Computing)</b>

* <b>개념:</b> 개발자가 서버의 프로비저닝이나 인프라 유지보수를 신경 쓰지 않고, 오직 코드(함수) 단위로만 실행하며 실제 사용량에 따라 과금하는 클라우드 모델입니다.  
* <b>주요 유형:</b> FaaS (Function as a Service, 예: AWS Lambda), BaaS (Backend as a Service).

<b>8. 5G 네트워크 슬라이싱 (5G Network Slicing)</b>

* <b>개념:</b> 하나의 물리적 코어 네트워크를 다수의 독립적인 논리적 가상 네트워크(슬라이스)로 분리하여, 각 서비스의 특성에 맞는 맞춤형 품질(QoS)을 제공하는 기술입니다.  
* <b>적용 분야:</b> eMBB(초고속), URLLC(초저지연/고신뢰), mMTC(초연결) 등 서비스별 독립망 구성.

<b>9. 정서 인공지능 (Affective Artificial Intelligence)</b>

* <b>개념:</b> 인간의 감정, 기분, 의도를 센서 및 데이터를 통해 인식, 해석, 처리, 시뮬레이션할 수 있는 인공지능 기술입니다.  
* <b>인식 방식:</b> 안면 인식(표정), 음성 분석(톤/억양), 생체 신호(심박수, 체온), 텍스트 감성 분석.

<b>10. 카오스 엔지니어링 (Chaos Engineering)</b>

* <b>개념:</b> 운영 중인 분산 시스템에 고의로 장애(변수)를 주입하여 시스템의 복원력(Resilience)과 내결함성을 선제적으로 검증하고 강화하는 테스트 기법입니다.  
* <b>핵심 원칙:</b> 정상 상태(Steady State) 정의 → 가설 수립 → 현실적 변수 주입 → 폭발 반경(Blast Radius) 최소화.

<b>11. 디지털 치료기기 (DTx, Digital Therapeutics)</b>

* <b>개념:</b> 의학적 장애나 질병을 예방, 관리, 치료하기 위해 환자에게 근거 기반의 치료적 개입을 제공하는 독립적인 소프트웨어 의료기기(SaMD)입니다.  
* <b>특징:</b> 일반 웰니스 앱과 달리 엄격한 임상 검증(RCT)과 식약처 등 규제 기관의 인허가가 필수적입니다 (예: 불면증 치료용 앱).

<b>12. 뮤테이션 테스트 (Mutation Test)</b>

* <b>개념:</b> 소스 코드의 일부를 의도적으로 변형(돌연변이 생성)한 후, 기존 테스트 케이스가 이 변형된 오류를 찾아내는지(Kill) 확인하여 테스트 케이스의 적합성을 검증하는 기법입니다.  
* <b>핵심 지표:</b> 뮤테이션 점수 (Killed Mutants / Total Mutants * 100).

<b>13. 동형암호 (Homomorphic Encryption)</b>

* <b>개념:</b> 암호화된 데이터를 복호화하지 않고 평문 상태와 동일하게 덧셈, 곱셈 등의 연산을 수행할 수 있는 차세대 프라이버시 보존 암호 기술입니다.  
* <b>주요 유형:</b> 부분 동형암호(PHE), 다소 동형암호(SHE), 완전 동형암호(FHE).

<b>14. BCP 주요 지표와 DRS 핵심 고려사항</b>

| 구분 | 핵심 요소 |
| --- | --- |
| <b>BCP 주요 지표</b> | <b>RTO</b>(목표 복구 시간), <b>RPO</b>(목표 복구 시점), <b>MTPD</b>(최대 허용 중단 시간) |
| <b>DRS 고려사항</b> | 복구 수준(Mirror, Hot, Warm, Cold), 네트워크 대역폭, 데이터 동기화 방식, 모의 훈련 체계 |

<b>15. 소프트웨어 3R</b>

| 기법 | 설명 |
| --- | --- |
| <b>역공학(Reverse)</b> | 운영 중인 기존 소스 코드로부터 설계서 등 상위 수준의 정보를 추출 (코드 → 설계) |
| <b>재공학(Re-engineering)</b> | 기존 시스템을 분석하여 기능 변경 없이 새로운 구조나 최신 기술로 개조 |
| <b>재사용(Reuse)</b> | 이미 검증된 기존 소프트웨어 컴포넌트를 새로운 시스템 개발에 다시 조립 및 활용 |

<b>16. PR 곡선과 ROC 곡선 비교</b>

| 구분 | PR (Precision-Recall) 곡선 | ROC 곡선 |
| --- | --- | --- |
| <b>X축 / Y축</b> | Recall(재현율) / Precision(정밀도) | FPR(1-특이도) / TPR(민감도, Recall) |
| <b>적합한 환경</b> | 정상/이상 클래스 불균형이 극심할 때 (예: 사기 탐지) | 클래스 비율이 균등하거나 일반적인 분류 모델 평가 |

<b>17. 베이지안 최적화 (Bayesian Optimization)</b>

* <b>개념:</b> 미지의 목적 함수(Black-box)를 최적화하는 하이퍼파라미터를 찾기 위해, 사전 정보와 관측 데이터를 바탕으로 사후 확률을 업데이트해 나가는 전역 최적화 기법입니다.  
* <b>구성 요소:</b> 대체 모델(Surrogate Model, 주로 가우시안 프로세스), 획득 함수(Acquisition Function).

<b>18. ELK 스택</b>

* <b>개념:</b> 대용량 로그 데이터의 수집, 검색, 시각화를 파이프라인으로 구성한 오픈소스 기반의 통합 로그 분석 플랫폼입니다.  
* <b>구성:</b> <b>E</b>lasticsearch (분산 검색 엔진) + <b>L</b>ogstash (데이터 수집 및 가공) + <b>K</b>ibana (데이터 시각화 대시보드).

<b>19. NoSQL의 CAP 정리</b>

* <b>개념:</b> 분산 시스템에서는 일관성(Consistency), 가용성(Availability), 분할 수용성(Partition Tolerance)의 세 가지 특성 중 두 가지만 완벽하게 만족할 수 있다는 정리입니다.

| 특성 조합 | 설명 | 대표 DB |
|---|---|---|
| <b>CP</b> | 네트워크 단절 시 일관성 보장을 위해 응답 차단(가용성 희생) | MongoDB, HBase, Redis |
| <b>AP</b> | 네트워크 단절 시에도 빠른 응답 보장(일관성 희생, 최종 일관성 지향) | Cassandra, DynamoDB | *(CA는 네트워크 장애를 배제할 수 없는 분산 환경에서 실현 불가)*

<b>20. 데이터 표준화의 필요성과 기대효과</b>

* <b>필요성:</b> 시스템 간 데이터 불일치 및 중복 해소, 인터페이스 연계 비용 증가 방지, 전사 데이터 통제력 상실 방지.  
* <b>기대효과:</b> 메타데이터 기반 데이터 품질 및 신뢰성 향상, 차세대 시스템 구축 및 EAI 연계 시 유연성 증대.

<b>21. 캡슐화(Encapsulation)와 정보은닉(Information Hiding)</b>

* <b>캡슐화:</b> 관련된 데이터(속성)와 이를 처리하는 메서드(행위)를 하나의 단위(클래스/객체)로 묶는 객체지향의 기본 원리.  
* <b>정보은닉:</b> 캡슐화된 객체의 내부 구현과 상세 데이터를 외부로부터 감추고, 허용된 공개(Public) 인터페이스를 통해서만 접근하게 하여 모듈 간 결합도를 낮추는 기법.

<b>22. SBOM (Software Bill of Material)</b>

* <b>개념:</b> 소프트웨어 개발, 빌드, 배포 과정에서 포함된 모든 오픈소스 및 서드파티 라이브러리의 의존성, 버전, 라이선스 정보를 명시한 상세 명세서입니다.  
* <b>목적:</b> 소프트웨어 공급망 공격(Supply Chain Attack) 방어, 취약점(예: Log4j) 발생 시 신속한 영향도 파악, 오픈소스 컴플라이언스 준수.

## 2교시형 문제 풀이

## [1번] 피지컬 AI (Physical AI)

<b>가. 피지컬 AI의 개념</b>
AI가 사이버 공간에 머물지 않고 로봇, 자율주행차, 센서 등을 통해 물리적 세계를 인지하고 상호작용하며, 실세계의 작업을 자율적으로 수행하는 인공지능 기술입니다.

<b>나. 피지컬 AI와 전통적 산업용 로봇 비교</b>

| 구분 | 전통적 산업용 로봇 | 피지컬 AI |
| --- | --- | --- |
| <b>제어 방식</b> | 사전 프로그래밍, 룰 기반 반복 수행 | 환경 인지 기반 자율적 판단 및 제어 |
| <b>환경 적응성</b> | 통제된 환경(생산 라인)에서만 작동 | 비정형화된 동적 환경에 적응 |
| <b>핵심 기술</b> | 정밀 기구학, 시퀀스 제어 | 컴퓨터 비전, 강화학습, 디지털 트윈 |

## [3번] 클라우드 네이티브 무중단 아키텍처 재해복구 전략

<b>가. RTO와 RPO</b>

* <b>RTO (Recovery Time Objective):</b> 업무 중단 발생 시점부터 서비스를 복구하여 정상 가동할 때까지의 <b>목표 복구 시간</b>.  
* <b>RPO (Recovery Point Objective):</b> 재해 발생 시 복구해야 하는 데이터의 <b>목표 복구 시점</b>(데이터 손실 허용량).

<b>나. Active-Active, Active-Passive, Pilot Light</b>

| 아키텍처 유형 | 설명 및 특징 | RTO 수준 |
| --- | --- | --- |
| <b>Active-Active</b> | 두 개 이상의 리전/존에서 트래픽을 동시 분산 처리. 무중단 서비스 가능. | 즉시 (Near Zero) |
| <b>Active-Passive</b> | 주 센터만 서비스하고 예비 센터는 대기. 장애 시 DNS 트래픽을 전환(Failover). | 수 분 ~ 수 시간 |
| <b>Pilot Light</b> | 핵심 인프라(DB 등)만 동기화해두고, 장애 발생 시 웹/WAS를 자동 확장(Scale-out)하여 복구. | 수 시간 |

## [4번] 메타모픽 테스트 (Metamorphic Test)

<b>가. 테스트 오라클 문제와 등장 배경</b>

* <b>테스트 오라클 문제:</b> AI 시스템(자율주행, LLM 등)은 입력에 대한 '절대적 정답(참값)'을 사전에 정의하거나 정량적으로 검증하기가 사실상 불가능합니다.  
* <b>등장 배경:</b> 정답을 몰라도 입력값의 의도적인 변화에 따른 출력값의 '예상되는 변화 패턴'을 검사하여, 논리적 모순을 통해 결함을 찾아내는 우회 검증 기법이 필요해졌습니다.

<b>나. 메타모픽 관계(MR)와 수행 절차</b>

* <b>메타모픽 관계(MR):</b> 원본 입력값($x$)과 변형된 입력값($x'$) 사이에, 원본 출력값($f(x)$)과 변형 출력값($f(x')$)이 반드시 충족해야 하는 논리적/수학적 속성입니다.  
* <b>수행 절차:</b> MR 식별 $\rightarrow$ 원본 테스트 생성 및 실행 $\rightarrow$ 변형 테스트 생성 및 실행 $\rightarrow$ 두 결과 비교를 통한 검증.

<b>다. 전통적 테스트와 메타모픽 테스트 기법 비교</b>

| 구분 | 전통적 테스트 | 메타모픽 테스트 |
| --- | --- | --- |
| <b>검증 기준</b> | 정의된 정답(Oracle)과의 일치 여부 | 원본-변형 결과 간의 논리적 관계(MR) 충족 여부 |
| <b>테스트 케이스</b> | 개별적인 독립된 입력-출력 쌍 | 여러 입력-출력 결과들의 관계 집합 |
| <b>적용 대상</b> | 일반 정보시스템, 정형화된 로직 | 머신러닝, 시뮬레이션, 검색 엔진 |

## [5번] HRN 알고리즘과 기아현상 해소

<b>가. HRN (Highest Response-ratio Next) 개념</b>
SJF(Shortest Job First)의 기아현상을 해결하기 위해, 프로세스의 '대기 시간'을 스케줄링 우선순위에 반영한 비선점형 스케줄링 알고리즘입니다.

* <b>우선순위 공식:</b> (대기 시간 + 서비스 시간) / 서비스 시간

<b>나. 기아현상(Starvation) 해소 방안</b>

* <b>에이징(Aging) 기법 적용:</b> 시스템에 오래 머문 프로세스의 우선순위를 점진적으로 높여주는 방식입니다. HRN은 공식 자체에 대기 시간을 분자로 포함하므로, 에이징 기법이 내재된 설계입니다.

## [8번] 무선 통신 프로토콜

* <b>가. CSMA/CA (Carrier Sense Multiple Access / Collision Avoidance):</b> 무선랜 환경에서 단말이 채널 사용 여부를 감지하고, 유휴 상태라도 무작위 백오프 시간만큼 대기하여 충돌을 '사전 회피'하는 프로토콜.  
* <b>나. CDMA (Code Division Multiple Access):</b> 확산 대역 기술을 이용해 여러 사용자가 동일 주파수를 동시에 사용하되, 고유한 '코드'를 부여하여 데이터를 구분하는 방식.  
* <b>다. TDMA (Time Division Multiple Access):</b> 동일 주파수 대역을 짧은 '시간 슬롯'으로 분할하여 다수의 사용자가 번갈아 전송하는 방식.

## [10번] 맨체스터 코딩 (Manchester Coding)

<b>가. 맨체스터 코딩의 개념</b>
데이터 신호와 클럭(Clock) 신호를 하나로 결합하여 전송하는 베이스밴드 회선 부호화 방식으로, 비트 펄스 구간 중간의 '전압 전이(Transition)' 방향으로 데이터를 표현합니다.

<b>나. 인코딩 및 디코딩 (IEEE 802.3 기준)</b>

* <b>인코딩:</b> 논리값 '0'은 High $\rightarrow$ Low 전이, '1'은 Low $\rightarrow$ High 전이로 부호화.  
* <b>디코딩:</b> 수신 측에서 비트 중간의 전압 변동 방향을 감지하여 데이터를 복원하고 클럭 동기화를 맞춤.

<b>다. 맨체스터 코딩과 차등 맨체스터 코딩 비교</b>

| 구분 | 맨체스터 코딩 | 차등(Differential) 맨체스터 코딩 |
| --- | --- | --- |
| <b>판별 기준</b> | 비트 구간 중간의 전이 <b>방향</b> | 비트 구간 <b>시작점</b>에서의 전이 <b>유무</b> |
| <b>규칙</b> | 0: 하향 전이 / 1: 상향 전이 | 0: 시작점에 전이 있음 / 1: 시작점에 전이 없음 |

## [11번] 객체 지향 프로그래밍 SOLID 원칙

1. <b>SRP (단일 책임 원칙):</b> 클래스는 단 하나의 변경 이유(책임)만을 가져야 합니다.  
2. <b>OCP (개방-폐쇄 원칙):</b> 확장에는 열려 있어야 하고, 수정에는 닫혀 있어야 합니다 (다형성/인터페이스 활용).  
3. <b>LSP (리스코프 치환 원칙):</b> 자식 클래스는 부모 클래스의 행위 규약을 위반하지 않고 완전히 대체 가능해야 합니다.  
4. <b>ISP (인터페이스 분리 원칙):</b> 클라이언트는 자신이 사용하지 않는 메서드에 의존하지 않도록 인터페이스를 작게 분리해야 합니다.  
5. <b>DIP (의존성 역전 원칙):</b> 고수준 모듈은 저수준 모듈에 의존해서는 안 되며, 둘 다 추상화(인터페이스)에 의존해야 합니다.

## [12번] 캐시 메모리

<b>가. 매핑(Mapping) 필요성과 방식</b>

* <b>필요성:</b> 용량이 작은 캐시에 대용량 주기억장치의 주소를 할당하고 신속하게 검색하기 위한 규칙.  
* <b>방식:</b> 직접 매핑(특정 라인 고정 매핑), 연관 매핑(자유 매핑), 집합 연관 매핑(세트 단위 매핑).

<b>나. 캐시 쓰기 정책 (Write Policy)</b>

* <b>Write-Through (동시 쓰기):</b> 캐시와 주기억장치에 데이터를 동시 기록 (일관성 높음, 속도 저하).  
* <b>Write-Back (나중 쓰기):</b> 캐시에만 기록(Dirty Bit) 후 블록 교체 시 주기억장치에 반영 (속도 빠름, 일관성 유지 필요).

<b>다. 다중 프로세서 캐시 일관성 기법</b>

* <b>스누핑(Snooping):</b> 공유 버스를 지속 감시하여 다른 캐시 쓰기 시 자신의 데이터를 무효화 (MESI 프로토콜).  
* <b>디렉토리(Directory):</b> 중앙 디렉토리에 캐시 상태를 기록하고 제어 (대규모 시스템에 적합).

## [13번] Privacy by Design (PbD)

<b>가. 7대 원칙</b>

1. 사전예방(Proactive) 2. 기본설정(Privacy as Default) 3. 설계삽입(Embedded) 4. 포지티브섬(Positive-sum) 5. 종단보안(End-to-End) 6. 가시성/투명성 7. 사용자 중심.

<b>나. 8대 전략 (호페딕의 전략)</b>

* <b>데이터 지향:</b> 최소화(Minimize), 은닉(Hide), 분리(Separate), 집계(Aggregate).  
* <b>프로세스 지향:</b> 정보제공(Inform), 통제(Control), 시연(Enforce), 준수(Demonstrate).

<b>다. 8대 전략과 개인정보보호법(제3조) 비교</b>

| PbD 8대 전략 | 개인정보보호법 제3조 주요 내용 |
| --- | --- |
| 최소화 (Minimize) | 개인정보 수집의 최소화 (제1항) |
| 통제 (Control), 은닉 (Hide) | 목적 외 사용 금지 및 안전성 확보 (제2, 4항) |
| 정보제공 (Inform) | 처리 목적 명확화, 투명성 확보 (제1, 5항) |
| 사용자 통제권 (User Control) | 정보주체의 권리 보장 및 신뢰 보호 (제5, 6항) |

## [14번] 생성형 AI 보안 위협 및 가이드라인

<b>가. 개념 및 활용 사례</b>

* <b>개념:</b> 대규모 데이터를 학습하여 텍스트, 이미지, 코드 등 새로운 콘텐츠를 생성하는 AI.  
* <b>사례:</b> ChatGPT(문서/코드 작성), Midjourney(이미지 생성), GitHub Copilot.

<b>나. 보안 위협 종류 및 원인</b>

* <b>프롬프트 인젝션:</b> 악의적 명령어를 주입하여 윤리 필터 우회 및 악성 콘텐츠 생성.  
* <b>데이터 유출:</b> 프롬프트에 입력된 기업 기밀(소스코드 등)이 모델 재학습에 활용되어 외부 유출.  
* <b>환각 (Hallucination):</b> 그럴듯한 허위 정보를 생성하여 의사결정 오류 초래.

<b>다. 대응 방안</b>

* <b>개발 단계:</b> 내부 폐쇄망(On-Premise) 모델 구축, 데이터 비식별화, RAG 기술 적용(환각 최소화).  
* <b>활용 단계:</b> 프롬프트 필터링(DLP 연동), 민감정보 사전 마스킹, 사내 보안 가이드라인 제정 및 교육.

## [15번] 다자간 계산 (MPC, Multi-Party Computation)

<b>가. 개념, 원리, 특징</b>

* <b>개념/원리:</b> 서로 신뢰하지 않는 참여자들이 각자의 비밀 데이터를 공개하지 않은 상태에서 공동으로 함수 연산 결과만 도출하는 암호학적 프로토콜.  
* <b>특징:</b> 완벽한 프라이버시 보장, 무영지식성(Zero-Knowledge), 단일 장애점(SPOF) 제거.

<b>나. 기술 종류</b>

* <b>비밀 분산 (Secret Sharing):</b> 데이터를 수학적으로 쪼개어 분배하고, 임계치 이상 모였을 때만 연산.  
* <b>가블드 서킷 (Garbled Circuit):</b> 논리 회로를 암호화하여 연산의 중간 과정을 숨김.

<b>다. 인증서비스 적용 사례</b>

* <b>블록체인 지갑 (TSS):</b> 개인키를 여러 디바이스에 분산 보관하고, 서명 시 키를 온전히 합치지 않고 MPC 연산으로 트랜잭션 서명 (자산 탈취 원천 차단).

## [16번] RDBMS 데이터 모델링

<b>가. 데이터 모델링 단계별 수행내용</b>

1. <b>개념적 모델링:</b> 업무 분석, 핵심 엔터티 도출, ERD 작성 (DBMS 독립적).  
2. <b>논리적 모델링:</b> 정규화 수행(1NF~3NF), 속성/관계/식별자 확정 (관계형 모델 정립).  
3. <b>물리적 모델링:</b> 특정 RDBMS에 맞춘 테이블, 인덱스 생성 및 성능을 위한 반정규화 수행.

<b>나. 데이터 관계 모델링 시 식별 vs 비식별 비교</b>

| 구분 | 식별 관계 (Identifying) | 비식별 관계 (Non-Identifying) |
| --- | --- | --- |
| <b>정의</b> | 부모의 PK가 자식의 PK에 포함됨 | 부모의 PK가 자식의 일반 속성(FK)으로 포함됨 |
| <b>종속성</b> | 강한 종속 (부모 없이 자식 존재 불가) | 약한 종속 (자식이 독립적으로 존재 가능) |
| <b>ERD 표기법</b> | 실선 (Solid Line) | 점선 (Dashed Line) |

<b>다. 고려사항</b>

* <b>정규화 vs 반정규화:</b> 무결성을 위해 정규화를 우선하되, 조인 성능 저하 시 제한적 반정규화 고려.  
* <b>도메인 무결성:</b> 데이터 타입, 길이, 제약조건 표준화를 통한 데이터 품질 확보.
