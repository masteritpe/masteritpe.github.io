## 1교시형 문제 풀이

## 1. PIM (Processing in Memory)

<b>1. PIM의 개요</b>

* <b>정의</b>: 메모리 내부에 연산기(Processor)를 통합하여, CPU와 메모리 간의 데이터 이동을 최소화하고 연산 효율을 극대화한 차세대 지능형 반도체 기술  
* <b>등장 배경</b>: 폰노이만 병목현상(CPU-메모리 간 대역폭 한계) 극복, AI/빅데이터 처리를 위한 고성능·저전력 요구 증대

<b>2. 주요 특징 및 기대효과</b>

* <b>특징</b>: 데이터 이동 감소, 병렬 처리 지원, 전력 소모 절감  
* <b>기대효과</b>: AI 모델 학습 및 추론 속도 향상, 디바이스의 발열 감소 및 에너지 효율 극대화

## 2. 웹 애플리케이션 방화벽 (WAF: Web Application Firewall)

<b>1. WAF의 개요</b>

* <b>정의</b>: 일반적인 네트워크 방화벽(L4)이 탐지하지 못하는 웹 애플리케이션 계층(L7)의 보안 취약점을 노린 공격을 탐지하고 차단하는 웹 전용 보안 솔루션  
* <b>목적</b>: SQL 인젝션, XSS(크로스 사이트 스크립팅), 웹 쉘 업로드 등 OWASP Top 10 웹 취약점 공격 방어

<b>2. 주요 기능 및 기존 보안장비 비교</b>

* <b>주요 기능</b>: HTTP/HTTPS 트래픽 검사, 웹 공격 시그니처 기반 차단, 사용자 정의 룰 셋 적용, 클로킹(서버 정보 은닉)  
* <b>네트워크 방화벽(FW)과의 비교</b>: FW는 IP/Port 기반의 접근을 제어(L3/L4)하는 반면, WAF는 패킷의 페이로드(웹 콘텐츠)를 심층 분석(L7)하여 비정상 트래픽을 차단함.

## 3. 페어 프로그래밍과 핑퐁 프로그래밍

<b>1. 기법의 개요</b>

* 애자일(Agile) 및 익스트림 프로그래밍(XP) 환경에서 코드 품질 향상과 지식 공유를 위해 두 명의 개발자가 협력하여 코드를 작성하는 기법

<b>2. 기법 비교</b>

| 구분 | 페어 프로그래밍 (Pair Programming) | 핑퐁 프로그래밍 (Ping Pong Programming) |
| --- | --- | --- |
| <b>개념</b> | 하나의 PC에서 두 명(Driver, Navigator)이 역할을 나누어 함께 코딩 | TDD(테스트 주도 개발)를 기반으로 두 개발자가 번갈아 가며 코딩 |
| <b>역할</b> | <b>Driver</b>: 코드 작성 및 타이핑<br><b>Navigator</b>: 코드 리뷰, 방향성 제시 및 오타 검수 | <b>개발자 A</b>: 실패하는 테스트 코드 작성<br><b>개발자 B</b>: 테스트를 통과하는 실제 코드 작성 후, 새로운 테스트 코드 작성 (교대) |
| <b>특징</b> | 실시간 코드 리뷰, 지속적인 소통 | 게임을 하듯 역할을 교대하여 몰입도 향상, TDD 실천의 원동력 |

## 4. 전송 부호화 기법: 소스코딩과 채널코딩

<b>1. 전송 부호화 기법의 개요</b>

* <b>정의</b>: 디지털 통신 시스템에서 데이터를 효율적이고 신뢰성 있게 전송하기 위해 송신측에서 데이터를 변환하고, 수신측에서 역변환하는 과정

<b>2. 소스코딩(Source Coding)과 채널코딩(Channel Coding) 비교</b>

| 구분 | 소스코딩 (Source Coding) | 채널코딩 (Channel Coding) |
| --- | --- | --- |
| <b>목적</b> | <b>전송 효율성 향상</b> (대역폭 절감) | <b>전송 신뢰성 향상</b> (오류 검출 및 정정) |
| <b>주요 원리</b> | 데이터의 중복성 제거 (압축) | 잉여 비트(Redundancy) 추가 |
| <b>기법/종류</b> | 허프만 코딩, PCM, 압축(MPEG, JPEG 등) | 해밍 코드, CRC, 길쌈 부호(Convolutional Code) |
| <b>위치</b> | 송신단에서 정보원 다음 단계에 위치 | 소스코더 다음 단계, 변조기 이전에 위치 |

## 5. HBM (High Bandwidth Memory)

<b>1. HBM의 개요</b>

* <b>정의</b>: 여러 개의 D램을 수직으로 적층한 후, TSV(Through Silicon Via, 실리콘 관통 전극) 기술을 이용해 연결함으로써 데이터 처리 속도를 혁신적으로 끌어올린 고대역폭 메모리

<b>2. HBM의 주요 특징 및 활용</b>

* <b>기술 요소</b>: TSV(미세 구멍을 통한 상하 칩 연결), Micro Bump, 베이스 다이(Base Die)  
* <b>특징</b>: 기존 GDDR 대비 압도적으로 넓은 대역폭 제공, 폼팩터 축소, 낮은 전력 소모  
* <b>활용</b>: 생성형 AI 모델 학습, 고성능 컴퓨팅(HPC), 차세대 그래픽 카드

## 6. 튜링 테스트 (Turing Test)

<b>1. 튜링 테스트의 개요</b>

* <b>정의</b>: 1950년 앨런 튜링이 제안한 것으로, 기계가 인간과 얼마나 비슷하게 대화할 수 있는지를 기준으로 기계의 지능(인공지능) 여부를 판별하는 테스트

<b>2. 테스트 방식 및 한계</b>

* <b>테스트 방식</b>: 심사위원(인간)이 텍스트 기반 대화를 통해 상대방이 기계인지 인간인지 구별하지 못한다면, 해당 기계는 사고하는 능력(지능)을 갖춘 것으로 판정함.  
* <b>한계 (중국어 방 논증)</b>: 규칙에 따라 기호만 조작하는 기계도 테스트를 통과할 수 있으므로, 대화의 성공이 곧 기계의 진정한 '이해'를 의미하지는 않음. (존 설의 비판)

## 7. Cache Memory 쓰기 정책: Write Through vs Write Back

<b>1. 캐시 메모리 쓰기 정책의 개요</b>

* <b>정의</b>: CPU가 캐시 메모리에 데이터를 기록할 때, 메인 메모리(주기억장치)와의 데이터 일관성(Coherence)을 언제, 어떻게 맞출 것인지 결정하는 방식

<b>2. Write Through와 Write Back 비교</b>

| 구분 | Write Through (동시 기록) | Write Back (나중 기록) |
| --- | --- | --- |
| <b>동작 방식</b> | 캐시와 메인 메모리에 <b>동시에</b> 데이터 쓰기 수행 | 데이터를 캐시에만 쓰고, 캐시 블록이 교체될 때 메인 메모리에 쓰기 수행 |
| <b>일관성</b> | 캐시와 메인 메모리가 항상 일치 (데이터 안전성 높음) | 일시적으로 불일치 발생 (수정 여부를 표시하는 Dirty Bit 필요) |
| <b>성능(속도)</b> | 매번 메모리 접근이 발생하여 <b>속도 느림</b> | 메모리 접근 횟수가 적어 <b>속도 빠름</b> |
| <b>적용 분야</b> | 데이터 손실이 치명적인 시스템 | 빠른 성능이 요구되는 일반적인 컴퓨터 시스템 |

## 8. 상용 소프트웨어 직접구매 제도 (분리발주)

<b>1. 제도의 개요</b>

* <b>정의</b>: 공공기관이 정보시스템 구축 사업을 발주할 때, 하드웨어나 시스템 통합(SI)과 함께 일괄 구매하지 않고 일정 기준을 충족하는 상용 소프트웨어를 발주처가 직접 발주 및 구매하도록 의무화한 제도

<b>2. 목적 및 적용 기준</b>

* <b>추진 목적</b>: 하도급 관행에 따른 단가 후려치기 방지, SW 제값 주기 실현, 중소 SW 기업의 육성 및 품질 향상 도모  
* <b>적용 대상</b>: 총 사업비(국가기관 7억 원 이상, 지자체 5억 원 이상) 중 단일 상용 SW 가격이 5천만 원 이상인 경우 의무 적용 (관련 법령 및 규정에 따름)

## 2교시형 문제 풀이

## 1. 정보시스템 하드웨어 규모산정지침(TTAK.KO-10.0292/R2)

<b>I. 정보시스템 하드웨어 규모산정의 개요 및 대상</b>
정보시스템 구축 시 요구되는 하드웨어 자원의 용량을 객관적이고 체계적으로 산정하기 위한 한국정보통신기술협회(TTA) 표준 지침입니다.

<b>1. 규모산정 대상</b>

* <b>CPU (중앙처리장치)</b>: tpmC(트랜잭션 처리 성능), SPECint(정수 연산 성능) 등의 지표를 활용하여 서버의 연산 처리 능력을 산정합니다.  
* <b>메모리 (Memory)</b>: 운영체제, 시스템 소프트웨어(DBMS, WEB, WAS 등), 애플리케이션 및 사용자 처리에 필요한 주기억장치 용량을 산정합니다.  
* <b>디스크 (Disk)</b>: 시스템 공간, 데이터베이스 공간, 백업 공간, 여유 공간 등을 고려하여 보조기억장치 용량을 산정합니다.

<b>II. 규모산정 방법 및 절차</b>
<b>1. 규모산정 방법 (수식 산정 방식 기준)</b>

* <b>CPU 규모산정</b>: `(동시 사용자 수 × 분당 트랜잭션 수 / 60) × 기본 tpmC × (보정요수 합)` 형태로 서비스 형태에 따라 산정합니다. 웹/WAS/DB 서버별로 다른 기준(tpmC, OPS 등)을 적용합니다.  
* <b>메모리 규모산정</b>: `시스템 OS 요구 메모리 + (동시 사용자 수 × 인당 필요 메모리) + SW 요구 메모리 + 버퍼 캐시` 등에 보정률을 곱하여 산정합니다.  
* <b>디스크 규모산정</b>: `(시스템 공간 + 데이터 공간) × RAID 여유율 × 디스크 여유율`로 산정하며, 데이터 증가율을 반영합니다.

<b>2. 규모산정 절차</b>

1. <b>업무 분석 및 요구사항 정의</b>: 업무 특성 파악, 동시 사용자 수, 트랜잭션 규모, 데이터 증가율 등 기초 자료를 수집합니다.  
2. <b>서버 아키텍처 정의</b>: Web, WAS, DB 서버 등 논리적/물리적 시스템 구성도(Topology)를 확정합니다.  
3. <b>항목별 규모산정 수행</b>: CPU, 메모리, 디스크 등 하드웨어 요소별로 수식 산정법 또는 참조 모델법을 적용하여 기본 용량을 계산합니다.  
4. <b>보정치 적용 및 최종 규모 확정</b>: 피크 타임, 클러스터링, 시스템 여유율(CPU 70~80% 타겟 등)을 고려한 보정 계수를 적용하여 최종 스펙을 확정합니다.

## 2. 사용자 테스트 (User Testing)

<b>I. 사용자 테스트의 개요 및 주요 기법</b>
사용자 테스트는 소프트웨어 개발 완료 후, 실제 사용 환경에서 사용자의 요구사항과 기대치를 충족하는지 검증하는 확인(Validation) 과정입니다.

<b>1. 알파(Alpha) 테스트</b>

* <b>개념</b>: 개발자 통제 하에 개발 환경 또는 사내 테스트 환경에서 선택된 내부 사용자(또는 테스터)가 수행하는 검사입니다.  
* <b>특징</b>: 오류 발생 시 즉각적인 피드백과 수정이 가능하며, 통제된 환경에서 진행됩니다.

<b>2. 베타 테스트 (Beta Test)</b>

* <b>개념</b>: 실제 운영 환경에서 제한되지 않은 일반 사용자(End-User)에게 소프트웨어를 배포하여 수행하는 필드 테스트입니다.  
* <b>특징</b>: 개발자 통제 없이 진행되며, 다양한 하드웨어/OS 환경에서의 호환성과 예기치 않은 오류를 발견하는 데 효과적입니다.

<b>3. 인수 테스트 (Acceptance Test)</b>

* <b>개념</b>: 소프트웨어를 인도하기 전, 발주자(고객)가 시스템이 요구사항을 충족하는지 최종적으로 확인하고 승인하기 위해 수행하는 테스트입니다.  
* <b>특징</b>: 계약 및 요구사항 명세서를 기준으로 하며, 알파/베타 테스트를 포함하는 광의의 개념으로도 쓰입니다. (규정 인수, 운영 인수, 사용자 인수 등으로 분류)

<b>II. 인수 테스트 프로세스 (Acceptance Test Process)</b>

1. <b>인수 테스트 계획 수립</b>: 테스트 목적, 범위, 일정, 자원, 통과 기준(Acceptance Criteria)을 정의합니다.  
2. <b>테스트 케이스/시나리오 작성</b>: 요구사항 명세서, 비즈니스 프로세스를 기반으로 실제 업무 시나리오를 도출합니다.  
3. <b>테스트 환경 구축 및 데이터 준비</b>: 실제 운영 환경과 유사한 테스트 베드를 구축하고 마이그레이션된 데이터를 준비합니다.  
4. <b>인수 테스트 실행 및 결함 관리</b>: 고객 주도 하에 테스트를 수행하고, 발견된 결함(Defect)을 등록, 분석, 수정, 재테스트합니다.  
5. <b>테스트 결과 보고 및 최종 승인</b>: 테스트 결과를 요약 보고하고, 사전에 정의된 통과 기준을 만족하면 고객이 시스템 인수를 최종 승인(Sign-off)합니다.

## 3. 운영체제 프로세스 스케줄링 알고리즘 (SQMS vs MQMS)

<b>I. 멀티프로세서 스케줄링의 개요</b>
멀티 코어/멀티 프로세서 환경에서 실행 가능한 프로세스(스레드)들을 여러 CPU에 효율적으로 할당하여 처리량을 극대화하기 위한 운영체제의 기법입니다.

<b>II. SQMS와 MQMS 비교 설명</b>

<b>1. 단일 큐 멀티프로세서 스케줄링 (SQMS: Single Queue Multiprocessor Scheduling)</b>

* <b>개념</b>: 시스템 전체에 오직 하나의 '준비 큐(Ready Queue)'를 두고, 모든 CPU가 이 단일 큐에서 프로세스를 가져와 실행하는 방식입니다.  
* <b>특징 및 단점</b>:  
* <b>구현 용이성</b>: 기존 단일 프로세서 스케줄링 정책을 쉽게 확장할 수 있습니다.  
* <b>확장성(Scalability) 부족</b>: 여러 CPU가 하나의 큐에 동시 접근하므로 동기화(Locking) 오버헤드와 병목 현상이 발생합니다.  
* <b>캐시 친화성(Cache Affinity) 저하</b>: 프로세스가 실행될 때마다 다른 CPU에 할당될 가능성이 높아 캐시 미스(Cache Miss)가 증가합니다.

<b>2. 멀티 큐 멀티프로세서 스케줄링 (MQMS: Multi Queue Multiprocessor Scheduling)</b>

* <b>개념</b>: 각 CPU(또는 코어)마다 독립적인 '준비 큐(Ready Queue)'를 할당하여 스케줄링을 분산 수행하는 방식입니다.  
* <b>특징 및 장점</b>:  
* <b>확장성 향상</b>: 큐 단위의 잠금(Lock)이 독립적이므로, CPU 증가에 따른 동기화 병목이 해소됩니다.  
* <b>캐시 친화성(Cache Affinity) 우수</b>: 프로세스가 동일한 CPU에서 계속 실행될 확률이 높아 L1/L2 캐시 활용도가 극대화됩니다.

* <b>단점 (부하 불균형)</b>: 특정 CPU의 큐에만 프로세스가 몰릴 수 있으므로, 큐 간에 프로세스를 이동시키는 <b>부하 균등화(Load Balancing)</b> 기법이 필수적으로 동반되어야 합니다.

## 4. 네트워크 스위치 (Network Switch)

<b>I. 스위치 개요</b>

* 네트워크 스위치는 수신된 패킷의 목적지 주소를 확인하고, 해당 목적지와 연결된 포트로만 패킷을 포워딩하여 네트워크 대역폭을 효율적으로 분배하는 통신 장비입니다.

<b>II. OSI 참조모델 레이어에 따른 스위치 유형</b>

| 스위치 유형 | 기준 정보 (PDU) | 동작 계층 (OSI 7 Layer) | 주요 기능 및 특징 |
| --- | --- | --- | --- |
| <b>L2 스위치</b> | MAC 주소 | 2계층 (데이터링크 계층) | 동일 네트워크 내 패킷 전달, 브로드캐스트 도메인 분리 불가, VLAN 지원 |
| <b>L3 스위치</b> | IP 주소 | 3계층 (네트워크 계층) | 서로 다른 네트워크 간 라우팅 기능 포함 (하드웨어 기반 라우팅) |
| <b>L4 스위치</b> | Port 주소, TCP/UDP 세션 | 4계층 (전송 계층) | 트래픽 부하 분산(Load Balancing), 세션 관리, 서버 이중화 지원 |
| <b>L7 스위치</b> | Payload (HTTP, URL 등) | 7계층 (애플리케이션 계층) | 콘텐츠 기반 지능형 스위칭, 웹 방화벽(WAF) 연동, 캐싱/압축 |

<b>III. L4 스위치와 L7 스위치 비교</b>

* <b>부하 분산 기준</b>: L4 스위치는 IP와 TCP/UDP 포트 번호를 기준으로 단순 부하 분산을 수행하지만, L7 스위치는 HTTP 헤더, 쿠키, URL, 페이로드 등 애플리케이션 계층의 콘텐츠를 분석하여 정밀하게 트래픽을 분산합니다.  
* <b>보안 및 제어</b>: L7 스위치는 비정상적인 접근(DDoS, 웹 공격 등)을 콘텐츠 수준에서 필터링할 수 있어 보안성이 높으나, 패킷 심층 분석으로 인해 L4 스위치 대비 처리 지연(Latency)이 발생할 수 있습니다.

## 5. 양자 컴퓨터 (Quantum Computer)

<b>I. 양자 컴퓨터의 주요 개념</b>
<b>1. 양자비트 (Qubit, 큐비트)</b>

* 기존 컴퓨터가 0과 1 중 하나의 상태만을 가지는 비트(Bit)를 사용하는 반면, 양자역학의 <b>중첩(Superposition)</b> 원리를 이용하여 0과 1의 상태를 동시에 가질 수 있는 양자 정보의 최소 단위입니다. $N$개의 큐비트는 $2^N$개의 상태를 동시에 처리할 수 있습니다.

<b>2. 양자 우월성 (Quantum Supremacy)</b>

* 양자 컴퓨터가 현존하는 최고 성능의 슈퍼컴퓨터로도 수만 년이 걸리는 문제를 불과 몇 분, 몇 초 만에 해결하여 고전 컴퓨터의 성능을 압도적으로 뛰어넘는 역사적 기점이나 능력을 의미합니다. (예: 구글의 시커모어 칩 발표)

<b>3. 양자 결어긋남 (Quantum Decoherence)</b>

* 양자 상태(중첩, 얽힘)가 온도, 전자기장 등 외부 환경의 미세한 간섭이나 노이즈와 상호작용하여 깨지고, 일반적인 고전 상태(0 또는 1)로 붕괴해 버리는 현상입니다. 양자 컴퓨터 구현의 가장 큰 장애물이며, 양자 오류 정정(QEC) 기술이 필수적입니다.

<b>II. 양자 컴퓨터 구현 방법 (물리적 큐비트 방식)</b>

* <b>초전도체 (Superconducting)</b>: 극저온(절대영도 부근)에서 저항이 0이 되는 초전도 회로를 이용해 조셉슨 접합(Josephson Junction)을 구성하여 큐비트를 구현합니다. (IBM, Google 등 주도)  
* <b>이온 트랩 (Ion Trap)</b>: 진공 상태에서 전자기장으로 개별 이온을 가두고, 레이저를 쏘아 이온의 전자 상태를 제어하여 큐비트를 조작합니다. (안정성이 높고 결어긋남 시간이 김)  
* <b>광자 (Photonic)</b>: 빛의 입자인 광자의 위상이나 편광 상태를 이용하여 큐비트를 구현하며, 상온에서 동작 가능한 장점이 있습니다.  
* <b>토폴로지컬 (Topological)</b>: 마요라나 페르미온 등 위상 물질의 입자를 이용하여 외부 노이즈에 원천적으로 내성을 갖는 큐비트를 구현하는 방식입니다. (MS 주도, 연구 초기 단계)

## 6. 표준 통신 프로토콜 (TCP, UDP, SCTP)

<b>I. 프로토콜 개요</b>
<b>1. TCP (Transmission Control Protocol)</b>

* 연결 지향형(Connection-oriented) 전송 프로토콜로, 3-Way Handshake를 통해 연결을 설정하고, 순서 제어, 흐름 제어, 혼잡 제어를 통해 데이터의 신뢰성 있는 전송을 보장합니다.

<b>2. UDP (User Datagram Protocol)</b>

* 비연결형(Connectionless) 전송 프로토콜로, 신뢰성을 보장하기 위한 오버헤드(오류 복구 등)가 없어 전송 속도가 매우 빠릅니다. 실시간 스트리밍, DNS 등에 주로 사용됩니다.

<b>3. SCTP (Streaming Control Transmission Protocol)</b>

* TCP의 신뢰성과 UDP의 메시지 지향(스트리밍) 특성을 결합한 차세대 전송 프로토콜입니다. 다중 스트리밍(Multi-streaming)과 다중 홈잉(Multi-homing)을 지원하여 한 경로에 장애가 발생해도 끊김 없는 통신을 제공합니다.

<b>II. TCP, UDP, SCTP 비교</b>

| 비교 항목 | TCP | UDP | SCTP |
| --- | --- | --- | --- |
| <b>연결 방식</b> | 연결 지향형 (Connection-oriented) | 비연결형 (Connectionless) | 연결 지향형 (Connection-oriented) |
| <b>데이터 단위</b> | 바이트 스트림 (Byte Stream) | 데이터그램 (Datagram) | 메시지 지향 (Message-oriented) |
| <b>신뢰성 보장</b> | 높음 (순서 보장, 오류 제어) | 낮음 (보장 안 됨) | 높음 (순서 보장, 오류 제어) |
| <b>다중 경로 지원</b> | 미지원 (Single-homing) | 미지원 | <b>지원 (Multi-homing)</b> |
| <b>보안 취약점 방어</b> | SYN Flooding 등 공격에 취약 | 차단 메커니즘 없음 | 4-Way Handshake 및 Cookie로 공격 방어 |

## 7. Ad-hoc 라우팅 프로토콜

<b>I. Ad-hoc 라우팅 프로토콜 개요</b>
고정된 기지국이나 라우터 등 인프라가 없는 환경에서, 이동 노드(Mobile Node)들 스스로가 라우터 역할을 수행하며 동적으로 네트워크 토폴로지를 구성하고 패킷을 중계하는 무선 라우팅 방식입니다.

<b>II. Ad-hoc 라우팅 프로토콜 유형</b>

1. <b>Proactive (Table-driven, 사전 주도형)</b>:  
* 네트워크 내의 모든 라우팅 정보를 주기적으로 브로드캐스팅하여 라우팅 테이블을 항상 최신 상태로 유지합니다. (예: DSDV)  
* 지연 시간은 짧으나 제어 오버헤드가 큽니다.

2. <b>Reactive (On-demand, 요구 주도형)</b>:  
* 데이터를 전송해야 할 시점에만 경로 탐색 과정을 거쳐 라우팅 경로를 설정합니다. (예: AODV, DSR)  
* 오버헤드는 적으나 초기 경로 탐색 지연이 발생합니다.

3. <b>Hybrid (혼합형)</b>:  
* 근거리(Zone 내부)는 Proactive 방식을, 원거리(Zone 외부)는 Reactive 방식을 결합하여 적용합니다. (예: ZRP)

<b>III. AODV (Ad-hoc On-Demand Distance Vector)</b>

* <b>개념</b>: 대표적인 Reactive 라우팅 프로토콜로, 목적지 노드로의 경로가 필요할 때만 경로를 탐색(Route Discovery)하고 유지(Route Maintenance)합니다.  
* <b>동작 방식</b>:  
* <b>경로 탐색</b>: 송신 노드가 네트워크에 RREQ(Route Request) 패킷을 브로드캐스트하고, 목적지 노드(또는 경로를 아는 중간 노드)가 RREP(Route Reply) 패킷을 유니캐스트로 응답하여 경로를 확립합니다.  
* <b>특징</b>: 루핑(Looping)을 방지하기 위해 Sequence Number를 사용하며, 경로 단절 시 RERR(Route Error) 패킷을 전송합니다.

## 8. 디스크 이미징 (Disk Imaging)

<b>I. 디스크 이미징의 용도</b>
디스크 이미징은 원본 저장 매체의 물리적인 섹터(Sector) 단위까지 비트 스트림(Bit-stream) 방식으로 100% 동일하게 복제하는 기술입니다.

* <b>디지털 포렌식</b>: 원본 데이터 훼손 방지(무결성 유지)를 위한 증거물 사본 생성  
* <b>백업 및 재해 복구</b>: 운영체제 및 시스템 환경 통째 백업 및 신속 복구  
* <b>대량 배포</b>: 동일한 OS 및 소프트웨어 환경을 다수의 PC에 신속히 설치

<b>II. Disk to Disk 와 Disk to File 방식 비교</b>

* <b>Disk to Disk (디스크 대 디스크)</b>:  
* 원본 디스크와 용량이 같거나 큰 대상 디스크에 섹터 단위로 1:1로 직접 복제하는 방식입니다.  
* 작업 완료 후 복제된 디스크를 시스템에 바로 연결하여 부팅 및 분석이 가능한 장점이 있습니다.

* <b>Disk to File (디스크 대 파일)</b>:  
* 원본 디스크의 전체 비트열을 읽어들여 하나의 이미지 파일(예: .dd, .e01)로 저장하는 방식입니다.  
* 압축 및 암호화를 적용할 수 있고, 하나의 대용량 저장소에 여러 매체의 증거 파일을 보관하기 용이하여 디지털 포렌식에서 표준적으로 사용됩니다.

<b>III. 디스크 이미징을 활용한 증거수집 방법 (포렌식 관점)</b>

1. <b>쓰기 방지 (Write Blocker) 적용</b>: 원본 디스크에 데이터가 기록되거나 변조되는 것을 하드웨어/소프트웨어적으로 원천 차단합니다.  
2. <b>이미징 수행 (Bit-stream Copy)</b>: EnCase, FTK Imager, dd(Linux) 등의 전문 도구를 사용하여 물리적 섹터 단위로 복제(Disk to File 권장)를 수행합니다.  
3. <b>해시(Hash) 값 계산 및 검증</b>: 이미징 전 원본 디스크의 해시값(MD5, SHA-256)과 생성된 사본 이미지 파일의 해시값을 비교하여 100% 동일함(무결성)을 입증합니다.  
4. <b>사본을 이용한 분석 및 원본 보관</b>: 분석은 반드시 생성된 이미지 사본(또는 사본의 사본)을 마운트하여 진행하고, 원본 디스크는 안전한 봉인 절차를 거쳐 증거물 보관소에 보관(Chain of Custody)합니다.
