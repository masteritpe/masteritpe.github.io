### 1. 양자머신러닝(QML, Quantum Machine Learning)

**1. 개요**  
- 정의: 양자컴퓨팅의 중첩(Superposition)·얽힘(Entanglement) 원리를 머신러닝 알고리즘에 결합하여 고차원 데이터의 특징추출 및 최적화 연산을 가속하는 융합기술  
- 배경: 고전 컴퓨팅의 지수적 연산복잡도 한계 및 대규모 파라미터 최적화 시간 문제 해소 필요성 증대

**2. 주요 구성요소 및 유형**

| 구분 | 내용 |
|---|---|
| 양자데이터 인코딩 | 고전데이터를 큐비트 상태로 매핑(Amplitude/Angle Encoding) |
| 변분양자회로(VQC) | 파라미터화된 양자게이트로 구성된 학습모델 |
| 하이브리드 방식 | 양자회로(추론)+고전옵티마이저(파라미터 갱신) 결합 |
| 대표알고리즘 | QSVM, QNN, QAOA, VQE |

**3. 핵심 원리**  
- 큐비트의 지수적 상태공간(2^n) 활용으로 고차원 커널함수 계산을 병렬처리  
- NISQ(Noisy Intermediate-Scale Quantum) 환경에서 얕은 회로+고전 피드백 루프로 노이즈 완화  
- 처리절차: 데이터 인코딩 → 양자회로 연산 → 측정(디코딩) → 손실함수 계산 → 고전 옵티마이저로 파라미터 업데이트(반복)

**4. 기대효과 및 고려사항**  
- 효과: 조합최적화·신약개발·금융리스크 모델링 등 고차원 문제 처리속도 향상  
- 고려사항: 큐비트 결함률(Decoherence), 양자-고전 인터페이스 오버헤드, 검증된 양자우위(Quantum Advantage) 사례 부족으로 상용화 초기 단계임을 인지 필요

### 2. 프롬프트 인젝션(Prompt Injection)

**1. 개요**  
- 정의: 공격자가 악의적 지시문을 입력·외부데이터에 삽입하여 LLM의 원래 시스템 지침을 우회, 의도하지 않은 동작을 유발하는 보안 취약점  
- 배경: LLM 기반 챗봇·에이전트의 자연어 명령 특성상 데이터와 명령의 경계가 불명확하여 발생

**2. 유형 분류**

| 유형 | 설명 |
|---|---|
| 직접 인젝션 | 사용자가 직접 악성 프롬프트 입력 |
| 간접 인젝션 | 웹페이지·문서·이메일 등 외부 콘텐츠에 은닉된 지시문을 RAG/에이전트가 읽어 실행 |
| 탈옥(Jailbreak) | 역할극·인코딩 우회로 안전정책(Guardrail) 무력화 |

**3. 공격 메커니즘 및 대응기술**  
- 메커니즘: LLM은 시스템/사용자/데이터 입력을 모두 토큰 시퀀스로 처리하여 우선순위 구분이 취약, "이전 지시를 무시하라"류 명령이 컨텍스트 내 삽입 시 실행됨  
- 대응기술: 입력-출력 경계 구분(Structured Prompting), 입력 필터링 및 이상탐지, 출력 검증(Guardrail LLM), 최소권한 원칙 기반 도구 실행권한 제한, 사용자 승인단계(Human-in-the-loop) 삽입

**4. 기대효과 및 고려사항**  
- 효과: 안전한 에이전틱 AI 도구 실행 및 민감정보 유출 방지  
- 고려사항: 완전 방어 어려우므로 다계층 방어(Defense in Depth) 설계, 지속적 레드팀 테스트 및 OWASP LLM Top10 대응 프로세스 수립 필요

### 3. 에이전틱 AI(Agentic AI)

**1. 개요**  
- 정의: LLM을 두뇌로 하여 목표를 스스로 계획(Planning), 도구 호출(Tool Use), 행동(Action), 결과 관찰(Observation)을 반복 수행하는 자율적 AI 시스템  
- 배경: 단순 질의응답형 생성AI의 한계를 넘어 복잡한 다단계 업무 자동화 요구 증대에 따라 등장

**2. 구성요소**

| 구성요소 | 역할 |
|---|---|
| Planner | 목표를 하위 작업으로 분해 |
| Memory | 단기(컨텍스트)/장기(벡터DB) 기억 관리 |
| Tool/Action | API, 코드실행, 검색 등 외부 도구 호출 |
| Orchestrator | 멀티에이전트 간 역할 분배 및 협업 제어 |

**3. 동작원리**  
- ReAct(Reasoning+Acting) 패턴: 사고→행동→관찰을 루프로 반복하며 목표 달성까지 자율 실행  
- 절차: 목표수신 → Task 분해 → 도구선택/실행 → 결과관찰 → 자기평가(Reflection) → 재계획 또는 종료  
- 멀티에이전트 구조(Supervisor-Worker)로 역할 특화 및 병렬처리 지원

**4. 기대효과 및 고려사항**  
- 효과: 업무 프로세스 종단간(End-to-End) 자동화, 인간 개입 최소화로 생산성 향상  
- 고려사항: 프롬프트 인젝션 등 보안취약점, 무한루프·환각(Hallucination) 전파 위험, 행동 감사로그 및 권한통제(Human-in-the-loop) 체계 필수

### 4. CXL (Compute Express Link)

**1. 개요**  
- 정의: PCIe 물리계층 기반의 캐시코히런트 인터커넥트 표준으로, CPU-가속기-메모리 간 저지연 메모리 확장 및 공유를 지원하는 개방형 규격  
- 배경: 빅데이터·AI 워크로드 확산에 따른 메모리 용량/대역폭 부족 및 이종 컴퓨팅자원 간 효율적 데이터 공유 필요성에서 대두

**2. 프로토콜 구성**

| 프로토콜 | 용도 |
|---|---|
| CXL.io | PCIe 기반 초기화·설정, 비코히런트 I/O |
| CXL.cache | 디바이스가 호스트 메모리를 캐시코히런트 방식 접근 |
| CXL.mem | 호스트가 디바이스 부착 메모리를 직접 접근 |

**3. 핵심 기술 및 활용 유형**  
- Type1(캐시 디바이스), Type2(가속기+메모리), Type3(메모리 확장 디바이스)로 구분  
- 메모리 풀링(Pooling) 및 메모리 스위치를 통한 다중 호스트 간 메모리 공유(CXL 3.0)로 자원 활용률 극대화  
- 캐시 코히런시 프로토콜로 CPU-가속기 간 메모리 일관성 유지, PCIe 대비 낮은 지연시간 확보

**4. 기대효과 및 고려사항**  
- 효과: 메모리 용량 확장, TCO 절감, 이종자원 풀링을 통한 데이터센터 자원효율 극대화  
- 고려사항: 기존 NUMA 대비 지연시간 튜닝 필요, 생태계(OS/펌웨어) 성숙도 및 상호운용성 검증 필요

### 5. 다크 팩토리 (Dark Factory)

**1. 개요**  
- 정의: 조명 등 인간을 위한 환경설비 없이 로봇·AI·IoT가 전 공정을 완전 자율 운영하는 무인 완전자동화 생산공장  
- 배경: 스마트팩토리 고도화, 저출산·고령화에 따른 생산인력 부족, 24시간 무중단 생산을 통한 원가경쟁력 확보 필요성 증대

**2. 핵심 구성요소**

| 구성요소 | 역할 |
|---|---|
| 산업용 로봇/AMR | 조립·이송·검사 등 물리작업 수행 |
| 디지털트윈 | 가상공간 시뮬레이션 기반 공정 사전검증 |
| MES/AI 관제시스템 | 실시간 공정 모니터링 및 자율 의사결정 |
| 산업용 5G/IIoT 센서 | 초저지연 데이터 수집 및 장비 간 통신 |

**3. 운영 원리**  
- 센서데이터 수집 → 디지털트윈 시뮬레이션 → AI 기반 이상탐지/예측정비 → 자율제어(무인 대응) → 결과 피드백의 폐루프(Closed-loop) 구조로 인간 개입없이 자율 운영  
- 완전 무인화 전 단계로 원격관제(Lights-out Operation)를 거쳐 단계적 전환

**4. 기대효과 및 고려사항**  
- 효과: 생산성 극대화, 불량률 감소, 에너지비용(조명·냉난방) 절감, 위험작업 대체를 통한 안전성 향상  
- 고려사항: 초기 투자비 부담, 설비 전면 고장 시 대응체계, 사이버보안 위협 확대에 따른 OT보안 강화 필요

### 6. RAG(Retrieval-Augmented Generation)

**1. 개요**  
- 정의: LLM이 응답 생성 전 외부 지식저장소에서 관련 정보를 검색하여 프롬프트에 결합, 정확성과 최신성을 보강하는 생성AI 아키텍처  
- 배경: LLM의 환각(Hallucination) 현상, 학습데이터 시점 제한(Knowledge Cutoff), 재학습 비용 문제 해소 필요성에서 등장

**2. 구성요소**

| 구성요소 | 역할 |
|---|---|
| 임베딩 모델 | 문서/질의를 벡터로 변환 |
| 벡터DB | 임베딩 저장 및 유사도 검색(ANN) |
| Retriever | 질의 관련 문서 Top-K 검색 |
| Generator(LLM) | 검색결과+질의 결합하여 답변 생성 |

**3. 처리절차**  
- 인덱싱: 문서 청킹(Chunking) → 임베딩 → 벡터DB 저장  
- 질의처리: 질의 임베딩 → 유사도검색(Retrieval) → 재랭킹(Reranking) → 프롬프트 증강(Augmentation) → LLM 생성(Generation)  
- 고도화 기법: 하이브리드검색(키워드+벡터), GraphRAG, 에이전틱 RAG(반복 검증 검색)

**4. 기대효과 및 고려사항**  
- 효과: 최신·전문 도메인 지식 반영, 환각 감소, 출처 근거 제시로 신뢰성 향상, 재학습 없이 지식 갱신 가능  
- 고려사항: 검색 품질이 답변 품질 좌우, 청킹전략·임베딩 성능 튜닝 필요, 검색 지연시간 및 벡터DB 운영비용 고려

### 7. 소버린(Sovereign) AI

**1. 개요**  
- 정의: 특정 국가·조직이 자국의 데이터, 인프라, 인력을 기반으로 자체 개발·운영하여 AI 기술에 대한 독립적 주권을 확보하는 전략 및 AI 시스템  
- 배경: 글로벌 빅테크 AI 종속 심화, 데이터 주권·안보·문화적 정체성 보호 필요성, 각국의 AI 자립 정책(반도체·에너지 포함) 추진에 따라 부상

**2. 핵심 구성요소**

| 구성요소 | 내용 |
|---|---|
| 자국어/문화 특화 LLM | 자국어 코퍼스 기반 파운데이션모델 구축 |
| 자체 컴퓨팅 인프라 | 국가 GPU팜, 자국 데이터센터 운영 |
| 데이터 거주성(Data Residency) | 국내 법제(개인정보보호법 등) 준수 데이터 보관 |
| 규제·거버넌스 체계 | AI 안전성·윤리 자체 규율 |

**3. 추진 방식**  
- 자체 파운데이션 모델 개발(Full Sovereign) 또는 오픈소스 모델 파인튜닝·현지화(Hybrid Sovereign) 방식으로 구분  
- 국가 차원 GPU 인프라 확보(AI 반도체 자립) 및 산·학·연 협력 기반 데이터 생태계 구축  
- 예: 국가별 초거대AI 프로젝트, 공공부문 On-premise/Private Cloud AI 전환

**4. 기대효과 및 고려사항**  
- 효과: 국가 안보·데이터주권 확보, 자국어 서비스 품질 향상, AI 산업 생태계 자립 및 경제효과 창출  
- 고려사항: 글로벌 모델 대비 성능·비용 격차, 막대한 컴퓨팅 투자비, 국제 협력과 폐쇄적 자립 간 균형전략 필요

### 8. 가상메모리

**1. 개요**  
- 정의: 물리메모리 용량 제약을 극복하기 위해 보조기억장치(디스크)를 활용, 프로세스에 실제보다 큰 논리적 주소공간을 제공하는 메모리 관리 기법  
- 배경: 다중 프로세스 동시실행 환경에서 물리메모리 한계 극복 및 프로세스 간 메모리 보호·독립적 주소공간 제공 필요성에서 도입

**2. 핵심 구성요소**

| 구성요소 | 역할 |
|---|---|
| 페이지테이블 | 논리주소-물리주소 매핑정보 관리 |
| TLB | 페이지테이블 캐시로 주소변환 가속 |
| 페이지폴트 핸들러 | 미적재 페이지 접근 시 예외처리 |
| 스왑영역 | 비활성 페이지 임시 저장공간(디스크) |

**3. 동작원리**  
- 주소변환: CPU가 논리주소 발생 → TLB조회(Hit시 즉시변환) → Miss시 페이지테이블 조회 → 물리주소 변환  
- 페이지폴트 처리: 요청 페이지 미적재 시 폴트 발생 → 디스크에서 페이지 로드 → 페이지테이블 갱신 → 명령 재실행  
- 페이지교체 알고리즘(LRU, Clock 등)으로 프레임 부족 시 희생페이지 선정, Locality(참조 지역성) 원리 기반 Working Set 관리로 스래싱(Thrashing) 방지

**4. 기대효과 및 고려사항**  
- 효과: 물리메모리 초과 프로그램 실행 가능, 프로세스 간 메모리 보호 및 효율적 다중작업 지원  
- 고려사항: 과도한 스와핑에 따른 스래싱 성능저하, TLB Miss 최소화를 위한 페이지크기·교체정책 최적화 필요

### 9. IEEE 802.11bn

**1. 개요**  
- 정의: Wi-Fi 8로 명명되는 차세대 무선랜 표준으로, 극도로 안정적이고 지연시간이 낮은 초고신뢰 연결(Ultra High Reliability, UHR)을 목표로 IEEE에서 표준화 진행 중인 규격  
- 배경: 기존 Wi-Fi 7(802.11be)의 속도 중심 발전을 넘어 산업용/실시간 응용에서 요구하는 연결 신뢰성·지연 안정성 확보 필요성에서 추진

**2. 주요 특징**

| 항목 | 내용 |
|---|---|
| 목표 | 처리량보다 신뢰성/지연 안정성(Latency Bound) 우선 |
| 멀티AP 협업 | 다중 AP 간 조정으로 로밍 끊김 최소화(Seamless Roaming) |
| 다중링크 강화 | MLO 고도화로 링크 이중화 및 신뢰성 향상 |
| 적응형 자원할당 | 트래픽 우선순위 기반 스케줄링 강화 |

**3. 핵심 기술요소**  
- Coordinated Multi-AP: 인접 AP 간 협업 빔포밍·자원조정으로 간섭 최소화 및 이동 중 무끊김 연결 지원  
- 향상된 MLO(Multi-Link Operation): 다중 주파수대역(2.4/5/6GHz) 동시 활용한 링크 이중화로 패킷손실 대응  
- 지연시간 예측성(Deterministic Latency) 강화로 산업 제어·XR 등 실시간성 요구 응용 지원

**4. 기대효과 및 고려사항**  
- 효과: 산업현장·스마트팩토리·XR 등 신뢰성 필수 환경에서 안정적 무선연결 제공, 로밍환경 사용자경험 개선  
- 고려사항: 표준 확정(2028년경 예상) 전 초안 단계로 상용화 시점 불확실, 기존 AP 인프라와의 하위호환성 및 전환비용 고려 필요

### 10. 기밀 컴퓨팅(Confidential Computing, CC)

**1. 개요**  
- 정의: 하드웨어 기반 신뢰실행환경(TEE)을 활용하여 데이터의 저장(At Rest)·전송(In Transit) 뿐 아니라 처리 중(In Use) 상태까지 암호화·격리 보호하는 컴퓨팅 보안 기술  
- 배경: 클라우드·멀티테넌트 환경에서 처리중 데이터가 메모리 덤프, 인프라 관리자, 하이퍼바이저 등에 노출되는 보안 공백 해소 필요성에서 등장

**2. 핵심 구성요소**

| 구성요소 | 역할 |
|---|---|
| TEE(Trusted Execution Environment) | 격리된 보안 실행공간(Enclave) 제공 |
| 원격증명(Remote Attestation) | 실행환경 무결성 원격 검증 |
| 하드웨어 루트오브트러스트 | CPU 내장 암호키 기반 신뢰 앵커 |
| 대표기술 | Intel SGX/TDX, AMD SEV, ARM CCA |

**3. 핵심 원리**  
- 메모리 암호화 격리: 인클레이브 내 데이터는 CPU 내부에서만 복호화되며 OS·하이퍼바이저·타 프로세스도 접근 불가  
- 절차: 인클레이브 생성 → 코드/데이터 로드 → 원격증명으로 무결성 검증 → 암호화 상태로 연산 수행 → 결과만 외부 반출  
- 클라우드 사업자조차 고객 데이터 내용을 볼 수 없는 "Zero Trust to Cloud Provider" 모델 구현

**4. 기대효과 및 고려사항**  
- 효과: 멀티클라우드 환경 민감데이터(금융·의료·개인정보) 안전처리, 데이터 협업(연합학습) 시 프라이버시 보장  
- 고려사항: TEE 자체 취약점(사이드채널 공격) 가능성, 성능 오버헤드, 벤더별 구현 상이로 표준화(Confidential Computing Consortium) 대응 필요

### 11. 디지털 포용법

**1. 개요**  
디지털 포용법은 디지털 전환 과정에서 발생하는 정보격차·디지털 소외 문제를 해소하기 위해 고령자, 장애인, 저소득층 등 디지털 취약계층의 디지털 접근성·역량·활용 기회를 보장하는 법적 근거를 마련한 법률임. 키오스크·모바일 뱅킹 등 비대면 서비스 확산에 따른 소외 심화가 입법 배경임.

**2. 주요 구성 요소**

| 구분 | 내용 |
|---|---|
| 디지털포용위원회 | 정책 심의·조정 기구(국무총리 소속) |
| 실태조사 | 디지털정보격차 실태조사 정기 실시 |
| 디지털배움터 | 취약계층 대상 디지털 역량 교육 |
| 접근성 기준 | 키오스크, 앱·웹 접근성 의무화 |
| 지원기관 지정 | 디지털포용센터, 전담기관 지정 |

**3. 상세 설명**  
법 적용 대상은 고령자, 장애인, 농어민, 저소득층, 북한이탈주민 등이며, 정부·지자체·공공기관에 디지털포용 시행계획 수립 의무를 부과함. 키오스크 등 무인정보단말기는 접근성 준수 설계(음성안내, 휠체어 접근 높이 등)를 의무화하고, 민간 사업자 대상 인증·지원 제도를 병행함. 기존 「지능정보화 기본법」상 정보격차해소 조항을 확대·독립 법제화한 성격을 가짐.

**4. 기대효과 및 고려사항**  
디지털 소외계층의 사회·경제적 활동 참여 기회 확대, 비대면 서비스 이용률 제고가 기대됨. 다만 실효성 확보를 위해 예산·인력 확충, 민간 서비스 접근성 강제력 강화, 지역 간 인프라 격차 해소 방안이 병행 검토되어야 함.

### 12. MCP(Model Context Protocol)

**1. 개요**  
MCP는 Anthropic이 2024년 공개한 개방형 표준 프로토콜로, LLM 기반 애플리케이션이 외부 데이터 소스·도구·시스템과 표준화된 방식으로 연결되도록 지원함. 기존 LLM 연동 시 서비스별 커스텀 통합이 반복되는 "N×M 통합 문제"를 해소하기 위해 등장하였으며, "AI를 위한 USB-C"로 비유됨.

**2. 구성 요소**

| 구성요소 | 역할 |
|---|---|
| Host | LLM 애플리케이션(예: Claude Desktop) |
| Client | Host 내 MCP 서버 연결 관리 모듈 |
| Server | 데이터·도구 제공, 표준 API 노출 |
| Resources | 서버가 제공하는 컨텍스트 데이터 |
| Tools | 모델이 호출 가능한 실행 기능 |
| Prompts | 재사용 가능한 프롬프트 템플릿 |

**3. 상세 설명**  
JSON-RPC 2.0 기반 클라이언트-서버 구조로 동작하며, stdio 또는 HTTP/SSE 전송 방식을 지원함. 서버는 Resources(읽기 데이터), Tools(실행 가능 함수), Prompts(템플릿)를 표준 스키마로 노출하고, Host는 사용자 승인 하에 이를 모델 컨텍스트에 주입함. Capability negotiation을 통해 지원 기능을 협상하며, 보안을 위해 사용자 동의(consent) 절차를 명시함.

**4. 기대효과 및 고려사항**  
개발자는 1회 구현으로 다수 LLM 애플리케이션과 연동 가능해 통합 비용이 절감되고, 생태계 표준화로 서드파티 도구 확산이 촉진됨. 다만 외부 서버 신뢰성 검증, 프롬프트 인젝션 등 보안 위협 대응, 권한 스코프 관리 체계 마련이 고려되어야 함.

### 13. CMMI v3.0(Capability Maturity Model Integration 3.0)

**1. 개요**  
CMMI v3.0은 ISACA가 2023년 발표한 프로세스 성숙도 모델 최신판으로, 조직의 프로세스 역량을 평가·개선하기 위한 프레임워크임. 기존 v2.0 대비 문서 부담을 줄이고 신속한 비즈니스 성과(Rapid Impact) 창출과 AI·데이터 관리 요소를 반영한 것이 특징임.

**2. 성숙도 수준 및 구조**

| 레벨 | 명칭 |
|---|---|
| Level 1 | Initial |
| Level 2 | Managed |
| Level 3 | Defined |
| Level 4 | Quantitatively Managed |
| Level 5 | Optimizing |

프랙티스 영역은 Doing(수행), Managing(관리), Enabling(지원), Improving(개선) 4개 카테고리로 재편됨.

**3. 상세 설명**  
v3.0은 성과(performance) 중심 평가로 전환하여, 단순 프로세스 준수 여부가 아닌 실제 비즈니스 가치 창출 여부를 심사(Benchmark Appraisal)함. AI 활용, 안전(Safety), 데이터 관리(Data Management) 프랙티스 영역이 신설·강화되었고, 조직 규모·성숙 단계에 맞춘 맞춤형 적용(Right-sizing) 가이드를 제공함. 인증은 SCAMPI 유사 방식의 Appraisal을 통해 부여됨.

**4. 기대효과 및 고려사항**  
프로세스 표준화를 통한 품질·생산성 향상, 고객 신뢰도 제고 효과가 있음. 다만 국내 조직은 문서 중심 심사 관행에서 성과 중심 심사로 전환 대응이 필요하며, AI 프랙티스 도입에 따른 내부 역량 확보가 요구됨.

### 14. 지오패트리에이션(Geopatriation)

**1. 개요**  
지오패트리에이션은 해외 클라우드·데이터센터에 위치한 자국 데이터 및 IT 워크로드를 데이터 주권(Data Sovereignty) 확보를 위해 자국 영토 내로 회수·재배치하는 전략을 의미함. 글로벌 클라우드 종속 심화, 개인정보보호법·GDPR 등 데이터 지역화(Data Localization) 규제 강화가 등장 배경임.

**2. 주요 유형**

| 유형 | 내용 |
|---|---|
| 물리적 재배치 | 데이터센터 자국 이전 |
| 논리적 격리 | 자국 리전 내 저장·처리 강제 |
| 하이브리드 전략 | 민감 데이터만 국내 보관, 나머지 해외 유지 |
| 주권형 클라우드 | 자국법 적용 독립 클라우드 구축 |

**3. 상세 설명**  
공공·금융 등 민감 데이터를 보유한 기관은 해외 사업자의 법적 관할권(예: 미국 클라우드법)에 자국 데이터가 노출되는 위험을 회피하기 위해 자국 내 리전·주권형 클라우드로 이전함. 이는 데이터 현지화(Localization)에서 한 단계 나아가 기존 해외 배치 데이터를 실제 국내로 "귀환"시키는 능동적 조치라는 점에서 구분됨. EU의 Gaia-X, 국내 공공기관 클라우드 보안인증(CSAP) 정책이 유사한 맥락임.

**4. 기대효과 및 고려사항**  
데이터 주권 확보, 법적 리스크 완화, 국내 클라우드 산업 활성화 효과가 기대됨. 다만 이전 비용, 글로벌 서비스 성능 저하, 국내 인프라 확충 필요성 등이 고려되어야 하며, 국제 규제와의 상충 여부 검토가 필요함.

### 15. AI-RAN(Artificial Intelligence in Radio Access Network)

**1. 개요**  
AI-RAN은 무선접속망(RAN)에 인공지능 기술을 결합하여 네트워크 자원을 지능적으로 운용하고, 나아가 RAN 인프라 자체를 AI 연산 플랫폼으로 활용하는 개념임. 5G/6G 트래픽 증가와 기지국 전력·운영 효율 문제, AI 추론 수요 급증이 등장 배경이며, Nvidia·SoftBank·T-Mobile 등이 참여하는 AI-RAN Alliance가 표준화를 주도함.

**2. 주요 유형**

| 유형 | 내용 |
|---|---|
| AI-for-RAN | AI로 RAN 성능 최적화(빔포밍, 스케줄링) |
| AI-and-RAN | 기지국 유휴 자원에 AI 워크로드 동시 처리 |
| AI-on-RAN | RAN 하드웨어(GPU 기반) 위에서 AI 서비스 제공 |

**3. 상세 설명**  
기존 RAN은 통신 전용 ASIC 기반이었으나, AI-RAN은 GPU·가속기 기반 범용 서버로 RAN 기능(vRAN)을 소프트웨어화하고, 트래픽이 적은 시간대 유휴 컴퓨팅 자원을 엣지 AI 추론(RAG, 실시간 비전 분석 등)에 활용함. 이를 통해 네트워크 슬라이싱, 실시간 채널 예측, 에너지 절감형 기지국 제어 등이 가능해짐.

**4. 기대효과 및 고려사항**  
기지국 자원 활용률 제고, 엣지 AI 서비스 신규 수익 창출, 네트워크 운영비 절감이 기대됨. 다만 통신 QoS와 AI 워크로드 간 자원 경쟁 관리, 실시간성 보장, 표준 인터페이스 정립이 향후 과제임.

### 16. ISO/IEC 25010:2023

**1. 개요**  
ISO/IEC 25010은 소프트웨어 및 시스템 품질 요구사항·평가(SQuaRE) 시리즈의 품질모델 표준으로, 2023년 개정판은 기존 2011년판의 품질특성을 재구조화하고 안전성(Safety)을 신규 특성으로 추가하여 AI·자율시스템 등 최신 소프트웨어 환경을 반영함.

**2. 품질모델 구성**

| 모델 | 품질특성(주요) |
|---|---|
| Product Quality Model | 기능적합성, 성능효율성, 호환성, 상호작용역량, 신뢰성, 보안성, 유지보수성, 이식성, 안전성(신규) |
| Quality in Use Model | 효과성, 효율성, 만족도, 위험회피성, 활용범위 |

**3. 상세 설명**  
기존 "사용성(Usability)"을 "상호작용역량(Interaction Capability)"으로 명칭·범위를 확장하여 사용자·시스템 간 상호작용 전반(접근성, 사용자 오류 방지 등)을 포괄함. 신설된 안전성은 인명·재산·환경에 대한 위해 방지 능력을 평가 항목으로 명시하여 자율주행·의료기기 등 고위험 SW에 대응함. 각 특성은 하위 부특성으로 세분화되며 정량적 측정지표(25023 등)와 연계되어 평가됨.

**4. 기대효과 및 고려사항**  
품질 요구사항 명세·평가의 국제 정합성 확보, 안전 필수 시스템 품질보증 체계 강화가 기대됨. 국내 SW 품질인증(GS인증 등) 및 발주 시 품질기준 개정 반영이 필요하며, 조직은 기존 품질모델 매핑·전환 작업이 요구됨.

### 17. Wi-Fi 7

**1. 개요**  
Wi-Fi 7(IEEE 802.11be)은 2024년 표준화 완료된 차세대 무선랜 규격으로, 초고속·초저지연·다중 접속을 요구하는 AR/VR, 8K 영상, 산업용 IoT 환경 대응을 위해 등장함. 기존 Wi-Fi 6/6E 대비 대역폭·속도·연결 안정성이 대폭 향상됨.

**2. 주요 특징**

| 항목 | Wi-Fi 6(E) | Wi-Fi 7 |
|---|---|---|
| 채널 대역폭 | 최대 160MHz | 최대 320MHz |
| 변조방식 | 1024-QAM | 4096-QAM |
| 최대속도(이론) | 9.6Gbps | 약 46Gbps |
| 다중접속 | OFDMA | MLO 지원 |
| 지연시간 | 상대적 높음 | 저지연 |

**3. 상세 설명**  
핵심 기술은 다중링크운용(MLO, Multi-Link Operation)으로, 2.4/5/6GHz 대역을 동시에 활용해 링크 결합·부하분산·끊김없는 전환을 구현함. Multi-RU(Resource Unit) 할당으로 자원 활용 효율을 높이고, 4096-QAM 및 320MHz 채널을 통해 전송률을 극대화함. 또한 향상된 오류정정(코딩률 개선)으로 혼잡 환경에서도 안정적 처리량을 유지함.

**4. 기대효과 및 고려사항**  
초고속·초저지연 서비스(클라우드 게이밍, 산업 자동화) 지원과 다수 기기 동시접속 환경 개선이 기대됨. 다만 6GHz 대역 국가별 규제 정합성, 단말 보급 확대, 기존 인프라와의 호환성 확보가 도입 시 고려사항임.

### 18. 소프트웨어 테스트

**1. 개요**  
소프트웨어 테스트는 개발된 소프트웨어가 요구사항을 충족하고 결함이 없는지 검증·확인하는 활동으로, 품질 보증 및 결함의 조기 발견을 통한 개발비용 절감을 목적으로 수행됨. V-모델에 따라 개발 단계별로 대응되는 테스트 레벨이 존재함.

**2. 테스트 레벨 및 기법**

| 레벨 | 대상 | 대응 개발단계 |
|---|---|---|
| 단위테스트 | 모듈/함수 | 상세설계 |
| 통합테스트 | 모듈 간 인터페이스 | 아키텍처설계 |
| 시스템테스트 | 전체 시스템 | 요구분석 |
| 인수테스트 | 사용자 요구 충족 | 요구분석 |

기법상으로는 화이트박스(구조 기반: 구문/분기/조건 커버리지)와 블랙박스(기능 기반: 동등분할, 경계값분석, 결정테이블)로 구분됨.

**3. 상세 설명**  
테스트 프로세스는 테스트 계획→설계(테스트케이스 작성)→실행→결과분석 및 결함관리 순으로 진행됨. 회귀테스트를 통해 수정 후 기존 기능 영향도를 검증하며, 최근에는 CI/CD 파이프라인 내 자동화 테스트(단위·API·UI 자동화)와 정적분석 도구가 결합되어 상시 품질 검증체계를 구축함.

**4. 기대효과 및 고려사항**  
결함의 조기 발견으로 유지보수 비용 절감, 소프트웨어 신뢰성 제고 효과가 있음. 테스트 커버리지와 비용 간 균형, 테스트 자동화 유지보수 부담, 비기능 요구사항(성능·보안) 테스트 강화가 고려되어야 함.

### 19. 공공데이터 품질인증

**1. 개요**  
공공데이터 품질인증은 행정안전부 및 한국지능정보사회진흥원(NIA)이 공공기관이 관리하는 데이터의 품질관리 수준 및 데이터 자체의 품질을 평가하여 인증하는 제도로, 「공공데이터의 제공 및 이용 활성화에 관한 법률」에 근거함. 공공데이터 개방 확대에 따른 데이터 신뢰성·활용성 확보가 목적임.

**2. 인증 유형**

| 구분 | 대상 | 평가 내용 |
|---|---|---|
| 품질관리수준 인증 | 기관의 품질관리 체계 | 계획, 측정, 개선 프로세스 |
| 데이터 품질인증 | 개별 데이터셋 | 정확성, 완전성, 최신성, 일관성 등 |

**3. 상세 설명**  
평가는 데이터 품질 진단(정량지표: 결측률, 오류율, 표준준수율 등)과 관리체계 진단(PDCA 기반 품질관리 프로세스 성숙도)으로 구성됨. 신청기관은 자체 품질진단 후 서류·현장심사를 거쳐 인증등급을 부여받으며, 유효기간(통상 3년) 내 사후관리·재심사가 이루어짐. 인증 결과는 공공데이터포털 개방 데이터 신뢰도 표시에 반영됨.

**4. 기대효과 및 고려사항**  
데이터 품질 향상을 통한 데이터 활용 서비스(민간 앱, AI 학습데이터 등) 신뢰성 제고, 데이터 기반 행정 효율화가 기대됨. 다만 인증 취득 후 지속적 품질 유지 관리, 소규모 기관의 인증 대응 역량 지원 방안이 병행 검토되어야 함.

### 20. 데이터베이스 트랜잭션 회복(Recovery) 기법

**1. 개요**  
트랜잭션 회복은 시스템 장애(전원장애, 디스크 오류, 트랜잭션 오류 등) 발생 시 데이터베이스를 장애 이전의 일관된 상태로 복구하는 기법으로, 트랜잭션의 원자성(Atomicity)과 내구성(Durability) 보장을 목적으로 함. 로그(Log) 기반 기록을 통해 Redo/Undo를 수행하는 것이 핵심 원리임.

**2. 주요 회복 기법 유형**

| 기법 | 내용 |
|---|---|
| 즉시갱신(Immediate Update) | 커밋 전 버퍼 변경사항을 DB에 즉시 반영, 로그로 Undo/Redo 수행 |
| 지연갱신(Deferred Update) | 커밋 시점까지 DB 반영 지연, Redo만 필요 |
| 체크포인트(Checkpoint) | 특정 시점 로그·버퍼 상태 기록, 회복 범위(Redo/Undo 대상) 축소 |
| 그림자페이징(Shadow Paging) | 페이지 테이블 이중화로 원자적 커밋 구현 |
| ARIES | Analysis-Redo-Undo 3단계 기반 로그 회복 알고리즘 |

**3. 상세 설명**  
로그기반 회복은 트랜잭션 시작·변경·커밋 정보를 로그에 선기록(Write-Ahead Logging)한 후, 장애 시 로그를 이용해 미완료 트랜잭션은 Undo, 완료(커밋)되었으나 반영 안 된 트랜잭션은 Redo함. 체크포인트는 장애 시점부터 로그 전체를 스캔하는 부담을 줄이기 위해 주기적으로 활성 트랜잭션 목록과 버퍼 상태를 기록하여 회복 시작점을 단축함. ARIES는 분석(Analysis)단계에서 장애 시점 활성/커밋 트랜잭션을 식별하고, Redo단계에서 전체 변경을 재반영, Undo단계에서 미완료 트랜잭션을 롤백하는 3단계 절차로 구성되어 상업용 DBMS의 표준 회복 방식으로 활용됨.

**4. 기대효과 및 고려사항**  
장애 발생 시에도 데이터 일관성·무결성을 보장하여 서비스 신뢰성을 확보함. 다만 로그 기록에 따른 I/O 오버헤드, 체크포인트 주기 설정에 따른 회복시간과 성능 간 트레이드오프, 분산 환경에서의 2단계 커밋(2PC)과의 연계 방안이 고려되어야 함.

### 21. 마이데이터 2.0

마이데이터 2.0은 개인이 자신의 정보를 능동적으로 관리·활용하도록 지원하는 마이데이터 제도의 고도화 버전으로, 기존 금융분야 중심 서비스의 한계를 극복하고 全산업 데이터 전송요구권 확대를 통해 개인정보 자기결정권을 강화한 정책 체계임.

### 22. OSI 7계층(Layer)

**1. 개요**  
OSI(Open Systems Interconnection) 7계층은 ISO가 제정한 이종 시스템 간 통신을 위한 표준 참조모델로, 네트워크 기능을 7개 계층으로 분리하여 계층 간 독립성과 상호운용성을 확보함.

**2. 계층별 설명**

| 계층 | 명칭 | 주요기능 | 대표 프로토콜/장비 |
|---|---|---|---|
| 7 | 응용(Application) | 사용자 서비스 제공 | HTTP, FTP, SMTP |
| 6 | 표현(Presentation) | 데이터 형식 변환, 암호화·압축 | SSL/TLS, JPEG |
| 5 | 세션(Session) | 연결 설정·유지·종료, 동기화 | NetBIOS, RPC |
| 4 | 전송(Transport) | 종단간 신뢰성 전송, 오류제어 | TCP, UDP |
| 3 | 네트워크(Network) | 라우팅, 논리주소(IP) | IP, ICMP, 라우터 |
| 2 | 데이터링크(Data Link) | 프레임화, 오류검출, MAC주소 | Ethernet, 스위치 |
| 1 | 물리(Physical) | 비트 전송, 전기·광 신호 | 케이블, 허브, NIC |

**3. 상세 설명**  
상위계층(5~7)은 응용프로그램 지원, 하위계층(1~4)은 실제 데이터 전송 담당. 캡슐화(Encapsulation)를 통해 각 계층 헤더가 추가되며, TCP/IP 4계층 모델과 매핑되어 실무에서 활용됨.

**4. 기대효과 및 고려사항**  
계층 분리로 프로토콜 독립적 개발·유지보수 용이, 장애구간 식별(계층별 트러블슈팅) 효율화. 다만 이론모델로서 실제 구현은 TCP/IP 모델 기반임에 유의.

### 23. OWASP Top 10 : 2025

**1. 개요**  
OWASP Top 10은 웹 애플리케이션 보안 취약점 중 위험도가 높은 10개 항목을 선정한 국제 표준 가이드로, 2025년 개정판은 공급망 보안 위협과 예외처리 결함 등 최신 위협 동향을 반영하여 항목을 재정비함.

**2. 2025년 주요 항목**

| 순위 | 항목 |
|---|---|
| A01 | 접근통제 실패(Broken Access Control) |
| A02 | 보안설정 오류(Security Misconfiguration) |
| A03 | 소프트웨어 공급망 실패(Software Supply Chain Failures) |
| A04 | 암호화 실패(Cryptographic Failures) |
| A05 | 인젝션(Injection) |
| A06 | 안전하지 않은 설계(Insecure Design) |
| A07 | 인증 실패(Authentication Failures) |
| A08 | 소프트웨어/데이터 무결성 실패 |
| A09 | 로깅·경보 실패 |
| A10 | 예외상황 처리 오류(신규) |

**3. 상세 설명**  
기존 "취약·구식 컴포넌트"는 SBOM·오픈소스 종속성 리스크를 포괄하는 "공급망 실패"로 확대·상향(3위)되었고, SSRF는 접근통제 범주로 통합됨. 신규 항목인 예외처리 오류는 미처리 예외로 인한 정보노출·서비스거부를 반영함.

**4. 기대효과 및 고려사항**  
개발단계 SBOM 관리, 시큐어코딩 교육, 정기 취약점 스캐닝(SAST/DAST), CI/CD 파이프라인 내 자동 보안검증 체계 구축이 필요함.

### 24. LLMOps(Large Language Model Operations)

**1. 개요**  
LLMOps는 대규모 언어모델(LLM)의 개발·배포·운영 전 과정을 체계적으로 관리하는 방법론으로, MLOps 원칙을 LLM 특성(프롬프트, 파인튜닝, 대규모 추론비용)에 맞게 확장한 개념임.

**2. 구성요소**

| 영역 | 내용 |
|---|---|
| 데이터/프롬프트관리 | 프롬프트 버전관리, 데이터셋 큐레이션 |
| 모델개발 | Fine-tuning, RAG, RLHF |
| 평가(Evaluation) | 정확도, 환각(Hallucination) 측정, A/B테스트 |
| 배포 | 서빙 인프라(vLLM 등), 캐싱, 오토스케일링 |
| 모니터링 | 응답품질, 지연시간, 토큰비용, 드리프트 감지 |
| 거버넌스 | 가드레일, 프롬프트 인젝션 방어, 감사로그 |

**3. 상세 설명**  
전통 MLOps와 달리 (1)프롬프트 엔지니어링이 핵심 자산, (2)벡터DB 연계 RAG 파이프라인 관리, (3)토큰 단위 비용·지연 최적화, (4)유해출력·환각 방지를 위한 실시간 가드레일이 요구됨. CI/CD는 프롬프트·모델 버전 배포 파이프라인으로 확장됨.

**4. 기대효과 및 고려사항**  
모델 품질의 지속적 개선, 운영비용 절감, 규제대응력 강화가 기대됨. 고려사항으로 데이터 프라이버시, 모델 편향 관리, 지속적 재학습 체계 확보가 필요함.

### 25. 대수의 법칙과 중심극한정리

**1. 개요**  
대수의 법칙(Law of Large Numbers)과 중심극한정리(Central Limit Theorem)는 표본을 이용한 통계적 추론의 이론적 근거를 제공하는 확률론의 핵심 정리로, 데이터 분석·품질관리·머신러닝 성능평가 등에 광범위하게 활용됨.

**2. 개념 비교**

| 구분 | 대수의 법칙 | 중심극한정리 |
|---|---|---|
| 정의 | 표본크기 증가시 표본평균이 모평균에 수렴 | 표본크기 증가시 표본평균 분포가 정규분포에 근사 |
| 초점 | 수렴(값의 근접) | 분포(형태)의 근사 |
| 조건 | 독립·동일분포(i.i.d), n→∞ | i.i.d, 유한분산, n≥30 권장 |
| 활용 | 몬테카를로 시뮬레이션 근거 | 신뢰구간·가설검정 근거 |

**3. 상세 설명**  
대수의 법칙은 "약법칙(확률수렴)"과 "강법칙(거의확실수렴)"으로 구분되며, 반복 시행 시 평균이 안정화됨을 보장. 중심극한정리는 원분포 형태와 무관하게 표본평균의 분포가 N(μ, σ²/n)에 근사함을 보여 정규분포 기반 통계기법(z검정, t검정) 적용을 정당화함.

**4. 기대효과 및 고려사항**  
표본크기 설계, A/B테스트, 품질관리(SPC) 등 실무 통계분석의 이론적 토대가 됨. 표본 독립성 위배·이상치 존재시 정리 적용에 유의 필요.

### 26. AI 디지털교과서

**1. 개요**  
AI 디지털교과서(AIDT)는 인공지능 기술을 활용하여 학습자 수준을 진단하고 맞춤형 학습경로를 제공하는 차세대 교과서로, 교육부가 2025년부터 단계적으로 도입한 에듀테크 정책임.

**2. 주요 특징**

| 구분 | 내용 |
|---|---|
| 대상과목 | 수학·영어·정보 등(단계적 확대) |
| 핵심기능 | 맞춤학습, 실시간 진단·피드백, 학습분석 대시보드 |
| 활용주체 | 학생-교사-보호자 연계 |
| 기반기술 | 학습분석(LA), 자연어처리, 추천알고리즘 |

**3. 상세 설명**  
(1)AI가 학습자 응답을 분석해 취약영역을 진단하고 난이도별 문항을 추천하는 적응형학습(Adaptive Learning) 구현, (2)교사에게는 학급단위 학습현황 대시보드 제공으로 수업설계 지원, (3)클라우드 기반 플랫폼으로 기기·교실 환경과 연동, (4)개인정보보호를 위한 학습데이터 비식별화 처리 필요.

**4. 기대효과 및 고려사항**  
학습격차 해소, 교사 행정부담 완화, 데이터 기반 교육정책 수립 지원 기대. 다만 디지털 기기 의존 심화, 학생 학습데이터 프라이버시 보호, 교사 디지털 역량 격차, 저소득층 디지털 접근성 격차 해소가 병행 과제임.

### 27. IT 프로젝트 관리에서의 리스크 대응

**1. 개요**  
리스크 대응(Risk Response)은 프로젝트 수행 중 식별·분석된 리스크에 대해 부정적 영향을 최소화하고 긍정적 기회를 극대화하기 위한 계획적 대응활동으로, PMBOK 리스크관리 프로세스의 핵심 단계임.

**2. 대응전략(부정적 리스크 기준)**

| 전략 | 개념 | 사례 |
|---|---|---|
| 회피(Avoid) | 리스크 원인 제거, 계획변경 | 위험기술 미채택, 요구사항 축소 |
| 전이(Transfer) | 제3자에게 리스크·책임 이전 | 보험가입, 외주계약(SLA) |
| 완화(Mitigate) | 발생확률·영향도 감소 | 이중화 설계, 사전 테스트 강화 |
| 수용(Accept) | 대응 없이 발생시 대처(예비비 편성) | 컨틴전시 예비, 사후대응계획 |
| 에스컬레이션(Escalate) | 권한 밖 리스크를 상위 조직에 이관 | 조직 전체 정책 리스크 보고 |

**3. 상세 설명**  
리스크 대응전략 선정 시 리스크 확률·영향도 매트릭스(정성적 분석) 및 EMV(기대금전가치, 정량적 분석)를 활용하여 우선순위 결정. 대응계획 수립 후 잔존리스크(Residual Risk)와 2차리스크(Secondary Risk)를 재평가하고 리스크 관리대장(Risk Register)에 등록·모니터링함.

**4. 기대효과 및 고려사항**  
예산·일정 초과 최소화, 프로젝트 성공률 제고가 기대됨. 고려사항으로 대응비용과 효과의 균형(비용대비효과), 정기적 리스크 재평가 체계 및 이해관계자 커뮤니케이션이 필요함.

### 28. 스푸핑(Spoofing) 공격

**1. 개요**  
스푸핑은 공격자가 신뢰할 수 있는 대상(IP, MAC, DNS, 이메일 등)으로 자신을 위장하여 정상 사용자·시스템을 속이고 정보를 탈취하거나 통신을 가로채는 사회공학적·기술적 공격기법임.

**2. 주요 유형**

| 유형 | 설명 | 대응방안 |
|---|---|---|
| IP 스푸핑 | 송신자 IP주소 위조 | 패킷필터링, 역경로검증(RPF) |
| ARP 스푸핑 | 위조 ARP응답으로 MAC주소 매핑 조작 | 정적 ARP, ARP감시툴 |
| DNS 스푸핑 | 조작된 DNS응답으로 악성 사이트 유도 | DNSSEC, 캐시검증 |
| 이메일 스푸핑 | 발신자 주소 위조 피싱메일 | SPF/DKIM/DMARC |
| GPS 스푸핑 | 위조 위성신호로 위치정보 조작 | 신호 인증, 다중센서 검증 |

**3. 상세 설명**  
공통적으로 신뢰관계(Trust Relationship)를 악용하며, 세션 하이재킹·MITM(중간자공격)·피싱의 선행기법으로 활용됨. ARP 스푸핑은 로컬 네트워크 내 스니핑에, DNS 스푸핑은 파밍(Pharming) 공격에 주로 연계됨.

**4. 기대효과 및 고려사항**  
다계층 방어(네트워크 인증, 암호화, 이메일 인증체계) 적용이 필요함. 특히 SPF/DKIM/DMARC 미적용 도메인은 이메일 스푸핑에 취약하므로 인증체계 구축이 핵심 대응방안임.

### 29. 벡터 데이터베이스(Vector Database)

**1. 개요**  
벡터 데이터베이스는 텍스트·이미지 등 비정형데이터를 임베딩(Embedding) 기법으로 고차원 벡터화하여 저장하고, 벡터 간 유사도 기반 검색을 지원하는 데이터베이스로, 최근 LLM·RAG 확산에 따라 핵심 인프라로 부상함.

**2. 주요 특징**

| 구분 | 내용 |
|---|---|
| 저장대상 | 임베딩 벡터(수백~수천 차원) |
| 검색방식 | ANN(근사 최근접 탐색), 코사인/유클리드 유사도 |
| 핵심 인덱스 | HNSW, IVF, LSH, PQ |
| 대표 제품 | Pinecone, Milvus, Weaviate, pgvector, Chroma |

**3. 상세 설명**  
(1)임베딩모델(예: 문장 임베딩)로 데이터를 벡터로 변환, (2)ANN 인덱스로 대규모 벡터 중 유사벡터를 고속 검색(정확도-속도 트레이드오프), (3)RAG 아키텍처에서 사용자 질의 임베딩과 문서벡터 유사도 검색을 통해 LLM 프롬프트에 관련 컨텍스트를 주입하여 환각 완화 및 최신정보 반영 가능.

**4. 기대효과 및 고려사항**  
시맨틱 검색·추천·이상탐지 등 활용범위 확대, LLM 답변 신뢰도 향상이 기대됨. 다만 대규모 벡터 저장에 따른 메모리·비용 부담, 임베딩모델 버전관리, 인덱스 재구축 비용, 데이터 최신성 유지가 고려사항임.

### 30. 정보보호 공시제도

**1. 개요**  
정보보호 공시제도(ISDS, Information Security Disclosure System)는 기업의 정보보호 투자·인력·활동 현황을 매년 공개하도록 의무화하여 정보보호 수준을 대외적으로 공시하고 자율적 투자를 유도하는 제도로, 정보통신망법에 근거함.

**2. 주요 내용**

| 구분 | 내용 |
|---|---|
| 근거법 | 정보통신망 이용촉진 및 정보보호 등에 관한 법률 |
| 대상기업 | 일정 규모 이상 정보통신서비스제공자, 상장사 등(의무/자율) |
| 공시항목 | 정보보호 투자금액·비율, 전담인력 수, 인증취득 현황 |
| 공시방법 | 공시포털(전자공시) 등록, 매년 6월 공시 |
| 관리기관 | 과학기술정보통신부, KISA |

**3. 상세 설명**  
기업은 직전년도 정보보호 투자현황(정보보호 예산/IT예산 비율), 정보보호 전담인력 현황, ISMS-P 등 인증취득 여부를 공시서식에 따라 작성·제출. 미공시·거짓공시 시 과태료 부과 등 제재규정 존재. 공시정보는 투자자·이용자의 기업 신뢰도 평가 지표로 활용됨.

**4. 기대효과 및 고려사항**  
기업의 자발적 정보보호 투자 확대 유도, 정보보호 산업 활성화, 투자자 의사결정 지원이 기대됨. 다만 형식적 공시(숫자 나열)에 그치지 않도록 실질 지표(침해대응 역량 등) 보완, 중소기업 공시부담 완화방안 검토가 필요함.

### 31. ISO/IEC 42001:2023 (AI 경영시스템 표준)

**1. 개요**  
ISO/IEC 42001은 조직이 AI를 개발·제공·운영하는 과정에서 발생하는 위험을 관리하고 신뢰성을 확보하기 위해 2023년 제정된 세계 최초의 AI 경영시스템(AIMS: AI Management System) 국제표준임. AI 기술의 급속한 확산과 편향, 안전성, 책임소재 불명확 등 부작용에 대응하여 조직 차원의 거버넌스 체계 필요성이 대두되며 등장함.

**2. 특징 및 구성요소**

| 구분 | 내용 |
|---|---|
| 적용범위 | AI를 개발·공급·사용하는 모든 유형·규모의 조직 |
| 구조 | ISO 경영시스템 공통구조(HLS) 기반, PDCA 순환모델 |
| 핵심요소 | 리더십, 기획, 지원, 운용, 성과평가, 개선 |
| 부속서 | Annex A(관리목적 및 통제항목), Annex B(구현지침) |

**3. 상세 설명**  
AI 정책 수립, 역할과 책임 정의, 위험평가(AI Risk Assessment) 및 영향평가(AI Impact Assessment) 수행 절차를 요구함. 데이터 품질관리, 투명성·설명가능성, 인간개입(Human Oversight), 3자 공급망 리스크 관리 등을 통제항목으로 규정하며, ISO 27001(정보보안), ISO 9001(품질)과 통합 인증 가능한 호환 구조로 설계되어 기존 경영시스템과 연계 운영 가능함.

**4. 기대효과 및 고려사항**  
AI 신뢰성·책임성 확보를 통한 이해관계자 신뢰 제고 및 글로벌 조달·수출 시 규제 대응력 강화 효과가 기대됨. 다만 인증 획득을 위한 조직 내 전담조직 구성, 지속적 위험 모니터링 체계 구축, EU AI Act 등 각국 규제와의 정합성 확보가 병행되어야 함.

### 32. SBOM (Software Bill Of Materials)

**1. 개요**  
SBOM은 소프트웨어를 구성하는 모든 컴포넌트, 라이브러리, 오픈소스, 버전정보, 의존관계 등을 목록화한 소프트웨어 자재명세서임. SolarWinds 해킹 사고 등 공급망 공격 급증과 오픈소스 취약점(예: Log4j) 확산으로 소프트웨어 구성요소의 가시성 확보 필요성이 강화되며 미국 행정명령(EO 14028) 등을 통해 의무화 추세로 확산됨.

**2. 특징 및 구성요소**

| 구성항목 | 내용 |
|---|---|
| 컴포넌트정보 | 명칭, 버전, 공급자, 라이선스 |
| 의존관계 | 상위-하위 컴포넌트 종속구조 |
| 식별자 | CPE, PURL 등 표준 식별체계 |
| 무결성정보 | 해시값, 서명정보 |

**3. 상세 설명**  
대표 표준형식으로 SPDX, CycloneDX, SWID가 있으며 각각 텍스트/XML/JSON 등 기계판독 가능한 포맷을 지원함. 생성단계는 소스코드 분석(SCA: Software Composition Analysis) → 의존성 트리 추출 → 표준 포맷 변환 → 배포 순으로 진행되며, 취약점 데이터베이스(NVD, CVE)와 연계하여 신규 취약점 발생 시 영향받는 제품·버전을 즉시 추적하는 VEX(Vulnerability Exploitability eXchange)와 결합 활용됨.

**4. 기대효과 및 고려사항**  
소프트웨어 공급망 투명성 확보로 취약점 신속대응, 라이선스 컴플라이언스 준수, 조달 시 보안성 검증 근거 자료로 활용 가능함. 다만 지속적 갱신을 위한 CI/CD 파이프라인 내 자동화 도구 통합, 다수 협력사 간 SBOM 상호운용성 확보, 관리 거버넌스 체계 마련이 과제로 남음.

### 33. 지능정보화 기본법

**1. 개요**  
지능정보화 기본법은 4차 산업혁명 시대 지능정보기술 기반의 지능정보사회 구현을 위해 기존 국가정보화 기본법을 전면 개정하여 2020년 시행된 법률임. AI, 빅데이터, 클라우드 등 지능정보기술 확산에 따른 법적 기반 마련과 디지털 격차, 알고리즘 편향 등 부작용 대응 필요성에서 제정됨.

**2. 특징 및 구성요소**

| 구분 | 주요내용 |
|---|---|
| 목적 | 지능정보사회 실현, 국가경쟁력 강화, 국민삶의질 향상 |
| 주요주체 | 정부, 지방자치단체, 지능정보화책임관(CIO) |
| 계획체계 | 지능정보사회 종합계획(3년), 시행계획(매년) |
| 핵심시책 | 데이터·네트워크·AI(D.N.A) 생태계 조성 |

**3. 상세 설명**  
지능정보사회 종합계획 수립·시행, 정보통신망 고도화, 데이터 활용 촉진, 초연결 지능정보통신망 구축 등을 국가 시책으로 규정함. 디지털 포용(정보격차 해소), 지능정보서비스 오남용 방지, 알고리즘 및 데이터 편향 방지를 위한 시책 마련 의무를 규정하며, 지능정보기술 관련 기반시설(클라우드, 데이터센터) 지정·보호, 초연결 사회 안전성 확보를 위한 재난관리 체계를 포함함.

**4. 기대효과 및 고려사항**  
국가 차원의 지능정보화 추진 법적 근거 확립으로 D.N.A 생태계 활성화와 디지털 포용사회 구현에 기여함. 다만 AI 기본법 등 신규 입법과의 중복·상충 조정, 급변하는 기술환경에 대응한 하위법령 및 고시 정비의 신속성 확보가 지속적으로 요구됨.

### 34. 도메인 특화 언어 모델 (Domain-Specific Language Models)

**1. 개요**  
도메인 특화 언어 모델은 범용 대규모 언어모델(LLM)을 특정 산업(의료, 법률, 금융 등) 도메인의 전문지식과 용어체계에 맞게 추가학습(Fine-tuning) 또는 재구성한 모델임. 범용 LLM의 전문영역 정확도 및 환각(Hallucination) 문제 한계를 보완하기 위해 등장함.

**2. 특징 및 구성요소**

| 구축방식 | 특징 |
|---|---|
| 도메인 사전학습 | 도메인 코퍼스로 처음부터 학습, 고비용·고정밀 |
| 파인튜닝(Fine-tuning) | 범용모델에 도메인 데이터로 추가학습 |
| RAG 결합 | 외부 도메인 지식베이스 검색 후 생성에 반영 |
| 어댑터/LoRA | 경량 파라미터만 학습하여 효율적 특화 |

**3. 상세 설명**  
구축절차는 도메인 데이터 수집·정제 → 전문용어 토크나이저 보강 → 사전학습/파인튜닝 → 도메인 벤치마크 평가 → 배포 순으로 진행됨. 의료(BioGPT, Med-PaLM), 법률, 금융 분야에서 전문용어 이해도와 규제 준수성 향상에 활용되며, 데이터 부족 및 프라이버시 이슈 해결을 위해 합성데이터 생성, 연합학습(Federated Learning)과 결합하는 사례가 증가함.

**4. 기대효과 및 고려사항**  
전문영역 응답 정확도 향상, 환각 감소, 업무 자동화 효율성 제고가 기대됨. 다만 도메인 데이터 확보의 어려움, 지속적 갱신 비용, 범용성 저하(Catastrophic Forgetting) 방지를 위한 지속학습 전략 및 검증체계 마련이 병행되어야 함.

### 35. VAE (Variational Autoencoder)

**1. 개요**  
VAE는 오토인코더 구조에 변분추론(Variational Inference) 개념을 결합하여 입력데이터의 확률분포를 학습하고 새로운 데이터를 생성할 수 있는 생성모델임. 기존 오토인코더가 결정론적 압축·복원에 그쳐 생성능력이 제한되는 한계를 극복하기 위해 2013년 제안됨.

**2. 특징 및 구성요소**

| 구성요소 | 기능 |
|---|---|
| 인코더(Encoder) | 입력을 잠재변수의 평균(μ)·분산(σ²)으로 매핑 |
| 잠재공간(Latent Space) | 확률분포(가우시안)로 표현되는 압축표현 |
| 디코더(Decoder) | 잠재변수 샘플링 값을 원본 데이터로 복원 |
| 손실함수 | 재구성오차 + KL Divergence |

**3. 상세 설명**  
재파라미터화 기법(Reparameterization Trick)을 통해 샘플링 과정의 미분불가능 문제를 해결하여 역전파 학습이 가능함. 손실함수는 복원손실(원본과 생성물 차이)과 KL발산(잠재분포와 표준정규분포 차이) 합으로 구성되어 정규화된 잠재공간을 형성하며, GAN과 달리 명시적 확률분포를 학습하여 학습 안정성이 높으나 생성물의 선명도(Blurry Image)는 GAN 대비 낮은 특성을 가짐.

**4. 기대효과 및 고려사항**  
안정적 학습과 잠재공간의 연속성·해석가능성을 바탕으로 이미지 생성, 이상탐지, 데이터 증강, 신약개발 분자생성 등에 활용됨. 다만 생성품질 향상을 위해 GAN·Diffusion 모델과의 하이브리드 구조(VAE-GAN) 적용 및 잠재공간 붕괴(Posterior Collapse) 방지 기법 고려가 필요함.

### 36. sLLM (Smaller Large Language Model)

**1. 개요**  
sLLM은 수십억 파라미터 규모의 초대형 언어모델(LLM) 대비 상대적으로 작은 파라미터(수억~수십억 수준)로 경량화되어 온디바이스 또는 저비용 인프라에서 구동 가능한 언어모델임. 대형 LLM의 높은 연산·비용 부담과 클라우드 의존성 한계를 극복하고 특정 목적에 최적화하기 위해 등장함.

**2. 특징 및 구성요소**

| 구분 | 특징 |
|---|---|
| 규모 | 1B~수십B 파라미터 수준 |
| 목적 | 특정 도메인·태스크 특화, 온디바이스 구동 |
| 경량화기법 | 지식증류, 양자화, 프루닝, LoRA |
| 대표모델 | Llama계열 소형모델, Phi, Gemma, 국내 소형 특화모델 |

**3. 상세 설명**  
지식증류(Knowledge Distillation)로 거대 교사모델(Teacher)의 지식을 소형 학생모델(Student)에 전달하여 성능 손실을 최소화하고, 양자화(Quantization)를 통해 파라미터를 저비트(INT8/INT4)로 표현, 프루닝으로 불필요 연결을 제거하여 모델 크기를 축소함. 온프레미스·엣지 디바이스 탑재로 응답속도(Latency) 개선, 데이터 외부유출 없는 프라이버시 보장이 가능함.

**4. 기대효과 및 고려사항**  
연산비용 절감, 온디바이스 AI 실현, 데이터 보안성 강화 등의 효과가 기대됨. 다만 범용 성능은 초대형 모델 대비 제한적이므로 특정 도메인 특화 학습전략 수립, 경량화 과정에서의 성능저하 최소화 기법 적용이 중요한 고려사항임.

### 37. VLM (Vision-Language Models)

**1. 개요**  
VLM은 이미지·비디오 등 시각정보와 텍스트 정보를 동시에 이해하고 상호 연관지어 처리하는 멀티모달 딥러닝 모델임. 단일 모달(텍스트 또는 이미지) 처리 모델의 한계를 넘어 인간처럼 시각과 언어를 통합적으로 인지할 필요성에서 발전함.

**2. 특징 및 구성요소**

| 구성요소 | 역할 |
|---|---|
| 비전 인코더 | 이미지 특징 추출(CNN, ViT) |
| 언어 인코더/디코더 | 텍스트 임베딩 및 생성(Transformer) |
| 정렬모듈(Cross-Modal Alignment) | 시각-텍스트 임베딩 공간 정합 |
| 대표모델 | CLIP, BLIP, GPT-4V, LLaVA |

**3. 상세 설명**  
사전학습단계에서 대규모 이미지-텍스트 페어 데이터로 대조학습(Contrastive Learning, 예: CLIP)을 통해 두 모달의 임베딩 공간을 정합하고, 이후 이미지 캡셔닝, VQA(Visual Question Answering), 이미지 기반 추론 등 다운스트림 태스크로 파인튜닝함. Cross-Attention 메커니즘을 통해 시각 특징과 언어 토큰 간 상호참조를 수행하여 통합적 의미 이해를 구현함.

**4. 기대효과 및 고려사항**  
이미지 검색, 자율주행 상황인지, 의료영상 판독 보조, 시각장애인 보조기술 등 다양한 산업에 적용되어 활용범위 확대가 기대됨. 다만 대규모 이미지-텍스트 데이터 확보 비용, 시각적 환각(Visual Hallucination) 문제, 편향된 학습데이터로 인한 공정성 이슈에 대한 지속적 검증이 필요함.

### 38. 전이학습 (Transfer Learning)

**1. 개요**  
전이학습은 특정 도메인·과업(Source Task)에서 학습된 모델의 지식을 다른 관련 도메인·과업(Target Task)에 재활용하여 학습효율을 높이는 기법임. 대규모 라벨링 데이터 확보의 어려움과 처음부터 학습(From Scratch)시 소요되는 높은 시간·비용 문제를 해결하기 위해 활용됨.

**2. 특징 및 구성요소**

| 유형 | 내용 |
|---|---|
| 특징추출(Feature Extraction) | 사전학습모델 가중치 고정, 출력층만 재학습 |
| 미세조정(Fine-tuning) | 사전학습모델 전체 또는 일부 가중치 추가학습 |
| 도메인 적응(Domain Adaptation) | 소스-타겟 도메인 분포차이 보정 |
| 멀티태스크학습 | 여러 과업 동시학습으로 공통표현 학습 |

**3. 상세 설명**  
절차는 대규모 데이터로 사전학습(Pre-training) → 타겟 도메인 데이터로 전이(가중치 초기화) → 미세조정 → 성능평가 순으로 이루어짐. 하위 레이어는 일반적 특징(엣지, 형태 등)을 학습하고 상위 레이어는 과업 특화 특징을 학습하는 계층적 표현 특성을 활용하며, ImageNet 사전학습 CNN, BERT/GPT 등 사전학습 언어모델이 대표적 전이학습 기반이며, LoRA 등 파라미터효율적 미세조정(PEFT)으로 발전함.

**4. 기대효과 및 고려사항**  
학습시간·비용 절감, 소량 데이터로도 높은 성능 달성, 다양한 산업 적용 확산 효과가 있음. 다만 소스-타겟 도메인 간 유사성이 낮을 경우 음성전이(Negative Transfer) 발생 가능성이 있어 적절한 레이어 선택 및 학습률 조정 전략이 요구됨.

### 39. PET (Privacy Enhanced Technology)

**1. 개요**  
PET(프라이버시 강화기술)는 개인정보를 보호하면서도 데이터의 활용가치를 유지할 수 있도록 지원하는 기술군을 의미함. 데이터 경제 활성화와 개인정보보호 규제(GDPR, 개인정보보호법 등) 강화라는 상충된 요구를 동시에 충족시키기 위해 발전함.

**2. 특징 및 구성요소**

| 기술유형 | 내용 |
|---|---|
| 동형암호(Homomorphic Encryption) | 암호화된 상태에서 연산 수행 |
| 차분프라이버시(Differential Privacy) | 노이즈 추가로 개인식별 방지, 통계값 보존 |
| 연합학습(Federated Learning) | 원본데이터 이동없이 로컬학습 후 모델만 공유 |
| 다자간 계산(MPC) | 여러 참여자가 데이터 노출없이 공동연산 |
| 익명화/가명처리 | 식별정보 제거·대체 |

**3. 상세 설명**  
동형암호는 복호화 없이 암호문 연산이 가능하여 클라우드 위탁 연산 시 데이터 노출을 방지하나 연산 오버헤드가 큰 특성을 가짐. 차분프라이버시는 쿼리결과에 통계적 노이즈를 부가하여 개별정보 역추적을 방지하며 프라이버시 예산(ε)으로 보호수준을 조절하고, 연합학습은 다수 기기·기관의 데이터를 중앙집중 없이 분산학습하여 결합, 의료·금융 등 민감데이터 협업분석에 활용됨.

**4. 기대효과 및 고려사항**  
개인정보 노출 위험 최소화와 데이터 활용 극대화를 동시에 달성하여 데이터 3법 및 마이데이터 산업 활성화에 기여함. 다만 연산 성능저하, 기술간 상호운용성 부족, 프라이버시-유용성 트레이드오프에 대한 적정 균형점 설정이 과제로 남음.

### 40. 데드락(Deadlock)의 발생 조건

**1. 개요**  
데드락은 다중 프로세스(또는 스레드)가 서로가 점유한 자원의 반납을 무한정 대기하여 어느 프로세스도 진행하지 못하는 교착상태를 의미함. 다중 프로그래밍 환경에서 자원의 동시 공유 및 병행처리 증가에 따라 자원경쟁 문제 해결이 필요해지며 중요성이 대두됨.

**2. 발생조건(4가지, 모두 동시 충족 시 발생)**

| 조건 | 내용 |
|---|---|
| 상호배제(Mutual Exclusion) | 자원은 한 순간에 한 프로세스만 점유 가능 |
| 점유와 대기(Hold and Wait) | 자원을 점유한 채 다른 자원을 추가로 대기 |
| 비선점(Non-preemption) | 타 프로세스의 자원을 강제로 빼앗을 수 없음 |
| 순환대기(Circular Wait) | 프로세스들이 원형으로 서로의 자원을 대기 |

**3. 상세 설명**  
자원할당그래프(Resource Allocation Graph)상에서 순환(Cycle)이 존재하면 데드락 발생 가능성을 시각적으로 판별 가능함. 해결방안은 예방(Prevention: 4대조건 중 하나 제거, 예-자원 순서화로 순환대기 제거), 회피(Avoidance: Banker's Algorithm으로 안전상태 유지), 탐지 및 복구(Detection & Recovery: 주기적 탐지 후 프로세스 종료·자원회수), 무시(Ostrich Algorithm: 발생빈도 낮을 시 방치 후 재부팅 대응)로 구분됨. 예방기법은 시스템 활용률과 처리율 저하를 유발할 수 있어 회피기법(사전 자원요청 검사)이 실용적으로 병행 적용됨.

**4. 기대효과 및 고려사항**  
데드락 방지·해결체계 구축을 통해 시스템 안정성과 자원활용 효율성을 동시에 확보 가능함. 다만 예방·회피 기법 적용 시 오버헤드 증가와 처리성능 저하가 발생하므로 시스템 특성에 맞는 기법 선택 및 타임아웃, 우선순위 기반 자원할당 전략과의 병행 적용이 필요함.

### 41. 소프트웨어 프로세스(SP, Software Process) 품질인증

**1. 개요**  
- 정의: SP 품질인증은 소프트웨어 개발·유지보수 조직의 프로세스 성숙도 및 품질관리 역량을 국가 공인기관이 평가·인증하는 제도임  
- 필요성: SW 품질은 산출물 검사만으로 보증 곤란, 개발 프로세스 자체의 표준화·체계화 필요성 증대에 따라 등장함

**2. 인증체계 및 구성요소**

| 구분 | 내용 |
|---|---|
| 인증기관 | 과학기술정보통신부 산하 인증기관(NIPA 등) |
| 근거모델 | CMMI, ISO/IEC 12207, SPICE(ISO/IEC 15504) |
| 평가영역 | 프로젝트관리, 요구공학, 설계, 테스트, 형상관리, 품질보증 |
| 등급 | 성숙도 레벨(1~5단계)로 구분 부여 |

**3. 상세 설명**  
- 절차: 신청 → 자체평가(Self-Assessment) → 문서심사 → 현장심사(인터뷰, 산출물 확인) → 등급 판정 → 인증서 발급 및 사후관리(정기 재심)  
- 평가기준: 프로세스 정의 여부, 표준 준수, 측정·분석 체계, 지속적 개선(PDCA) 활동 여부를 정량·정성적으로 평가  
- 특징: 결과물 중심이 아닌 프로세스 성숙도 중심 평가로, 반복 가능하고 예측 가능한 품질 산출이 핵심 목표임

**4. 기대효과 및 고려사항**  
- 기대효과: 공공 SW 사업 발주 시 가점 부여로 기업 신뢰도 제고, 프로젝트 지연·결함률 감소, 조직 역량 객관적 입증  
- 고려사항: 인증 획득 자체가 목적화되지 않도록 실질적 프로세스 내재화 필요, 인증 후 사후관리 소홀 방지를 위한 지속적 모니터링 체계 구축 필요

### 42. AES(Advanced Encryption Standard)

**1. 개요**  
- 정의: AES는 미국 NIST가 2001년 표준으로 채택한 대칭키 블록암호 알고리즘으로, 기존 DES의 키 길이 취약성을 보완하기 위해 등장함  
- 특징: Rijndael 알고리즘 기반, 128비트 고정 블록 크기, 128/192/256비트 키 길이 지원

**2. 구성요소 및 유형**

| 키 길이 | 라운드 수 | 보안강도 |
|---|---|---|
| 128비트 | 10 | 표준 |
| 192비트 | 12 | 강화 |
| 256비트 | 14 | 최고 |

**3. 상세 설명**  
- 처리구조: 평문을 4x4 바이트 State 배열로 구성, 각 라운드에서 SubBytes(치환), ShiftRows(행 이동), MixColumns(열 혼합), AddRoundKey(라운드키 XOR) 연산 반복 수행  
- 키 스케줄: 초기키로부터 각 라운드용 서브키를 생성하는 Key Expansion 수행  
- 운영모드: ECB, CBC, CTR, GCM 등과 결합하여 사용하며, GCM은 기밀성과 무결성(인증)을 동시 제공  
- DES 대비 우수성: 키 길이 확장으로 전수공격 저항성 증대, S-Box 기반 비선형 구조로 차분·선형 공격에 강함

**4. 기대효과 및 고려사항**  
- 기대효과: 전자상거래, VPN, 저장매체 암호화 등 전 산업 표준으로 활용, 하드웨어 가속(AES-NI) 지원으로 고속 처리 가능  
- 고려사항: 양자컴퓨팅 대비 키 길이 상향(256비트) 권고, 운영모드 선택 오류 시 취약점 발생 가능하므로 GCM 등 인증암호 모드 적용 필요

### 43. 가디언 에이전트(Guardian Agent)

**1. 개요**  
- 정의: 가디언 에이전트는 자율적으로 동작하는 AI 에이전트(작업 수행 에이전트)의 행위를 실시간 감시·검증·제어하는 감독형 AI 에이전트를 의미함  
- 등장배경: 생성형 AI 기반 자율 에이전트의 업무 자동화 확산에 따라 오작동, 편향된 판단, 권한 오남용 등 위험 통제 필요성 증대

**2. 주요 기능 및 구성요소**

| 구성요소 | 역할 |
|---|---|
| 정책엔진 | 허용 행위 범위(가드레일) 정의 |
| 모니터링 모듈 | 에이전트 행위·출력 실시간 추적 |
| 검증 모듈 | 결과물의 사실성·안전성 검증 |
| 개입 제어 | 이상행위 탐지 시 차단·롤백·승인요청 |

**3. 상세 설명**  
- 동작원리: 작업 에이전트의 입출력 및 도구 호출(Tool Call)을 인터셉트하여 사전 정의된 정책과 대조, 위반 시 실행 차단 또는 인간 승인(Human-in-the-loop) 요청  
- 적용기법: 프롬프트 인젝션 탐지, 행위 로그 기반 이상행위 탐지(Anomaly Detection), 다중 에이전트 간 상호검증(Multi-agent Cross-check)  
- 유사개념과 차이: 단순 로깅·모니터링과 달리 실시간 개입 및 자율적 판단 능력을 보유함이 특징

**4. 기대효과 및 고려사항**  
- 기대효과: 자율 에이전트 도입에 따른 신뢰성·안전성 확보, 규제 준수(책임소재 명확화), 오작동 조기 차단으로 피해 최소화  
- 고려사항: 가디언 에이전트 자체의 오판·과잉차단(False Positive) 문제, 에이전트 간 권한 위임 체계 및 책임 범위 명확화 필요

### 44. 플랫폼 엔지니어링(Platform Engineering)

**1. 개요**  
- 정의: 플랫폼 엔지니어링은 개발자가 셀프서비스 방식으로 인프라·배포 자원을 활용할 수 있도록 내부 개발자 플랫폼(IDP)을 설계·구축·운영하는 활동임  
- 등장배경: DevOps 확산에 따른 개발자의 인프라 관리 부담(Cognitive Load) 가중, 조직 규모 확대 시 일관성 부족 문제 해결 필요성 증대

**2. 구성요소**

| 구성요소 | 설명 |
|---|---|
| IDP(내부개발자플랫폼) | 셀프서비스 포털, API 제공 |
| 골든패스(Golden Path) | 표준화된 배포·개발 워크플로우 |
| 카탈로그 | 서비스·API·문서 통합관리(Backstage 등) |
| 자동화 파이프라인 | CI/CD, IaC(Terraform 등) 연계 |

**3. 상세 설명**  
- 핵심원리: 플랫폼팀이 인프라 복잡성을 추상화하여 제품처럼 제공(Platform as a Product), 개발자는 코드 작성에 집중  
- 절차: 요구사항 수집 → 골든패스 정의 → 셀프서비스 포털 구축 → 카탈로그화 → 지속적 피드백 개선  
- DevOps와의 관계: DevOps 철학을 조직 규모에서 실현하기 위한 구체적 실행 방법론으로, SRE·GitOps와 연계 운영

**4. 기대효과 및 고려사항**  
- 기대효과: 배포 리드타임 단축, 개발자 생산성 향상, 인프라 표준화를 통한 보안·거버넌스 일관성 확보  
- 고려사항: 과도한 추상화로 인한 유연성 저하 방지, 플랫폼팀의 지속적 사용자(개발자) 피드백 반영 체계 필요

### 45. ModelDoS

**1. 개요**  
- 정의: ModelDoS는 AI/LLM 모델에 대해 과도한 연산·자원 소모를 유발하는 입력을 반복 전송하여 서비스 가용성을 저하시키는 서비스거부 공격임  
- 등장배경: LLM API 기반 서비스 확산에 따라 추론(Inference) 연산 비용이 급증하며 이를 악용한 신종 공격 벡터로 부각됨

**2. 공격 유형**

| 유형 | 설명 |
|---|---|
| 긴 입력/출력 유도 | 최대 토큰 소모로 GPU 자원 고갈 |
| 반복 프롬프트 공격 | 동일 세션 대량 요청으로 큐 포화 |
| 재귀적 추론 유도 | Chain-of-Thought 남용으로 연산 폭증 |
| 모델 추론 루프 유발 | 무한 루프성 응답 생성 유도 |

**3. 상세 설명**  
- 공격원리: 정상 요청처럼 보이는 입력으로 모델의 토큰 생성량·연산 시간을 극대화시켜 GPU/메모리 자원 점유, 타 사용자 요청 처리 지연 및 서비스 중단 유발  
- 기존 DoS와 차이: 네트워크 대역폭이 아닌 모델 추론 연산량 자체를 소모 대상으로 하며, 소량 요청으로도 고비용 유발 가능(비대칭성)  
- 대응기술: 토큰 사용량 제한(Rate Limiting), 입력 복잡도 사전 분석, 요청별 타임아웃/자원 할당량 설정, 이상 패턴 탐지

**4. 기대효과 및 고려사항**  
- 고려사항: API 과금 체계 악용(비용 폭탄) 가능성 함께 검토 필요, 정상 사용자와 공격 구분을 위한 행위기반 탐지 모델 고도화 필요, 모델 서빙 인프라의 자원 격리(멀티테넌시) 설계 중요

### 46. 지속적인 위협 노출 관리(CTEM)

**1. 개요**  
- 정의: CTEM(Continuous Threat Exposure Management)은 조직의 공격표면과 노출된 취약점을 지속적·반복적으로 식별·검증·우선순위화하여 실질적 위험을 관리하는 프로그램으로, Gartner가 제시함  
- 등장배경: 클라우드·SaaS 확산으로 공격표면이 급증하고 정기 취약점 스캔만으로는 실시간 위협 대응 한계 발생

**2. 5단계 구성**

| 단계 | 내용 |
|---|---|
| Scoping | 관리대상 자산·비즈니스 우선순위 정의 |
| Discovery | 자산·취약점·오설정 식별 |
| Prioritization | 악용 가능성·영향도 기반 우선순위화 |
| Validation | 실제 공격 시나리오 기반 검증(모의공격) |
| Mobilization | 대응조치 실행 및 이해관계자 협업 |

**3. 상세 설명**  
- 핵심원리: 단발성 진단이 아닌 지속적 순환(Cycle) 프로세스로 운영, BAS(Breach and Attack Simulation)·ASM(Attack Surface Management) 도구와 연계  
- 기존 취약점관리와 차이: CVSS 점수 중심이 아닌 실제 악용 가능성·비즈니스 영향 기반 우선순위화(Risk-based) 수행  
- 적용기술: 자동화된 자산탐색, 위협인텔리전스 연계, 공격경로 시뮬레이션

**4. 기대효과 및 고려사항**  
- 기대효과: 실질적 위험 노출 최소화, 보안조치 자원의 효율적 배분, 규제 대응력 강화  
- 고려사항: 조직 전반의 프로세스·거버넌스 정착 필요, 자동화 도구와 인적 검증(Validation)의 균형 필요

### 47. 통합 테스트(Integration Test)

**1. 개요**  
- 정의: 통합 테스트는 단위 테스트를 통과한 개별 모듈들을 결합하여 모듈 간 인터페이스 및 상호작용의 정확성을 검증하는 테스트 단계임  
- 필요성: 개별 모듈은 정상이나 결합 시 인터페이스 불일치, 데이터 전달 오류 등이 발생할 수 있어 별도 검증 필요

**2. 통합 테스트 유형**

| 유형 | 설명 |
|---|---|
| Big-Bang | 전체 모듈 동시 통합 후 테스트 |
| Top-Down | 상위 모듈부터 순차 통합, Stub 사용 |
| Bottom-Up | 하위 모듈부터 순차 통합, Driver 사용 |
| Sandwich(혼합) | Top-Down/Bottom-Up 병행 |

**3. 상세 설명**  
- 절차: 통합계획 수립 → 통합 순서 결정 → Stub/Driver 작성 → 모듈 결합 → 인터페이스·데이터흐름 검증 → 결함 리포트  
- Stub: 미구현 하위 모듈을 대체하는 임시 모듈(Top-Down 시 사용)  
- Driver: 상위 모듈 역할을 대체하는 테스트 구동 모듈(Bottom-Up 시 사용)  
- 검증항목: 인터페이스 파라미터, 데이터 형식, 예외처리, 제어흐름, 성능(응답시간) 등  
- V-모델과의 관계: 아키텍처 설계 단계와 대응되며, 단위테스트(모듈설계) 이후 시스템테스트(요구사항) 이전 단계에 위치

**4. 기대효과 및 고려사항**  
- 기대효과: 모듈 간 결함 조기 발견으로 시스템 테스트 단계의 리스크 감소, 결함 위치 특정 용이  
- 고려사항: 통합 전략(Top-Down/Bottom-Up) 선정 시 시스템 구조·일정·자원 고려 필요, CI 파이프라인과 연계한 자동화된 지속적 통합테스트 권장

### 48. 보안 운영체제(Secure OS)

**1. 개요**  
- 정의: Secure OS는 기존 범용 운영체제(OS) 커널에 보안 기능을 추가·강화하여 접근제어, 권한 최소화, 침입 탐지 등을 커널 레벨에서 수행하는 운영체제임  
- 필요성: 응용계층 보안 솔루션만으로는 커널·시스템 자원에 대한 근본적 통제 한계, 관리자 권한 탈취(루트 권한 오남용) 대응 필요

**2. 주요 구성요소**

| 구성요소 | 기능 |
|---|---|
| 참조모니터(RM) | 모든 접근요청 중재, 정책 강제 |
| 강제접근제어(MAC) | 시스템 정책 기반 강제 통제 |
| 최소권한(Least Privilege) | 프로세스별 필요 최소권한 부여 |
| 감사(Audit) | 시스템 호출·접근 이력 기록 |

**3. 상세 설명**  
- 핵심원리: 참조모니터가 모든 주체(프로세스)-객체(파일, 자원) 간 접근을 커널 레벨에서 검사, DAC(임의접근제어)와 별도로 MAC 정책을 강제 적용하여 관리자도 정책 우회 불가  
- 접근제어모델: BLP(기밀성), Biba(무결성), RBAC 등을 정책엔진에 반영  
- 구현방식: 커널 패치형(SELinux, AppArmor), 커널 대체형(자체 커널 개발), 각각 커널 무결성·성능 트레이드오프 존재  
- 주요기능: root 권한 제한, 실행파일 무결성 검증, 네트워크 접근 통제, 프로세스 격리

**4. 기대효과 및 고려사항**  
- 기대효과: 내부자 권한 오남용 및 루트킷·악성코드에 의한 시스템 장악 방지, 정보시스템 최상위 보안계층 확보  
- 고려사항: 정책 설정 복잡도로 인한 운영 부담, 과도한 정책 적용 시 정상 서비스 장애 가능성으로 도입 전 충분한 정책 테스트 필요

### 49. 패스키(Passkey)

**1. 개요**  
- 정의: 패스키는 FIDO Alliance와 W3C가 제정한 FIDO2/WebAuthn 표준 기반의 비밀번호 없는(Passwordless) 인증 수단으로, 공개키 암호 방식을 활용함  
- 등장배경: 비밀번호 유출·재사용·피싱에 의한 계정탈취 문제 해결 및 사용자 편의성 제고 필요성 증대

**2. 구성요소**

| 구성요소 | 역할 |
|---|---|
| 개인키 | 사용자 기기 내 보안영역(TPM/Secure Enclave) 저장, 외부 미노출 |
| 공개키 | 서비스 서버에 등록 |
| 인증장치 | 생체인증(지문·안면) 또는 PIN으로 개인키 사용 승인 |
| 동기화 | 클라우드 계정(iCloud, Google 등) 통해 다중기기 공유 |

**3. 상세 설명**  
- 동작원리: 등록 시 기기에서 키쌍 생성 후 공개키만 서버 전송, 로그인 시 서버가 challenge 전송 → 기기가 생체인증 후 개인키로 서명 → 서버가 공개키로 검증  
- 기존 방식과 차이: 비밀번호를 서버에 저장하지 않아 서버 유출 시에도 인증정보 탈취 불가, 피싱 사이트에서는 도메인 불일치로 서명 자체가 불가능(피싱 원천 차단)  
- 표준기술: WebAuthn API, CTAP2 프로토콜, 공개키 기반구조(PKI) 원리 활용

**4. 기대효과 및 고려사항**  
- 기대효과: 비밀번호 관리 부담 해소, 피싱·크리덴셜스터핑 공격 원천 차단, 사용자 편의성 및 로그인 성공률 향상  
- 고려사항: 기기 분실 시 복구절차 마련 필요, 플랫폼 간(iOS/Android/Windows) 상호운용성 및 레거시 시스템과의 병행 전환 전략 필요

### 50. WAAP(Web Application and API Protection)

**1. 개요**  
- 정의: WAAP은 웹 애플리케이션과 API를 동시에 보호하기 위해 WAF, API 보안, DDoS 방어, 봇 관리 기능을 통합한 클라우드 기반 보안 플랫폼임  
- 등장배경: MSA·모바일 확산으로 API 트래픽이 급증하고, 기존 WAF만으로는 API 고유 위협(과도한 데이터 노출, 인증 우회 등) 대응 한계 발생

**2. 주요 구성요소**

| 구성요소 | 기능 |
|---|---|
| WAF | SQL Injection, XSS 등 웹 공격 차단 |
| API 보안 | API 스키마 검증, 인증·인가 오남용 탐지 |
| Bot Management | 자동화 봇·크롤러 식별 및 차단 |
| DDoS 방어 | L3~L7 대용량 공격 완화 |
| Rate Limiting | 요청빈도 제어로 남용 방지 |

**3. 상세 설명**  
- 핵심원리: API 명세(OpenAPI/Swagger) 기반 스키마 검증으로 정의되지 않은 엔드포인트·파라미터 요청 탐지, 행위기반 분석으로 정상 사용자와 봇·자동화 공격을 구분  
- OWASP API Top10 대응: BOLA(객체수준 인가취소), 과도한 데이터 노출, Rate Limit 미비 등 API 특화 취약점 대응체계 포함  
- 배포형태: 클라우드 서비스형(SaaS), CDN 엣지 연계형이 주로 활용되어 글로벌 분산 방어 가능  
- 기존 WAF와 차이: WAF는 시그니처 기반 웹 공격 방어 중심인 반면, WAAP은 API 생애주기 전반(발견-분류-보호-모니터링)을 포괄

**4. 기대효과 및 고려사항**  
- 기대효과: API 자산 가시성 확보 및 자동화 공격·데이터 유출 방지, 통합 관리로 보안운영 효율성 증대  
- 고려사항: Shadow API(비관리 API) 탐지체계 병행 필요, 오탐으로 인한 정상 API 트래픽 차단 방지를 위한 정책 튜닝 필요

### 51. 멀티클라우드(MultiCloud)

**개요**: 멀티클라우드는 AWS, Azure, GCP, NCP 등 2개 이상의 서로 다른 CSP(Cloud Service Provider) 서비스를 목적별·업무별로 병행 사용하는 클라우드 운영 전략임. 단일 벤더 종속(Vendor Lock-in) 위험 회피, 서비스 가용성·재해복구(DR) 강화, 데이터 주권 및 비용 최적화 요구 증대에 따라 확산됨.

**특징 및 구성요소**

| 구분 | 내용 |
|---|---|
| 하이브리드클라우드와 차이 | 하이브리드는 온프레미스+클라우드 결합, 멀티클라우드는 복수 CSP 간 결합 |
| 아키텍처 유형 | Active-Active, Active-Standby, 워크로드별 분산배치 |
| 핵심 구성요소 | 클라우드관리플랫폼(CMP), 컨테이너/K8s, IaC(Terraform), Service Mesh, 통합 IAM |

**상세설명**: 컨테이너 및 K8s 기반으로 워크로드 이식성을 확보하고, IaC로 인프라 프로비저닝을 표준화하여 CSP 간 배포 일관성을 유지함. API Gateway와 Service Mesh를 통해 CSP 간 트래픽을 제어하고, CSPM(Cloud Security Posture Management)·CASB로 보안 형상을 통합 관리함. 데이터 동기화는 이벤트 기반 메시징 및 복제 기술을 활용함.

**기대효과 및 고려사항**: 벤더 종속 방지, 가용성·복원력 향상, CSP 간 비용 협상력 확보가 가능하나, 관리 복잡성 증가, 네트워크 지연, 데이터 일관성 및 통합 거버넌스 체계 마련이 선행되어야 하며, 통합 모니터링(Observability) 체계 구축이 필수임.

### 52. 쿠버네티스(Kubernetes)

**개요**: 쿠버네티스는 컨테이너화된 애플리케이션의 배포, 스케일링, 운영을 자동화하는 오픈소스 컨테이너 오케스트레이션 플랫폼임. 마이크로서비스 아키텍처 확산과 컨테이너 수 증가에 따른 수동 운영의 한계를 극복하기 위해 구글의 Borg 시스템을 기반으로 개발됨.

**구성요소**

| 구분 | 구성요소 | 설명 |
|---|---|---|
| Control Plane | API Server, etcd, Scheduler, Controller Manager | 클러스터 상태 관리·저장 및 스케줄링 |
| Node | Kubelet, Kube-proxy, Container Runtime | 실제 컨테이너 실행 및 네트워킹 |
| 리소스 오브젝트 | Pod, Deployment, Service, ConfigMap, PVC | 배포 단위 및 서비스 노출 정의 |

**상세설명**: etcd에 클러스터 전체 상태를 저장하고, Controller가 현재 상태를 원하는 상태(Desired State)로 지속 조정하는 선언적 관리 방식을 채택함. Pod 단위 스케줄링, Auto Scaling(HPA/VPA/Cluster Autoscaler), Self-healing(재시작·재배치), Service Discovery 및 Load Balancing 기능을 제공함. Helm으로 패키지 관리, Istio 등 Service Mesh로 트래픽·보안 정책을 확장함.

**기대효과 및 고려사항**: 인프라 자원 활용률 극대화, 무중단 배포(롤링 업데이트) 및 자동 복구로 운영 안정성 확보 가능하나, 학습 곡선이 높고 네트워크·스토리지 설계 복잡성이 있어 RBAC, 네트워크 정책 등 보안 강화 및 운영 전담 인력 확보가 필요함.

### 53. 분산분석(ANOVA)

**개요**: 분산분석(Analysis of Variance)은 3개 이상 집단 간 평균 차이가 통계적으로 유의한지를 집단 내 분산과 집단 간 분산의 비율(F통계량)로 검정하는 통계 기법임. 두 집단 비교에 사용되는 t검정을 다중 집단으로 확장하면서 반복적 t검정 시 발생하는 제1종 오류 누적 문제를 해결하기 위해 사용됨.

**가정**: ① 각 집단 표본은 정규분포를 따름(정규성), ② 각 집단의 분산이 동일함(등분산성, Levene 검정으로 확인), ③ 관측치는 상호 독립임(독립성)

**유형**

| 유형 | 설명 |
|---|---|
| 일원분산분석(One-way) | 독립변수 1개(요인)에 대한 집단 간 평균 비교 |
| 이원분산분석(Two-way) | 독립변수 2개, 요인 간 상호작용효과 분석 포함 |
| 반복측정 ANOVA | 동일 대상을 반복 측정한 데이터 분석 |

**절차**: 가설설정(H0: 모든 집단 평균 동일) → 분산분해(전체제곱합=집단간제곱합+집단내제곱합) → F값 산출(집단간분산/집단내분산) → F분포 기준 유의성 판단(p<α이면 H0 기각). H0 기각 시 어느 집단 간 차이인지 확인 위해 사후검정(Post-hoc) 실시함.

**사후검정**: Tukey HSD(등분산 가정), Scheffe(보수적), Bonferroni(다중비교 보정), Games-Howell(이분산 가정) 등을 활용하며, 다중비교로 인한 오류율 증가를 통제함.

### 54. React2Shell (웹 애플리케이션 원격 셸 획득 공격)

**개요**: React2Shell 유형의 공격은 React 기반 SSR(Server-Side Rendering) 프레임워크(Next.js 등)나 관련 서버 컴포넌트의 취약점을 악용하여 공격자가 원격으로 임의 코드를 실행, 웹쉘을 업로드하여 서버 셸 권한을 획득하는 원격 코드 실행(RCE) 공격임. 프론트엔드 프레임워크의 서버측 렌더링 확대와 npm 생태계 의존성 급증에 따라 공급망 취약점 노출 위험이 커지며 등장함.

**공격 유형 및 취약점**

| 구분 | 내용 |
|---|---|
| 취약점 원인 | SSR 미들웨어 역직렬화 결함, 서버 액션(Server Action) 입력 검증 미비, 의존 패키지 공급망 오염 |
| 공격 경로 | 악성 페이로드 전송→서버측 코드 실행→웹쉘 업로드→권한 상승 |
| 유사사례 | Log4Shell, npm 패키지 하이재킹형 공급망 공격 |

**상세설명**: 공격자는 취약한 API 라우트나 서버 액션에 조작된 요청을 전송하여 서버 프로세스 권한으로 명령을 실행시키고, 이를 통해 웹쉘을 심어 지속적 백도어를 확보함. 이후 내부망 이동(Lateral Movement) 및 데이터 유출로 이어짐.

**대응방안**: 입력값 화이트리스트 검증 및 역직렬화 제한, 의존성 SBOM 관리 및 정기 취약점 스캐닝(SCA), WAF/RASP 도입, 최소권한 컨테이너 실행, 정기 패치 및 웹쉘 탐지용 파일 무결성 모니터링(FIM) 적용이 필요함.

### 55. 시계열 데이터베이스

**개요**: 시계열 데이터베이스(Time Series Database, TSDB)는 시간 순서에 따라 연속적으로 생성되는 데이터(타임스탬프+값)를 고속 수집·저장·조회하는 데 특화된 데이터베이스임. IoT 센서, 인프라 모니터링, 금융 틱데이터 등 초당 대량의 시계열 데이터 발생에 따라 기존 RDBMS의 쓰기 성능·저장효율 한계를 극복하기 위해 등장함.

**특징 및 대표 제품**

| 구분 | 내용 |
|---|---|
| 데이터 모델 | 타임스탬프+메트릭+태그(레이블) 구조 |
| 대표제품 | InfluxDB, Prometheus, TimescaleDB, OpenTSDB |
| 주요 연산 | 다운샘플링, 이동평균, 구간 집계(Rollup) |

**상세설명**: 시간 순 정렬 저장구조(LSM-Tree 기반)로 순차 쓰기 성능을 최적화하고, 컬럼 지향 압축(Delta/Delta-of-delta, Run-length 인코딩)으로 저장공간을 절감함. 데이터 보존정책(Retention Policy)에 따라 오래된 데이터를 자동 삭제하거나 다운샘플링하며, Continuous Query로 실시간 집계 뷰를 생성함. 태그 기반 인덱싱으로 다차원 필터링 조회를 지원함.

**기대효과 및 고려사항**: 대량 시계열 데이터의 고속 적재 및 실시간 분석(모니터링·알림) 가능하나, 고카디널리티(태그 조합 폭증) 시 성능 저하 우려가 있어 태그 설계 최적화 및 보존정책 수립이 중요함.

### 56. CSAP (Cloud Security Assurance Program)

**개요**: CSAP(클라우드서비스 보안인증제)는 과학기술정보통신부·한국인터넷진흥원(KISA)이 클라우드 서비스의 보안성을 평가하여 인증하는 국내 제도로서, 공공기관이 안전성이 검증된 클라우드 서비스를 이용하도록 하기 위해 도입됨. 클라우드컴퓨팅법에 근거하며, 공공부문 클라우드 도입 확산에 따른 보안 신뢰성 확보 필요성에서 비롯됨.

**등급 및 구성**

| 등급 | 적용 대상 |
|---|---|
| 상급(물리적 분리) | 민감정보·기밀 취급 공공기관 |
| 중하급(논리적 분리) | 일반 행정업무용 |

**인증기준 영역**: 정보보호정책, 인적보안, 물리적 보안, 접근통제, 암호화, 침해사고관리, 재해복구 등 총 14개 영역, 117개 세부 통제항목으로 구성됨(운영환경에 따라 항목 수 변동).

**상세설명**: 신청기관은 자체 평가 및 취약점 점검 후 KISA 인증기관의 서면심사·현장심사를 거쳐 인증위원회 심의로 인증서를 발급받으며, 인증 유효기간은 원칙적으로 5년이고 매년 사후관리 심사를 받음. 최근 등급제 개편으로 상급 요건이 완화되며 민간 CSP의 공공시장 진입장벽 완화가 추진됨.

**기대효과 및 고려사항**: 공공 클라우드의 보안 신뢰성 확보 및 이용기관의 검증 부담 경감 효과가 있으나, 심사 기간·비용 부담, 글로벌 CSP와의 상호인정(해외 인증 연계) 확대가 과제임.

### 57. SDP(Software Defined Perimeter)

**개요**: SDP는 네트워크 경계를 물리적 위치가 아닌 소프트웨어 기반의 논리적 경계로 정의하여, 인증·인가된 사용자와 디바이스에게만 필요한 리소스로의 접근을 동적으로 허용하는 보안 아키텍처임. 클라우드·재택근무 확산으로 전통적 경계(방화벽/VPN) 기반 보안모델의 한계가 드러나며 제로트러스트(Zero Trust) 구현 기술로 부상함.

**핵심 구성요소**

| 구성요소 | 역할 |
|---|---|
| SDP Controller | 인증·정책 관리, 접속 승인 결정 |
| Initiating Host(Client) | 접속 요청 및 인증 수행 |
| Accepting Host(Gateway) | 승인된 연결만 리소스 노출 |

**상세설명**: 핵심 동작원리는 "Need-to-know" 모델과 단일패킷인가(SPA: Single Packet Authorization)로, 인증 전에는 서버 존재 자체를 숨겨 사전 접근 시도를 차단함(Dark Cloud 효과). 접속 절차는 ①디바이스/사용자 인증 →②Controller가 정책 기반 접근권한 검증→③암호화된 마이크로 터널을 동적 생성→④승인된 리소스에만 1:1 연결하는 순서로 진행됨. 기존 VPN이 네트워크 전체 접근을 허용하는 것과 달리 자원 단위로 세분화(마이크로세그멘테이션)된 접근제어를 제공함.

**기대효과 및 고려사항**: 공격표면 최소화, 내부망 측면이동(Lateral Movement) 차단 효과가 크나, 기존 인프라와의 연계 통합, 엔드포인트 에이전트 배포·관리 부담을 고려해야 함.

### 58. 인공지능 소프트웨어 품질 보증을 위한 테스트 기법

**개요**: AI 소프트웨어는 학습 데이터에 기반한 확률적·비결정적(Non-deterministic) 특성을 가져 명세 기반의 전통적 테스트로는 결함 검증에 한계가 있음. 이에 데이터, 모델, 시스템 전 영역을 포괄하는 AI 특화 품질보증 기법이 요구됨.

**품질 특성 및 테스트 대상**

| 구분 | 대상 | 주요 이슈 |
|---|---|---|
| 데이터 품질 | 학습/검증 데이터 | 편향(Bias), 라벨오류, 대표성 |
| 모델 품질 | 알고리즘/파라미터 | 과적합, 정확도, 강건성 |
| 시스템 품질 | 서빙 환경 | 응답성능, 드리프트 대응 |

**주요 테스트 기법**: ① 메타모픽 테스팅(Metamorphic Testing) - 오라클 부재 문제 해결 위해 입력 변형 시 출력 간 관계(불변성)를 검증, ② 커버리지 기반 테스트 - 뉴런/레이어 활성화 커버리지(Neuron Coverage)로 테스트 충분성 측정, ③ 적대적 테스트(Adversarial Testing) - 미세 변형 입력으로 모델 강건성·오분류 검증, ④ A/B 테스트 및 챔피언-챌린저 - 운영환경 성능 비교, ⑤ 데이터 드리프트/모델 드리프트 모니터링 - 운영 중 성능 저하 탐지, ⑥ 설명가능성(XAI) 검증 - SHAP/LIME으로 판단근거 타당성 확인.

**기대효과 및 고려사항**: 모델 신뢰성·공정성·안전성 확보가 가능하나, 테스트 오라클 정의 곤란, 대량 테스트데이터 구축 비용, MLOps 파이프라인 내 지속적 검증체계(CI/CD for ML) 내재화가 필요함.

### 59. WBS(Work Breakdown Structure) 작성방법

**개요**: WBS는 프로젝트 범위 전체를 계층적으로 세분화하여 관리 가능한 작업단위(Work Package)로 분해한 산출물 중심의 작업분류체계임. 프로젝트 범위 명확화, 일정·비용·자원 산정의 기준선을 마련하기 위해 PMBOK 범위관리 프로세스의 핵심 기법으로 활용됨.

**작성원칙**

| 원칙 | 내용 |
|---|---|
| 100% Rule | 상위 요소는 하위요소 총합과 100% 일치 |
| MECE | 하위 요소 간 중복 없이(상호배타), 빠짐없이(전체포괄) 구성 |
| 최소단위 | Work Package는 8~80시간 등 관리 가능한 크기로 분할 |

**작성절차**: ① 프로젝트 범위기술서·요구사항 분석 →② 주요 인도물(Deliverable) 식별(1~2레벨) →③ 인도물을 하위 활동으로 점진적 세분화(Decomposition, 3~4레벨) →④ Work Package 단위까지 분해 후 코드체계(WBS Dictionary) 부여 →⑤ 각 작업패키지에 담당자·기간·산출물 정의. 분해 방식은 산출물 기준(Deliverable-based) 또는 생명주기 단계 기준(Phase-based)을 활용하며, 과도한 분해(Analysis Paralysis)를 지양함.

**기대효과 및 고려사항**: 명확한 범위 통제, 정확한 일정/원가 산정(CPM, EVM 연계), 책임소재 명확화(RAM 매트릭스 연계) 효과가 있으나, 요구사항 변경 시 WBS 갱신 체계(형상관리)와 이해관계자 합의가 병행되어야 함.

### 60. 소프트웨어 무중단 배포 방식

**개요**: 무중단 배포는 서비스 중단 없이 신규 버전을 운영환경에 배포하는 기법으로, 애자일/DevOps 확산과 상시 가용성 요구 증대에 따라 배포로 인한 다운타임과 장애 리스크를 최소화하기 위해 도입됨.

**주요 배포 방식 비교**

| 방식 | 개념 | 장점 | 단점 |
|---|---|---|---|
| 블루그린(Blue-Green) | 동일한 신·구 환경 2세트 구성, 트래픽을 전체 일괄 전환 | 즉시 롤백 용이, 검증 용이 | 이중 인프라로 자원비용 2배 |
| 롤링(Rolling) | 기존 인스턴스를 순차적으로 신버전으로 교체 | 추가 자원 최소화 | 신·구버전 혼재기간 존재, 롤백 지연 |
| 캐너리(Canary) | 신버전을 일부 사용자·트래픽에만 우선 배포 후 점진 확대 | 실사용자 기반 위험 최소화 | 모니터링·트래픽분할 체계 필요 |

**상세설명**: 블루그린은 로드밸런서의 라우팅 대상을 Blue→Green으로 전환하여 즉시 원복 가능하며, 롤링은 K8s Deployment 등에서 일정 배치(Batch) 단위로 순차 교체하는 방식이 기본값임. 캐너리는 5%→20%→100% 등 단계적 트래픽 증가와 함께 오류율·지연시간 등 핵심 지표를 실시간 모니터링하여 이상 시 자동 롤백(Feature Flag, Service Mesh 연계)함.

**기대효과 및 고려사항**: 배포 리스크 감소 및 가용성 확보가 가능하나, 데이터베이스 스키마 하위호환성 유지, 세션 처리, 모니터링/알림 자동화 체계 구축이 선행되어야 함.

### 61. 엣지(Edge) 컴퓨팅과 클라우드 컴퓨팅의 차이점

**1. 개요**  
- (정의) 클라우드 컴퓨팅은 중앙집중형 데이터센터에서 컴퓨팅·저장·네트워크 자원을 인터넷을 통해 원격 제공하는 방식이며, 엣지 컴퓨팅은 데이터 발생지(단말·현장)에 인접한 위치에서 연산을 수행하는 분산형 컴퓨팅 방식임  
- (배경) IoT 기기 폭증, 5G·자율주행·스마트팩토리 등 실시간 처리 요구 증대로 중앙집중 처리 시 발생하는 지연시간·네트워크 부하 문제 해소 필요성에서 등장함

**2. 비교**

| 구분 | 클라우드 컴퓨팅 | 엣지 컴퓨팅 |
|---|---|---|
| 처리위치 | 중앙 데이터센터 | 단말 인근 로컬 노드 |
| 지연시간 | 상대적으로 큼 | 매우 낮음(실시간성) |
| 대역폭 부담 | 큼(전량 전송) | 작음(현장 전처리) |
| 확장성 | 자원 확장 용이 | 개별 노드 확장 |
| 보안관리 | 중앙집중 통제 용이 | 분산되어 관리 복잡 |
| 활용예 | 빅데이터 분석, ERP | 자율주행, 스마트공장 |

**3. 상세설명**  
- (계층구조) Device-Edge-Cloud 3계층으로 구성, 엣지에서 센서데이터 전처리·실시간 이상탐지 수행 후 정제데이터만 클라우드로 전송하여 대용량 학습·장기저장 수행  
- (연계원리) Edge-Cloud Continuum 개념으로 상호 보완적 역할 분담, MEC(Mobile Edge Computing) 등을 통해 통신사망 엣지에 서비스 배치

**4. 기대효과 및 고려사항**  
- (기대효과) 응답지연 최소화, 네트워크 트래픽 절감, 데이터 로컬 처리로 개인정보 노출 최소화  
- (고려사항) 다수 엣지노드에 대한 통합관제·보안취약점 관리, 표준 프로토콜 부재에 따른 이종 연동 문제, 엣지-클라우드 간 데이터 동기화 정책 수립 필요

### 62. 과적합(Overfitting)과 과소적합(Underfitting)의 발생 원인과 해결 방안

**1. 개요**  
- (정의) 과적합은 모델이 학습데이터의 노이즈까지 과도하게 학습하여 새로운 데이터에 대한 일반화 성능이 저하되는 현상이며, 과소적합은 모델이 학습데이터의 패턴조차 충분히 학습하지 못한 상태임  
- (배경) 머신러닝 모델 성능은 편향(Bias)-분산(Variance) 트레이드오프에 의해 결정되므로 적정 모델 복잡도 설정이 핵심 과제임

**2. 특징 비교**

| 구분 | 과적합 | 과소적합 |
|---|---|---|
| 학습오차 | 매우 낮음 | 높음 |
| 검증오차 | 높음(격차 큼) | 높음(학습오차와 유사) |
| 원인모델 | 과도하게 복잡 | 과도하게 단순 |
| 편향/분산 | 저편향·고분산 | 고편향·저분산 |

**3. 원인 및 해결방안**  
- (과적합 원인) 모델 복잡도 과다, 학습데이터 부족, 학습 반복(epoch) 과다, 이상치·노이즈 과학습  
- (과적합 해결) 정규화(L1/L2, Dropout), Early Stopping, 데이터 증강(Augmentation), 교차검증(K-fold), 앙상블(Bagging)  
- (과소적합 원인) 모델 표현력 부족, 특징(Feature) 부족, 학습 부족, 과도한 정규화  
- (과소적합 해결) 모델 복잡도 증가(층/파라미터 확대), 특징 엔지니어링 추가, 학습반복 증가, 하이퍼파라미터 재조정

**4. 기대효과 및 고려사항**  
- (기대효과) 학습오차·검증오차 균형을 통한 일반화 성능 확보  
- (고려사항) 검증셋·테스트셋 분리를 통한 지속적 성능 모니터링, 학습곡선(Learning Curve) 분석을 통한 원인 진단, 데이터 품질 및 양적 확보 우선 검토

### 63. CTEM(Continuous Threat Exposure Management)

**1. 개요**  
- (정의) CTEM은 Gartner가 제시한 개념으로, 조직의 공격표면에 대한 위협 노출도를 지속적으로 식별·평가·검증·개선하는 반복적 보안관리 프로그램임  
- (배경) 클라우드·디지털전환에 따른 공격표면 확대, 기존 정기적(Point-in-time) 취약점 점검의 한계, 실제 악용가능성 기반 대응체계 부재 문제를 해소하기 위해 등장함

**2. 특징**  
- 지속적(Continuous) 순환 수행, 비즈니스 영향도 기반 우선순위화, 실제 공격 시나리오 기반 검증, 보안팀·현업 이해관계자 공동참여형 프로세스

**3. 5단계 프로세스**

| 단계 | 주요내용 |
|---|---|
| Scoping | 보호대상 자산 및 비즈니스 범위(공격표면) 정의 |
| Discovery | 자산·취약점·오설정·노출경로 식별 |
| Prioritization | 악용가능성·비즈니스 영향도 기반 위험 우선순위화 |
| Validation | 모의침투(PT)·BAS 등으로 실제 공격 성공가능성 검증 |
| Mobilization | 조치계획 수립, 부서간 협업체계 구축 및 대응 실행 |

**4. 기대효과 및 고려사항**  
- (기대효과) 선제적·실질적 위협대응, 보안투자 효율화, 잔존위험 가시화를 통한 의사결정 지원  
- (고려사항) ASM·BAS 등 자동화도구와의 연계, 부서간 협업 거버넌스 확립, 1회성이 아닌 반복적(Cycle) 운영체계 정착 필요

### 64. 기업의 업무구조를 바꾸는 다중 에이전트 시스템(MAS, Multi-Agent System)

**1. 개요**  
- (정의) MAS는 자율적으로 판단·행동하는 다수의 AI 에이전트가 상호 통신·협업하여 복잡한 업무를 분업 수행하는 시스템임  
- (배경) 생성형 AI·LLM 고도화로 단일 에이전트의 처리범위·정확도 한계를 극복하고, 반복적·정형화된 업무 자동화를 넘어 판단이 필요한 복합업무 자동화 요구 증대에 따라 확산됨

**2. 구성요소**  
- Orchestrator(작업분배·조정), Worker Agent(역할별 전문 에이전트), 통신프로토콜(MCP, A2A 등), 공유메모리·컨텍스트, 외부 Tool/API 연동모듈

**3. 상세설명**  
- (협업구조 유형) 계층형(Supervisor-Sub agent), 수평형(Peer-to-Peer), 파이프라인형(순차처리)으로 구분  
- (동작원리) 목표수신→작업분해(Task Decomposition)→역할별 에이전트 할당→병렬/순차 수행→결과통합 및 검증  
- (기존 방식과의 차이) RPA·단일 챗봇은 사전정의 규칙 기반 처리에 한정되나, MAS는 동적 상황판단과 에이전트간 자율적 협업·재조정이 가능함

**4. 기대효과 및 고려사항**  
- (기대효과) 부서간 경계 완화 및 업무 프로세스 재설계, 의사결정 자동화를 통한 생산성·처리속도 향상, 인적자원의 고부가가치 업무 전환  
- (고려사항) 에이전트간 오류 전파(Hallucination 확산) 방지, 보안·거버넌스 체계 마련, 핵심 의사결정에 대한 Human-in-the-loop 적용, 책임소재 명확화 필요

### 65. 울트라 이더넷 (Ultra Ethernet)

**1. 개요**  
- 정의: AI/HPC 클러스터의 대규모 병렬 연산에 최적화된 차세대 이더넷 통신 표준으로, UEC(Ultra Ethernet Consortium)가 주도 개발함  
- 배경: 생성형 AI 학습에 GPU 수만 개가 참여하며 기존 InfiniBand·전통 이더넷의 지연·확장성 한계 극복 필요성 증대에 따라 등장함

**2. 특징 및 구성요소**

| 구분 | 내용 |
|---|---|
| 전송계층 | UET(Ultra Ethernet Transport), RDMA 기반 |
| 혼잡제어 | 다중경로 기반 패킷 스프레이(Packet Spray) |
| 신뢰성 | 선택적 재전송, 순서 무관 전달 |
| 보안 | 라인레이트 암호화 지원 |

**3. 상세 설명**  
- 기존 RoCEv2의 단일경로 한계를 극복하기 위해 패킷 단위 다중경로 분산 전송(Packet Spray) 적용, 링크 활용률 극대화함  
- 순서 보장 없는 전달(Out-of-order delivery) 허용으로 헤드오브라인 블로킹 제거함  
- 혼잡 발생 시 실시간 신호 기반 능동 혼잡제어(Congestion Control) 수행하여 마이크로버스트 완화함  
- 표준 이더넷 스위치·NIC 생태계 활용으로 InfiniBand 대비 비용·상호운용성 개선함

**4. 기대효과 및 고려사항**  
- 기대효과: GPU 클러스터 확장성 확보, TCO 절감, 개방형 생태계 조성  
- 고려사항: 초기 상용 스위치/NIC 지원 미성숙, 기존 인프라 전환 비용, 표준 버전 호환성 검증 필요함

### 66. 스테이블 코인(Stable Coin)

**1. 개요**  
- 정의: 법정화폐, 실물자산 또는 알고리즘을 기반으로 가치를 특정 자산에 고정시켜 가격 변동성을 최소화한 암호자산임  
- 배경: 비트코인 등 암호화폐의 극심한 가격 변동성으로 인한 결제·거래 수단 활용 제약을 해소하기 위해 등장함

**2. 유형 및 구성요소**

| 유형 | 담보방식 | 예시 |
|---|---|---|
| 법정화폐 담보형 | 은행예치·국채 | USDT, USDC |
| 암호자산 담보형 | 초과담보 암호화폐 | DAI |
| 알고리즘형 | 수요공급 알고리즘 조절 | (구)UST |
| 원화 스테이블코인 | 국내 발행 추진 | 발행 검토 중 |

**3. 상세 설명**  
- 발행사가 담보자산을 예치하고 1:1 페깅(Peg)된 토큰을 발행, 상환 시 소각(Burn)하는 구조로 운영됨  
- 지급결제, DeFi 담보, 국경간 송금 등에 활용되며 블록체인 상 스마트컨트랙트로 발행·유통 자동화됨  
- 리스크: 디페깅(Depegging), 담보 투명성 부족에 따른 뱅크런, 알고리즘형의 구조적 붕괴 위험 존재함  
- 규제 동향: 미국 GENIUS Act, EU MiCA, 국내 가상자산이용자보호법 2단계 입법 추진 중임

**4. 기대효과 및 고려사항**  
- 기대효과: 결제 효율화, 크로스보더 금융 혁신, 디지털 자산 생태계 확장  
- 고려사항: 담보자산 실시간 감사체계, 발행사 건전성 규제, 통화주권·금융안정 영향 검토 필요함

### 67. 휴머노이드 로봇(Humanoid Robot)

**1. 개요**  
- 정의: 인간의 신체 구조와 유사한 형태로 이동·조작이 가능하며 AI 기반 인지·판단 능력을 갖춘 범용 로봇임  
- 배경: 생성형 AI·강화학습 발전으로 로봇의 인지·제어 성능이 비약적으로 향상되며 제조·서비스 현장 적용 가능성 확대됨

**2. 구성요소**

| 구성 | 역할 |
|---|---|
| 액추에이터 | 관절 구동, 인체 유사 자유도 구현 |
| 센서 | LiDAR·카메라·힘토크 센서로 환경 인지 |
| Foundation Model | VLA(Vision-Language-Action) 기반 판단 |
| 배터리/구동계 | 자율 이동 및 균형제어(ZMP 등) |

**3. 상세 설명**  
- 인지-계획-행동(Perception-Planning-Action) 파이프라인으로 동작, 최근 VLA 모델 도입으로 자연어 명령 기반 범용 작업 수행 가능해짐  
- 시뮬레이션 기반 강화학습(Sim-to-Real)으로 보행·파지 등 물리적 스킬 학습 후 실환경 전이함  
- 테슬라 Optimus, 보스턴다이내믹스 Atlas, 피규어AI 등이 제조라인·물류 실증 진행 중임  
- 핵심 난제: 저전력 고출력 액추에이터, 촉각센서 정밀도, 실시간 온디바이스 추론 지연 해결 필요함

**4. 기대효과 및 고려사항**  
- 기대효과: 제조·물류·돌봄 등 노동력 대체 및 고위험 작업 대응  
- 고려사항: 안전 표준·책임소재 규정, 고비용 구조 개선, 일자리 대체에 따른 사회적 수용성 확보 필요함

### 68. 국가 망 보안체계(N2SF, National Network Security Framework)

**1. 개요**  
- 정의: 기존 물리적 망분리 중심 정책에서 벗어나 데이터 중요도 기반으로 보안수준을 차등 적용하는 국가 정보보안 프레임워크임  
- 배경: 클라우드·AI 활용 확대로 경직된 망분리의 업무 비효율이 지적되며 국정원 주도로 개편 추진됨

**2. 구성요소 및 분류체계**

| 구분 | 내용 |
|---|---|
| 데이터 등급 | 공개/민감/기밀 3단계 분류 |
| 보안영역 | 등급별 차등 접근제어 영역 구분 |
| 통제방식 | 논리적 망분리+제로트러스트 결합 |
| 적용대상 | 공공기관, 국가기관 정보시스템 |

**3. 상세 설명**  
- 기존 인터넷망·업무망 물리적 이원화 방식을 데이터 중요도 기반 등급제로 전환, 등급별 허용 클라우드·인터넷 접근범위 차등화함  
- 제로트러스트 아키텍처(ZTA)와 연계하여 지속적 인증·최소권한·마이크로세그멘테이션 적용함  
- 등급 분류 기준: 국가안보·개인정보 관련 기밀정보는 최고등급, 일반 행정정보는 완화된 등급 적용함  
- 단계적 시범적용 후 전 공공기관 확산 로드맵 추진 중이며 클라우드 네이티브 업무환경 지원 목표로 함

**4. 기대효과 및 고려사항**  
- 기대효과: 업무 효율성 제고, 클라우드·AI 활용 확대, 유연한 보안체계 구축  
- 고려사항: 등급 분류 기준 명확화, 과도기 보안공백 방지, 기관별 전환 비용·인력 확보 필요함

### 69. 딥페이크(Deepfake)

**1. 개요**  
- 정의: GAN·Diffusion 등 딥러닝 기반 생성모델을 활용하여 특정 인물의 얼굴·음성을 합성·조작한 미디어 콘텐츠임  
- 배경: 생성형 AI 기술 대중화로 제작 진입장벽이 낮아지며 허위정보·명예훼손·금융사기 등 악용 사례 급증에 따른 대응 필요성 증대됨

**2. 유형 및 생성기술**

| 구분 | 내용 |
|---|---|
| 생성기술 | GAN(생성자-판별자 경쟁학습), Diffusion Model |
| 유형 | Face Swap, Lip Sync, 음성복제(Voice Cloning) |
| 악용사례 | 딥보이스 보이스피싱, 허위영상물, 여론조작 |

**3. 상세 설명**  
- GAN은 생성자가 위조 데이터를 생성, 판별자가 진위 구분하며 경쟁학습으로 정교화됨. Diffusion 모델은 노이즈 제거 과정을 역이용하여 고품질 이미지 생성함  
- 탐지기술: 픽셀·주파수 아티팩트 분석, 생체신호(눈 깜빡임·맥박) 불일치 검출, 워터마킹(C2PA 표준) 기반 콘텐츠 출처 인증  
- 국내법: 성폭력처벌법·정보통신망법 개정으로 딥페이크 성범죄물 제작·유포 처벌 강화됨  
- 대응체계: 탐지 AI 고도화와 법적 규제가 병행되어야 하나 생성기술 발전 속도가 탐지기술을 상회하는 창과 방패 경쟁 지속됨

**4. 기대효과 및 고려사항**  
- 기대효과: 콘텐츠 산업·교육 등 긍정적 활용 가능성도 존재함  
- 고려사항: 실시간 탐지체계 구축, 콘텐츠 출처 인증 의무화, 국제 공조 대응체계 마련 필요함

### 70. 개인정보 보호 강화기술(Privacy Enhancing Technology)

**1. 개요**  
- 정의: 개인정보를 활용하면서도 프라이버시 노출을 최소화하도록 설계된 기술적 수단의 총칭임  
- 배경: 빅데이터·AI 학습에 개인정보 활용이 필수화되며 데이터 활용과 프라이버시 보호 간 균형(Privacy-Utility Trade-off) 요구 증대됨

**2. 주요 기법**

| 기법 | 원리 |
|---|---|
| 차분정보보호(Differential Privacy) | 통계결과에 잡음 추가로 개인 식별 방지 |
| 동형암호(Homomorphic Encryption) | 암호화 상태에서 연산 수행 |
| 연합학습(Federated Learning) | 원본 데이터 미이동, 모델만 학습·공유 |
| 비식별화(k-익명성, 합성데이터) | 식별정보 제거·가명처리 |
| 다자간 계산(MPC) | 다수 참여자 데이터 결합 없이 공동연산 |

**3. 상세 설명**  
- 차분정보보호는 쿼리 결과에 라플라스/가우시안 잡음을 추가해 개별 레코드 존재 여부를 통계적으로 은닉하며 개인정보 유출 한계를 정량화(ε값)함  
- 연합학습은 각 디바이스·기관에서 로컬 학습 후 파라미터만 중앙서버로 집계, 원본 데이터 유출 위험 최소화함  
- 동형암호는 데이터 복호화 없이 암호문 상태로 연산 가능하여 클라우드 위탁처리 시 안전성 확보함  
- 국내 개인정보보호법상 가명처리·안전성 확보조치와 결합하여 데이터 활용 법적 근거로 활용됨

**4. 기대효과 및 고려사항**  
- 기대효과: 데이터 활용 활성화와 프라이버시 보호 동시 달성, 데이터 3법 준수 지원  
- 고려사항: 연산 오버헤드에 따른 성능저하, 기법별 적용 시나리오 선정, 표준화·검증체계 필요함

### 71. AI 거버넌스(Artificial Intelligence Governance)

**1. 개요**  
- 정의: AI 시스템의 개발·배포·운영 전 과정에서 신뢰성·안전성·윤리성을 확보하기 위한 정책·조직·기술적 관리체계임  
- 배경: 생성형 AI 확산에 따른 편향·오남용·안전사고 우려 증대로 국가·기업 차원의 체계적 위험관리 필요성 부각됨

**2. 구성요소**

| 구성 | 내용 |
|---|---|
| 정책/법제 | EU AI Act, 국내 AI기본법 |
| 조직 | AI 윤리위원회, 책임자(CAIO) 지정 |
| 리스크관리 | 위험도 기반 등급 분류·평가체계 |
| 기술적 통제 | 설명가능AI(XAI), 레드팀 테스트, 워터마킹 |

**3. 상세 설명**  
- EU AI Act는 AI를 위험도(금지/고위험/제한/최소)로 분류, 고위험 AI에 데이터거버넌스·인간감독 등 의무 부과함  
- 국내 AI기본법(2026년 시행)은 고영향 AI 사업자에 위험관리·설명·안전성 확보 의무 규정함  
- 거버넌스 프레임워크는 생명주기 전반(설계-개발-배포-모니터링) 걸쳐 편향성 검증, 데이터 품질관리, 사고 대응체계를 포함함  
- NIST AI RMF의 Govern-Map-Measure-Manage 4단계 모델이 국제적 참조모델로 활용됨

**4. 기대효과 및 고려사항**  
- 기대효과: AI 신뢰성 제고, 규제 리스크 사전대응, 사회적 수용성 확보  
- 고려사항: 과잉규제로 인한 혁신저해 방지, 국가간 규제 상호운용성, 중소기업 준수 부담 완화 필요함

### 72. 머신러닝 의사결정나무(Decision Tree) 모델

**1. 개요**  
- 정의: 데이터를 특성값 기준으로 반복 분기하여 트리 구조로 분류·회귀를 수행하는 지도학습 알고리즘임  
- 배경: 결과 해석이 어려운 블랙박스 모델의 대안으로 직관적이고 설명 가능한 모델 필요성에 따라 널리 활용됨

**2. 구성요소**

| 구성 | 내용 |
|---|---|
| 루트/내부노드 | 분기 기준(특성, 임계값) |
| 리프노드 | 최종 예측값(클래스/연속값) |
| 분할기준 | 지니계수, 엔트로피(정보이득), 분산감소 |
| 가지치기 | 과적합 방지 위한 트리 크기 제한 |

**3. 상세 설명**  
- 분류 시 지니계수 또는 엔트로피 기반 정보이득이 최대가 되는 특성을 선택하여 노드 분할, 순도(Purity)를 높이는 방향으로 트리 성장시킴  
- 정보이득 = 부모노드 엔트로피 - 자식노드 가중평균 엔트로피로 계산, 값이 클수록 우수한 분할기준임  
- 회귀나무는 분산 감소량을 기준으로 분할, 리프노드는 해당 구간 평균값을 예측치로 사용함  
- 과적합 방지를 위해 최대깊이 제한, 최소 리프 샘플수 설정 등 사전/사후 가지치기(Pruning) 적용함  
- 확장모델: 다수 트리 앙상블인 랜덤포레스트(Bagging), Gradient Boosting/XGBoost(Boosting)로 성능 개선함

**4. 기대효과 및 고려사항**  
- 기대효과: 높은 해석가능성, 전처리 부담 적음, 비선형 관계 포착 용이  
- 고려사항: 단일 트리의 과적합·불안정성, 앙상블 기법 병행 필요, 클래스 불균형 데이터 처리 주의 필요함

### 73. 데이터 자산화 및 데이터 유통 활성화

**1. 개요**  
- 정의: AI 학습·서비스의 핵심자원인 데이터를 법적·경제적 자산으로 인정하고 안전한 거래·유통 생태계를 조성하는 정책·제도적 체계임  
- 배경: AI 확산으로 고품질 데이터 수요가 급증하며 데이터 소유권·활용 규범 정립과 유통시장 활성화 필요성이 대두됨

**2. 주요 구성요소**

| 구분 | 내용 |
|---|---|
| 데이터 3법 | 개인정보보호법, 정보통신망법, 신용정보법 |
| 자산화 제도 | 데이터자산 평가, 데이터 자산 등재(콘텐츠산업진흥법 등) |
| 유통 인프라 | 데이터거래소, 데이터바우처, 마이데이터 |
| 활용기술 | 가명처리, PET, 데이터라벨링 표준화 |

**3. 상세 설명**  
- 2020년 데이터 3법 개정으로 가명정보 개념 도입, 통계작성·연구목적 활용 시 정보주체 동의 없이 처리 가능해짐  
- 개인정보보호법상 가명처리, 신용정보법상 마이데이터(본인신용정보관리업)로 금융분야 데이터 이동권 실질화됨  
- 한국데이터거래소·금융데이터거래소 등을 통해 데이터 상품 등록·매칭·가격산정 지원, 데이터바우처로 중소기업 데이터 구매 보조함  
- AI 학습데이터 관련 저작권법상 공정이용 여부, 데이터 소유권 불명확성이 유통 활성화의 제약요인으로 지적됨

**4. 기대효과 및 고려사항**  
- 기대효과: 데이터 경제 활성화, AI 학습데이터 공급 확대, 신산업 창출  
- 고려사항: 데이터 소유권·수익배분 기준 정립, 프라이버시 침해 방지, 데이터 품질·표준화 체계 확립 필요함

### 74. Self-Attention 메커니즘

**1. 개요**  
- 정의: 입력 시퀀스 내 모든 토큰 간 상호 연관도를 직접 계산하여 문맥적 가중치를 부여하는 Transformer의 핵심 연산 메커니즘임  
- 배경: RNN/LSTM의 순차처리로 인한 병렬화 한계와 장거리 의존성 소실 문제를 해결하기 위해 2017년 "Attention is All You Need" 논문에서 제안됨

**2. 구성요소**

| 구성 | 역할 |
|---|---|
| Query(Q) | 현재 토큰이 찾고자 하는 정보 |
| Key(K) | 각 토큰이 갖는 정보의 색인 |
| Value(V) | 실제 전달되는 정보 값 |
| Multi-Head | 여러 표현공간에서 병렬 attention 수행 |

**3. 상세 설명**  
- 입력 임베딩을 가중치행렬 Wq, Wk, Wv와 곱하여 Q, K, V 벡터 생성함  
- Attention(Q,K,V) = softmax(QK^T/√dk)V 수식으로 계산, QK^T로 유사도 산출 후 √dk로 스케일링하여 기울기 소실 방지함  
- softmax로 정규화된 가중치를 V에 곱해 문맥 반영된 새로운 표현 생성, 모든 토큰이 서로 직접 참조하므로 장거리 의존성 문제 해소됨  
- Multi-Head Attention은 서로 다른 헤드에서 병렬로 attention 수행 후 결합(Concat)하여 다양한 관점의 문맥정보 포착함  
- 위치정보 부재를 보완하기 위해 Positional Encoding을 입력에 추가함

**4. 기대효과 및 고려사항**  
- 기대효과: 병렬처리로 학습속도 향상, 장거리 문맥 포착, GPT/BERT 등 LLM 기반기술로 확산  
- 고려사항: 시퀀스 길이 증가 시 O(n²) 연산복잡도 문제, Flash Attention·Sparse Attention 등 경량화 기술 병행 필요함

### 75. 모라벡의 역설(Moravec's Paradox)

**개요**: 모라벡의 역설은 인간에게 쉬운 감각·운동 능력(보행, 시각인식, 손동작 등)은 컴퓨터로 구현하기 어렵고, 반대로 인간에게 어려운 논리·수리적 추론(체스, 수식계산)은 컴퓨터가 오히려 쉽게 수행한다는 역설적 현상임. 1980년대 로봇공학자 한스 모라벡이 AI·로봇 연구 과정에서 제시함.

**특징 및 원인**

| 구분 | 인간 | 컴퓨터(AI) |
|---|---|---|
| 논리·연산(체스, 계산) | 어려움 | 쉬움(정형화·규칙기반) |
| 지각·운동(보행, 표정인식) | 쉬움 | 어려움(비정형·고차원) |

- 진화적 배경: 지각·운동능력은 수억 년 진화로 신경계에 고도로 최적화된 반면, 추상적 추론은 인류 발달 후기에 형성되어 비교적 단순한 회로로 처리  
- 계산적 배경: 지각·운동은 연속적·비정형 데이터의 실시간 처리 요구, 논리연산은 정형 규칙 기반 처리로 알고리즘화 용이

**상세**: 딥러닝·강화학습·센서융합 기술 발전으로 자율주행, 로봇팔 제어 등에서 역설이 점차 완화되고 있으나, 실세계 물리적 상호작용·상식추론 영역은 여전히 인간 대비 격차 존재함.

**시사점**: AI 개발 시 알고리즘 고도화만으로는 한계가 있으며, 센서·액추에이터·엣지컴퓨팅 등 SW-HW 통합 접근이 필요함. 최근 피지컬 AI, 휴머노이드 로봇 투자 확대의 이론적 근거로 활용됨.

### 76. 운영체제의 프로세스 스케줄링

**개요**: 프로세스 스케줄링은 CPU 자원을 다수의 프로세스에 효율적으로 할당하기 위해 실행 순서와 시간을 결정하는 운영체제 핵심 기능임. 멀티태스킹 환경에서 자원 활용률 극대화와 응답성 확보를 목적으로 함.

**스케줄링 목적**: CPU 이용률 최대화, 처리량(Throughput) 증대, 응답시간·대기시간 최소화, 공정성 보장, 균형있는 자원 활용

**주요 기법**

| 기법 | 방식 | 특징 |
|---|---|---|
| FCFS | 도착순 처리(Non-preemptive) | 구현 단순, Convoy Effect 발생 |
| SJF | 실행시간 짧은 순 처리 | 평균 대기시간 최소이나 Starvation 우려 |
| RR | 고정 Time Quantum 순환할당(Preemptive) | 응답시간 균등, 시분할 시스템에 적합 |
| MLFQ | 다단계 큐+우선순위 동적조정 | 짧은작업 우대, 기아방지 위해 Aging 적용 |
| Priority | 우선순위 기반 선점/비선점 | 우선순위 역전 문제(Aging으로 보완) |

**성능평가 지표**: CPU 이용률, 처리량, 반환시간(Turnaround Time), 대기시간(Waiting Time), 응답시간(Response Time)

**고려사항**: 실시간 시스템은 Rate Monotonic, EDF 등 결정론적 스케줄링 필요하며, 멀티코어 환경에서는 Load Balancing 및 캐시 지역성(Affinity)을 고려한 스케줄링 설계가 중요함.

### 77. 국내 AI기술 도입 및 활용 시 발생할 수 있는 프라이버시 이슈

**개요**: AI 모델의 학습·추론 과정에서 대규모 개인정보가 수집·활용되면서 개인정보보호법 등 국내 법제와 충돌하는 프라이버시 침해 우려가 증대됨. 최근 국내 AI서비스의 개인정보 무단수집 사례로 사회적 논란이 지속됨.

**주요 이슈 유형**

| 구분 | 내용 |
|---|---|
| 학습데이터 수집 | 웹크롤링 시 동의없는 개인정보 포함, 저작권 침해 병행 |
| 재현/추론위험 | 모델 역공학(Model Inversion)으로 학습데이터 유추·복원 가능 |
| 멤버십추론공격 | 특정 데이터가 학습셋 포함여부 추론, 민감정보 노출 |
| 목적외 이용 | 최초 수집목적과 다른 AI학습 활용(2차 이용 동의 미확보) |
| 아동·민감정보 | 생체정보, 아동정보 등 민감정보의 비식별화 미흡 |

**상세**: 개인정보보호법상 가명처리·비식별조치 의무가 있으나 생성형 AI는 원본 특징을 암묵적으로 내재화하여 완전한 비식별화가 어려움. 국내는 개인정보위 「AI 개인정보 처리 가이드라인」을 통해 학습데이터 적법성 점검, 옵트아웃 절차 마련을 권고함.

**고려사항**: Privacy by Design 적용, 연합학습·차분프라이버시 등 프라이버시 강화기술(PET) 도입, AI 학습데이터 출처관리 및 동의체계 정비, 정기적 AI 영향평가(AIA) 수행이 필요함.

### 78. 합성 데이터(Synthetic Data)

**개요**: 합성 데이터는 실제 데이터의 통계적 특성과 패턴을 모사하여 알고리즘·시뮬레이션으로 인공적으로 생성한 데이터임. 개인정보 노출없이 AI 학습·테스트에 활용 가능해 데이터 부족 및 프라이버시 문제의 대안으로 부각됨.

**생성 기법 및 유형**

| 기법 | 설명 |
|---|---|
| GAN 기반 | 생성자-판별자 경쟁학습으로 실제와 유사한 데이터 생성 |
| VAE 기반 | 잠재공간 학습 후 샘플링을 통해 데이터 재생성 |
| 규칙/시뮬레이션 | 통계모델·물리엔진 기반 규칙적 데이터 생성(자율주행 시뮬레이션 등) |
| 확산모델(Diffusion) | 노이즈 제거과정을 학습하여 고품질 이미지·데이터 생성 |

**특징**: 원본 데이터와 통계적 유사도 유지, 개인 식별정보 미포함(프라이버시 보존), 희소 케이스(Edge Case) 데이터 대량 생성 가능, 라벨링 자동화로 비용 절감

**활용분야**: 의료영상 학습데이터, 금융 이상거래 탐지, 자율주행 시뮬레이션, 데이터 불균형 해소(Oversampling)

**기대효과 및 고려사항**: 데이터 확보비용 절감, 데이터 편향 완화 가능하나, 원본 분포 왜곡 시 모델 성능저하 우려 및 재식별 가능성 완전 배제 불가하므로 품질검증(Fidelity·Utility·Privacy 평가지표) 체계 마련이 필요함.

### 79. VPN(Virtual Private Network)

**개요**: VPN은 공중 인터넷망 상에 암호화된 가상의 전용 통신경로를 구성하여 원격지 간 안전한 데이터 통신을 제공하는 기술임. 재택근무·지사간 연결 등 비용효율적 사설망 구축 필요성에 따라 발전함.

**유형 및 구성요소**

| 유형 | 특징 |
|---|---|
| Site-to-Site VPN | 본사-지사 등 네트워크 간 상시 연결(IPSec 기반) |
| Remote Access VPN | 개별 사용자의 원격 접속(SSL VPN, Client 설치) |
| MPLS VPN | 통신사 제공 라벨기반 논리적 사설망 |

**핵심 프로토콜**: IPSec(AH/ESP, 3계층 암호화), SSL/TLS VPN(응용계층, 클라이언트리스 접속 용이), L2TP, WireGuard(경량·고성능 최신 프로토콜)

**동작원리**: 터널링(Tunneling)으로 원본 패킷을 캡슐화하고, 암호화(AES 등)·인증(인증서, PSK)을 통해 기밀성·무결성·인증 확보. IPSec은 IKE로 키교환 후 SA(Security Association) 수립.

**기대효과 및 고려사항**: 전용선 대비 구축비용 절감, 원격근무 보안성 확보 가능하나, Split Tunneling으로 인한 내부망 노출 위험, VPN 게이트웨이 단일장애점(SPOF), 최근 Zero Trust 아키텍처(ZTNA) 도입으로 VPN의 광범위한 접근권한 문제를 보완하는 추세임.

### 80. 가상융합산업 진흥법(메타버스산업 진흥법)

**개요**: 가상융합산업 진흥법은 메타버스 등 가상융합기술·서비스의 육성과 이용자 보호를 위해 제정된 법률로, XR·메타버스 산업 생태계 조성 및 신뢰기반 확산을 목적으로 함. 국내 메타버스 산업 활성화와 글로벌 경쟁력 확보 필요성에 따라 추진됨.

**주요 내용**

| 구분 | 내용 |
|---|---|
| 정의 | 가상융합기술(VR·AR·MR·XR 등 실감기술), 가상융합산업 개념 법제화 |
| 진흥계획 | 정부의 기본계획 수립·시행, 실태조사 실시 |
| 산업지원 | 기술개발, 표준화, 창업·중소기업 지원, 융합인재 양성 |
| 이용자보호 | 부작용(중독, 저작권 침해, 사생활 침해) 방지 시책 마련 |
| 클러스터 | 가상융합산업 진흥시설·클러스터 지정 지원 |

**상세**: 과기정통부 주관으로 메타버스 윤리원칙, 안전한 가상융합서비스 확산기반 마련을 병행하며, 기존 정보통신융합법·콘텐츠산업진흥법 등과의 정합성을 고려해 제정 추진됨.

**기대효과 및 고려사항**: 메타버스 산업 투자활성화, 실감콘텐츠 경쟁력 강화 기대되나, 가상자산·아이템 거래의 법적성격 불명확, 메타버스 내 범죄행위 규율체계 미비 등 후속 법제 정비가 병행되어야 함.

### 81. AI 신뢰성 검인증 제도(CAT, Certification for AI Trustworthiness)

**개요**: CAT는 AI 시스템의 안전성·신뢰성·윤리성을 공인기관이 검증·인증하는 제도로, AI 오작동·편향·보안취약점 등에 대한 사회적 신뢰 확보를 위해 도입됨. 국내 TTA 등을 중심으로 AI 신뢰성 검증체계가 구축되고 있음.

**인증 대상 및 평가영역**

| 평가영역 | 세부내용 |
|---|---|
| 안전성 | 오작동·이상행동에 대한 안전장치, 견고성(Robustness) |
| 신뢰성 | 정확성, 일관성, 재현성 |
| 공정성 | 데이터·알고리즘 편향(Bias) 검증 |
| 설명가능성 | XAI 기반 의사결정 근거 제시 |
| 개인정보보호 | 학습데이터 프라이버시 침해여부 |

**절차**: 신청 → 서류심사(설계문서, 데이터셋 검토) → 기술심사(테스트베드 기반 성능·안전성 시험) → 인증서 발급 → 사후관리(정기 재평가)

**상세**: ISO/IEC 42001(AI경영시스템), IEEE 7000시리즈 등 국제표준과 연계하여 평가기준을 정립하며, 고위험 AI(의료, 자율주행 등) 우선 적용을 추진함.

**기대효과 및 고려사항**: AI 서비스에 대한 이용자 신뢰 제고, 기업의 책임있는 AI 개발 유도 기대되나, 인증기준의 국제 정합성 확보, 인증비용 부담으로 인한 중소기업 참여저해 완화 방안이 필요함.

### 82. 정보시스템 감리의 시스템 운영 및 유지보수 감리

**개요**: 운영·유지보수 감리는 이미 구축되어 운영 중인 정보시스템의 안정적 운영상태, 변경관리 적정성, 보안·성능을 점검하여 지속적인 서비스 품질을 보장하기 위한 감리 활동임. 전자정부법·소프트웨어산업진흥법에 근거하여 수행됨.

**감리 점검영역**

| 영역 | 점검내용 |
|---|---|
| 운영관리 | 운영절차 표준화, 장애관리(SLA 이행), 백업·복구체계 |
| 변경관리 | 변경요청 승인절차, 형상관리, 테스트 후 반영 여부 |
| 성능관리 | 응답시간, 자원사용률(CPU·메모리), 용량관리 |
| 보안관리 | 접근통제, 취약점 점검, 로그관리 |
| 유지보수 | 유지보수 계획 대비 실적, 결함관리(버그 추적) |

**상세절차**: 감리계획 수립 → 감리자료 요청 및 검토(운영매뉴얼, 장애이력) → 현장점검(인터뷰, 시스템 실사) → 문제점 도출 및 개선권고 → 감리보고서 작성 및 시정조치 확인

**기대효과 및 고려사항**: 운영 안정성 확보, 잠재적 장애·보안사고 사전예방, SLA 준수율 제고 기대됨. 다만 형식적 점검에 그치지 않도록 정량적 성과지표(KPI) 기반 평가와 상시감리·자동화된 모니터링 연계가 필요함.

### 83. 데이터베이스 트랜잭션 격리 수준(Transaction Isolation Level)

**개요**: 트랜잭션 격리수준은 동시에 수행되는 다수 트랜잭션 간 데이터 접근을 어느 정도 격리할지를 정의하는 기준으로, 동시성과 데이터 일관성 간 트레이드오프를 조절하기 위해 ANSI SQL 표준에서 정의됨.

**이상현상(Anomaly) 유형**

| 이상현상 | 설명 |
|---|---|
| Dirty Read | 커밋되지 않은 타 트랜잭션의 변경데이터를 읽음 |
| Non-repeatable Read | 동일 트랜잭션 내 같은 행을 재조회 시 값이 변경되어 조회됨 |
| Phantom Read | 동일 조건 재조회 시 타 트랜잭션의 삽입/삭제로 결과행 개수 변화 |

**격리수준별 방지범위**

| 격리수준 | Dirty Read | Non-repeatable Read | Phantom Read |
|---|---|---|---|
| Read Uncommitted | 발생 | 발생 | 발생 |
| Read Committed | 방지 | 발생 | 발생 |
| Repeatable Read | 방지 | 방지 | 발생(DB별 상이) |
| Serializable | 방지 | 방지 | 방지 |

**상세**: 격리수준 강화 시 Lock 범위 확대·MVCC 스냅샷 유지로 일관성은 향상되나 동시성 저하 및 처리량 감소 발생. MySQL InnoDB는 Repeatable Read에서도 Next-Key Lock으로 Phantom Read를 방지함.

**고려사항**: 업무 특성에 따라 격리수준을 선택적 적용(금융거래는 Serializable, 조회위주 업무는 Read Committed)하고, 낙관적 동시성제어(MVCC) 활용으로 성능-일관성 균형을 확보해야 함.

### 84. IEEE 표준과 IEC 국제표준의 비교

**개요**: IEEE(Institute of Electrical and Electronics Engineers)와 IEC(International Electrotechnical Commission)는 각각 전기·전자·IT 분야의 표준을 제정하는 대표적 표준화기구로, 표준의 제정주체·적용범위·절차상 차이가 존재함.

**비교**

| 구분 | IEEE | IEC |
|---|---|---|
| 성격 | 미국 기반 전문가단체(민간, 사실상표준 De facto) | 정부간 국제기구 성격(공적표준 De jure) |
| 주요분야 | 소프트웨어공학, 네트워크(802.11 등), 반도체 | 전기전자기기, 안전, 스마트그리드 |
| 제정절차 | 워킹그룹 중심 상대적으로 신속 | 각국 국가표준기관(NC) 투표기반, 절차 상대적으로 장기 |
| 대표표준 | IEEE 802(LAN), IEEE 754(부동소수점), IEEE 12207(SW생명주기) | IEC 61508(기능안전), IEC 62443(산업보안), IEC/ISO 27001(공동) |
| 국제성 | 사실상 글로벌 채택되나 공적 국제표준 아님 | 회원국 합의기반 공적 국제표준(ISO와 협력) |

**상세**: IEEE는 신기술 대응력이 빠르고 산업계 실무 반영이 용이하여 통신·SW분야에서 사실상표준으로 광범위하게 채택됨. IEC는 ISO와 공동으로 JTC1 등을 운영하며 국가간 무역·안전 규제와 연계된 공적 표준으로 기능함.

**시사점**: 양 표준은 상호 보완적으로 활용되며(예: IEEE 802.11이 국제표준화 과정에서 ISO/IEC 채택), 기업은 기술개발 시 IEEE 표준을 선도적으로 적용하고 국제인증 시 IEC/ISO 표준 준수를 병행해야 함.

### 85. 인공지능 시스템의 취약점

**1. 개요**  
- 정의: AI 모델의 학습·추론·배포 전 생애주기에서 발생하는 보안 결함으로, 공격자가 모델의 오작동, 정보유출, 자산탈취를 유발할 수 있는 취약점을 의미함  
- 필요성: AI가 금융·의료·자율주행 등 고위험 영역에 적용 확대됨에 따라, 전통적 SW보안과 달리 데이터·모델 자체를 겨냥한 신규 위협에 대한 대응체계 필요성 증대됨

**2. 주요 취약점 유형**

| 유형 | 공격시점 | 설명 |
|---|---|---|
| 적대적 공격(Adversarial Attack) | 추론단계 | 미세 노이즈 삽입으로 오분류 유도 |
| 데이터 포이즈닝 | 학습단계 | 학습데이터 오염으로 모델 왜곡·백도어 삽입 |
| 모델 추출(Model Extraction) | 추론단계 | 질의-응답 반복분석으로 모델구조·파라미터 복제 |
| 멤버십 추론/프라이버시 침해 | 추론단계 | 특정 데이터의 학습포함 여부 추론, 원본데이터 재구성 |

**3. 상세 설명**  
- 적대적 공격: FGSM, PGD 등 gradient기반 perturbation으로 결정경계를 왜곡, White/Black-box 방식 존재함  
- 데이터 포이즐닝: Label flipping, Trigger 삽입형 백도어 공격 등으로 특정 입력에서만 오작동 유발  
- 모델추출: API 반복호출로 대체모델(Surrogate) 생성, 지식재산 침해 및 후속 공격의 발판 제공  
- 프라이버시 침해: 멤버십 추론공격(MIA), 모델 인버전 공격을 통해 학습데이터 노출

**4. 기대효과 및 고려사항**  
- 대응: 적대적학습(Adversarial Training), 입력 검증·이상탐지, 차등정보보호(Differential Privacy), 모델워터마킹 적용  
- 고려사항: AI 보안생애주기(MLSecOps) 관점의 지속적 모니터링, AI 특화 보안 가이드라인(OWASP ML Top10 등) 준용 필요

### 86. DMA(Direct Memory Access)

**1. 개요**  
- 정의: CPU 개입 없이 I/O 장치와 메모리 간 데이터를 직접 전송하는 방식으로, DMA 컨트롤러(DMAC)가 버스 제어권을 위임받아 전송을 수행함  
- 필요성: CPU가 매 바이트 전송을 관장하는 폴링/인터럽트 방식의 오버헤드를 제거, 대용량 데이터 전송시 CPU 자원 효율화 필요

**2. 구성요소**

| 구성 | 역할 |
|---|---|
| DMA Controller | 전송 주소·길이·모드 관리, 버스 중재 |
| Address Register | 메모리 시작주소 저장 |
| Count Register | 전송할 바이트/워드 수 저장 |
| Bus Arbiter | CPU-DMAC간 버스 사용권 조정 |

**3. 상세 설명 (동작 절차)**  
1) CPU가 DMAC에 전송할 장치, 메모리주소, 길이, 방향(R/W) 설정(Programming)  
2) CPU는 DMA 요청 후 다른 작업 수행(연산 병행)  
3) I/O장치 준비완료시 DREQ 신호로 DMAC에 전송요청  
4) DMAC가 버스 제어권 획득(Cycle Stealing/Burst/Block 모드) 후 메모리-I/O간 직접 전송  
5) 전송완료시 DMAC가 CPU에 인터럽트(DACK/EOP)로 완료 통지  
- 전송모드: Cycle Stealing(버스를 짧게 점유, CPU와 공유), Burst Mode(전체 블록 일괄 전송, 고속이나 CPU 지연 발생)

**4. 기대효과 및 고려사항**  
- 효과: CPU 개입 최소화로 처리율 향상, 디스크·네트워크·그래픽 등 대용량 I/O 성능 개선  
- 고려사항: 캐시 일관성 문제(Cache Coherency) 발생 가능하여 캐시 무효화/Snooping 필요, 다중 DMA채널 사용시 버스 경쟁 관리 필요

### 87. 프로젝트 위험관리 (PMBOK 기준)

**1. 개요**  
- 정의: 프로젝트 목표(범위·일정·비용·품질)에 긍정적/부정적 영향을 줄 수 있는 불확실 사건을 식별·분석하여 대응·통제하는 관리활동  
- 필요성: 프로젝트 복잡성·불확실성 증가에 따라 사후대응보다 사전예방적 관리로 실패비용 최소화 필요

**2. PMBOK 리스크관리 프로세스**

| 프로세스 | 주요 내용 |
|---|---|
| 리스크 관리계획 | 리스크 관리방침·역할·기준(Risk Appetite) 정의 |
| 리스크 식별 | 브레인스토밍, 체크리스트, SWOT, Risk Register 작성 |
| 정성/정량 분석 | 발생확률·영향도 평가, P-I Matrix, EMV, Monte Carlo |
| 대응계획 수립 | 회피/전이/완화/수용(위협), 활용/공유/증대(기회) |
| 리스크 감시(Monitor) | 잔존리스크 추적, 신규리스크 식별, 대응효과 검토 |

**3. 상세 설명**  
- 식별단계: 내부(기술·자원)·외부(시장·법규) 리스크를 Risk Register에 등록(원인-사건-영향 구조화)  
- 정성분석: 확률·영향 매트릭스로 우선순위 등급화(High/Medium/Low)  
- 정량분석: 기대금전가치(EMV), 민감도분석, 의사결정나무 활용, 예비비(Contingency Reserve) 산출  
- 대응전략: 부정적 리스크는 회피(Avoid)·전이(Transfer, 보험/외주)·완화(Mitigate)·수용(Accept), 긍정적 리스크는 활용(Exploit)·공유(Share)  
- 감시: 반복적 리스크 감사(Risk Audit), 워크어라운드(Workaround) 대응, EVM 연계 추적

**4. 기대효과 및 고려사항**  
- 효과: 예산초과·일정지연 사전방지, 의사결정 신뢰성 확보  
- 고려사항: 전 생애주기 반복적(Iterative) 수행 필요, 조직의 리스크 성향과 이해관계자 소통 병행 필요

### 88. HNDL(Harvest Now, Decrypt Later) 공격

**1. 개요**  
- 정의: 현재는 해독 불가한 암호화 데이터를 대량 수집·저장한 후, 향후 양자컴퓨터 등 해독역량 확보시점에 사후 복호화하는 공격 기법  
- 배경: RSA·ECC 등 공개키 암호는 Shor 알고리즘 기반 양자컴퓨터로 다항시간 해독 가능하다는 이론적 취약성 존재, 장기보관 필요 민감정보(국방·의료·금융)에 실질적 위협으로 부상

**2. 특징**

| 구분 | 내용 |
|---|---|
| 공격시점 이원화 | 수집(현재)-해독(미래)이 시간적으로 분리 |
| 대상 데이터 | 장기 기밀성 요구 데이터(국가기밀, 개인정보, 지재권) |
| 위협원천 | CRQC(Cryptographically Relevant Quantum Computer) 출현 |
| 탐지 어려움 | 수집행위 자체는 정상 네트워크 트래픽과 구분 어려움 |

**3. 상세 설명**  
- 공격절차: ①암호화 트래픽/저장데이터 무차별 수집 및 아카이빙 → ②양자컴퓨터 상용화 대기 → ③Shor알고리즘 등으로 RSA/ECC 개인키 역산 → ④과거 수집 데이터 일괄 복호화  
- 위험성: 데이터의 유효기간(비밀유지 필요기간)이 양자컴퓨터 실현시점보다 길 경우 실질적 피해로 직결(예: 30년 보관 국가기밀)  
- 근본 취약점: 현행 PKI가 소인수분해·이산대수 문제의 계산적 난이도에 기반, 양자 알고리즘 앞에서 안전성 붕괴

**4. 기대효과 및 고려사항(대응방안)**  
- PQC(Post-Quantum Cryptography) 전환: NIST 표준화(CRYSTALS-Kyber/Dilithium 등) 알고리즘 조기 도입  
- 하이브리드 암호화: 기존 암호+PQC 병행 적용으로 전환 리스크 완화  
- 암호이전 로드맵(Cryptographic Agility) 수립, 장기보관 데이터 우선 재암호화 및 양자내성 키관리체계 구축 필요

### 91. 피지컬 AI(Physical AI)

**1. 개요**  
- 정의: 디지털 공간의 인지·추론 능력을 갖춘 AI가 로봇·자율기기 등 물리적 실체(Embodiment)에 결합되어 현실세계를 인지·판단·행동하는 AI 패러다임  
- 배경: 기존 생성형AI가 텍스트·이미지 등 디지털 영역에 국한된 한계를 넘어, 센서·액추에이터를 통해 실세계와 상호작용하는 Embodied AI로 진화 요구 증대됨

**2. 특징 및 구성요소**

| 구성요소 | 내용 |
|---|---|
| 인지(Perception) | 카메라·라이다·센서로 환경정보 수집 |
| 판단(Reasoning) | Foundation Model 기반 상황이해·계획수립 |
| 행동(Action) | 로봇팔·모빌리티 등 액추에이터로 물리적 실행 |
| 학습 | 시뮬레이션(디지털트윈) 기반 강화학습 및 Sim-to-Real 전이 |

**3. 상세 설명**  
- 핵심원리: 인지-판단-행동 루프(Perception-Cognition-Action Loop)를 실시간 폐루프로 구성, 멀티모달 파운데이션 모델이 상황판단 담당  
- 학습방식: 실물학습의 비용·위험 한계를 극복하기 위해 가상시뮬레이터(Omniverse 등)에서 대량 학습 후 실제 로봇에 전이(Sim-to-Real)  
- 적용분야: 자율주행, 산업용 협동로봇, 물류자동화, 휴머노이드 등  
- 기존AI와 차이: 디지털AI는 정보처리에 국한되나, 피지컬AI는 물리법칙·불확실성이 존재하는 실세계에서 즉시 행동결과가 발생

**4. 기대효과 및 고려사항**  
- 효과: 제조·물류·돌봄 등 노동집약산업의 자동화 고도화, 위험작업 대체  
- 고려사항: 실세계 오작동시 안전사고 직결되므로 Safety Layer 및 인간개입(HITL) 체계 필수, 대규모 실물데이터 수집·표준화 과제 존재

### 92. 클라우드 네이티브 보안

### 93. SVM(Support Vector Machine)

**1. 개요**  
- 정의: 두 클래스 데이터를 구분하는 초평면(Hyperplane) 중 마진(Margin)을 최대화하는 최적 결정경계를 찾는 지도학습 기반 분류/회귀 알고리즘  
- 필요성: 단순 선형분류는 과적합·일반화 성능에 한계가 있어, 데이터간 여유공간을 최대화하여 노이즈에 강건하고 일반화 성능이 우수한 분류기 필요성에서 고안됨

**2. 핵심 구성요소**

| 구성요소 | 내용 |
|---|---|
| 지원벡터(Support Vector) | 결정경계에 가장 근접한 학습데이터, 경계 결정에 직접 관여 |
| 마진(Margin) | 결정경계와 최근접 데이터간 거리, 이를 최대화(Maximum Margin) |
| 슬랙변수(Slack Variable) | 완전분리 불가시 오분류 허용 정도(Soft Margin) |
| 커널함수 | 저차원 비선형데이터를 고차원으로 매핑하여 선형분리 가능화 |

**3. 상세 설명**  
- 마진 최대화: 결정경계 wx+b=0 기준 |

|w|
|를 최소화(=마진 최대화)하는 제약최적화 문제로 정식화, 라그랑지안 쌍대문제(Dual Problem)로 변환하여 해석 - Soft Margin: C(패널티 파라미터)로 마진크기와 오분류 허용의 트레이드오프 조절, C가 클수록 오분류에 엄격(과적합 위험) - 커널트릭(Kernel Trick): 실제 고차원 매핑 없이 커널함수(Linear, Polynomial, RBF/Gaussian, Sigmoid)로 내적연산만 계산하여 연산량 절감하면서 비선형 분리 수행 - 다중클래스 확장: One-vs-One, One-vs-Rest 방식으로 이진분류기를 조합

**4. 기대효과 및 고려사항**  
- 효과: 고차원 소규모 데이터에서 우수한 일반화 성능, 과적합에 강건  
- 고려사항: 대용량데이터에서 연산복잡도 급증, 커널·하이퍼파라미터(C, gamma) 선택에 성능 민감, 다중클래스 처리 시 계산비용 증가

### 94. OT 환경의 제로트러스트 필요성 및 핵심원칙

**1. 개요**  
- 정의: OT(Operational Technology, 산업제어시스템) 환경에 "암묵적 신뢰 배제, 모든 접근을 지속적으로 검증"하는 제로트러스트 원칙을 적용하는 보안모델  
- 필요성: IT-OT 융합(스마트팩토리) 확대로 폐쇄망 전제가 붕괴되었고, 랜섬웨어의 OT 침투·경계기반 보안의 한계가 노출되어 최소권한·지속검증 기반 보안체계 전환 필요

**2. OT-IT 환경 차이 및 적용 난제**

| 구분 | IT 환경 | OT 환경 |
|---|---|---|
| 우선순위 | 기밀성(C) | 가용성(A)·안전성 |
| 시스템수명 | 3~5년 | 15~20년(legacy 다수) |
| 패치/인증 | 상시 가능 | 실시간성 저해로 제약 |
| 프로토콜 | 표준(TCP/IP) | Modbus 등 인증기능 부재 프로토콜 |

**3. 핵심원칙**  
- 명시적 검증(Verify Explicitly): 모든 사용자·디바이스·엔지니어링 워크스테이션 접근시 신원·상태 지속 인증  
- 최소권한 접근(Least Privilege): 운전원·정비자별 세분화된 권한부여, Just-In-Time 접근 적용  
- 마이크로세그멘테이션: PLC·HMI·SCADA 등 자산군을 네트워크 존(Zone)/컨듀잇(Conduit)으로 분리, 측방이동(Lateral Movement) 차단(IEC 62443 연계)  
- 위반가정(Assume Breach): 침해를 전제로 지속적 트래픽 모니터링·이상행위 탐지 및 자동격리 체계 구축  
- 가시성 확보: 자산 전수조사(Asset Inventory) 및 OT전용 이상탐지솔루션 연계

**4. 기대효과 및 고려사항**  
- 효과: 랜섬웨어 등 IT발 위협의 OT 확산 차단, 공급망·원격유지보수 접근 리스크 최소화  
- 고려사항: 가용성 저해 없는 인증체계 설계, 레거시 장비의 인증기능 부재 보완(게이트웨이 기반 프록시 인증), 단계적 도입 로드맵 필요

### 95. 칩렛(Chiplet)

**1. 개요**  
- 정의: 단일 SoC를 기능별로 분할한 소형 다이(Die)를 패키지 내에서 인터커넥트로 결합하여 하나의 반도체처럼 동작시키는 이종집적(Heterogeneous Integration) 기술임  
- 등장배경: 무어의 법칙 둔화, 모놀리식 SoC의 수율 저하 및 설계비용 급증, 공정 미세화 한계에 따른 대안으로 부상함

**2. 구성요소 및 유형**

| 구분 | 내용 |
|---|---|
| Compute Chiplet | CPU/GPU 코어, 연산 담당 |
| I/O Chiplet | PCIe, 메모리 컨트롤러 등 |
| 인터커넥트 | UCIe, Infinity Fabric, EMIB 등 |
| 패키징 | 2.5D/3D 적층(TSV, 실리콘 인터포저) |

**3. 상세 설명**  
- 핵심원리: 이종 공정(7nm+14nm 등)으로 제작된 다이를 인터포저 위에서 초고속 인터커넥트(대역폭 수백GB/s, 저지연)로 연결, 단일 칩처럼 동작  
- 표준화: UCIe(Universal Chiplet Interconnect Express) 표준을 통해 이종 벤더 칩렛 간 상호운용성 확보 추진  
- 설계 유연성: 필요 기능별 최적 공정 선택 가능(예: CPU는 최신공정, I/O는 성숙공정)

**4. 기대효과 및 고려사항**  
- 기대효과: 수율 향상에 따른 원가절감, 설계 재사용성 증대, TTM(Time to Market) 단축  
- 고려사항: 다이 간 열관리, 인터커넥트 지연/전력 오버헤드, 테스트 및 검증 복잡도 증가, 표준 미성숙에 따른 벤더 종속성 우려

### 96. HBM(High Bandwidth Memory)

**1. 개요**  
- 정의: DRAM 다이를 TSV(Through Silicon Via)로 수직 적층하고 실리콘 인터포저를 통해 프로세서와 근접 연결하는 초고대역폭 메모리 규격임  
- 등장배경: AI/HPC 연산 가속기의 메모리 병목(Memory Wall) 해소를 위해 대역폭과 전력효율을 동시에 개선할 필요성에서 등장함

**2. 구성요소 및 세대별 특징**

| 세대 | 대역폭(스택당) | 특징 |
|---|---|---|
| HBM2E | ~460GB/s | 8-High 적층 |
| HBM3 | ~819GB/s | 12-High, 대용량 |
| HBM3E | ~1.2TB/s | 온디바이스 ECC 강화 |
| HBM4 | 차세대 | 로직다이 결합 검토 |

**3. 상세 설명**  
- 핵심원리: DRAM 다이 4~12개를 TSV로 수직 적층, 베이스 로직다이 통해 GPU/가속기와 인터포저 상 초단거리 배선으로 연결하여 넓은 I/O 폭(1024비트 이상) 확보  
- 기존 GDDR 대비 핀당 속도는 낮으나 병렬 채널 수가 많아 총 대역폭과 전력효율(pJ/bit)이 우수함  
- AI 가속기(GPU, NPU)의 필수 구성요소로 자리매김, HBM 공급이 AI 반도체 생산 캐파의 핵심 제약요인화

**4. 기대효과 및 고려사항**  
- 기대효과: 대규모 파라미터 모델의 학습/추론 처리량 향상, 메모리-컴퓨트 간 병목 완화  
- 고려사항: TSV 공정 수율 문제, 적층에 따른 발열 및 열저항 관리, 고비용에 따른 생산단가 상승, 인터포저 대면적화의 물리적 한계

### 97. GNN(Graph Neural Network)

**1. 개요**  
- 정의: 노드(Node)와 엣지(Edge)로 구성된 그래프 구조 데이터의 위상정보와 속성정보를 동시에 학습하는 딥러닝 모델임  
- 등장배경: 이미지/텍스트 같은 정형 격자구조가 아닌 소셜망, 분자구조, 지식그래프 등 비유클리드 데이터 분석 필요성 증대로 등장함

**2. 유형 및 구성요소**

| 유형 | 핵심 메커니즘 |
|---|---|
| GCN | 인접노드 특징 합성곱 집계 |
| GAT | Attention 기반 가중 집계 |
| GraphSAGE | 샘플링 기반 확장성 학습 |
| GIN | 그래프 동형사상 판별력 강화 |

**3. 상세 설명**  
- 핵심원리: Message Passing 방식으로 각 노드가 이웃 노드의 정보를 반복적(Layer-wise) 집계(Aggregate)하고 갱신(Update)하여 노드/그래프 임베딩 생성  
- 처리절차: ①그래프 구성 ②이웃 정보 수집(Aggregation) ③특징 갱신(Update) ④Readout을 통한 그래프 단위 표현 생성 ⑤분류/예측 수행  
- 응용분야: 추천시스템, 신약개발(분자특성 예측), 사기탐지, 지식그래프 완성, 교통망 예측 등

**4. 기대효과 및 고려사항**  
- 기대효과: 관계형 데이터의 구조적 패턴 학습으로 예측정확도 향상, 비정형 관계 데이터 활용범위 확대  
- 고려사항: Over-smoothing(층수 증가 시 노드 구분력 저하), 대규모 그래프의 확장성/연산비용, 동적 그래프 대응 한계

### 98. 데이터 분석 시 아웃라이어(Outlier)

**1. 개요**  
- 정의: 데이터 집합의 전반적 분포 패턴에서 통계적으로 크게 벗어난 관측값을 의미함  
- 필요성: 아웃라이어는 모델 성능 저하 및 통계량(평균, 분산) 왜곡의 원인이 되므로 정확한 탐지 및 처리가 데이터 분석 품질을 좌우함

**2. 탐지기법 비교**

| 기법 | 원리 | 특징 |
|---|---|---|
| Z-score | 평균 기준 표준편차 3σ 이상 판정 | 정규분포 가정, 단변량 |
| IQR | Q1-1.5IQR ~ Q3+1.5IQR 범위 초과 | 분포 무관, 강건함 |
| DBSCAN | 밀도기반 클러스터링 후 미포함점 판정 | 비선형/다변량 데이터 적합 |
| Isolation Forest | 데이터 분리 난이도로 이상치 산정 | 고차원 대용량 데이터 적합 |

**3. 상세 설명**  
- 원인 구분: 측정오류(제거대상), 자연적 극단값(보존 후 별도분석), 신종 패턴(사기/이상탐지 등 분석대상)으로 구분하여 접근 필요  
- 처리방안: ①제거(Trimming) ②변환(Log, Winsorizing) ③대체(평균/중앙값 대치) ④별도 모델링(로버스트 통계, 이상탐지 전용 모델)  
- 도메인 지식과 통계적 기준을 병행하여 판단해야 오탐(정상값 제거) 방지 가능함

**4. 기대효과 및 고려사항**  
- 기대효과: 모델 학습 안정성 및 예측 정확도 향상, 데이터 품질 신뢰성 확보  
- 고려사항: 단일 기법 의존 지양, 데이터 특성(정규성, 차원, 밀도)에 따른 기법 선택, 아웃라이어 자체가 분석목적(사기탐지 등)인 경우 제거 금지

### 99. 독립표본 t-검정과 대응표본 t-검정

**1. 개요**  
- 정의: 두 집단 간 평균 차이의 통계적 유의성을 검증하는 모수적 가설검정 기법으로, 표본구조에 따라 독립표본(Independent)과 대응표본(Paired) 방식으로 구분됨  
- 필요성: 표본 간 관계(독립/연관)를 무시하고 부적합한 검정을 적용하면 제1종/제2종 오류가 증가하므로 적용조건 구분이 중요함

**2. 두 검정 비교**

| 구분 | 독립표본 t-검정 | 대응표본 t-검정 |
|---|---|---|
| 대상 | 서로 다른 두 집단 | 동일 대상의 사전/사후 측정 |
| 예시 | A반 vs B반 성적 비교 | 교육 전/후 동일인 성적 비교 |
| 통계량 계산 | 두 집단 평균차/합동분산 기반 | 짝의 차이값(d) 평균/표준편차 기반 |
| 가정 | 독립성, 정규성, 등분산성 | 차이값의 정규성 |
| 자유도 | n1+n2-2 | n-1(n=짝의 수) |

**3. 상세 설명**  
- 독립표본: 등분산 가정 충족 시 Pooled t-test, 미충족 시 Welch's t-test 적용, Levene 검정으로 등분산성 사전 확인 필요  
- 대응표본: 개체 내 변동요인(개인차)을 제거하여 검정력이 높으며, 각 짝의 차이값(d_i)에 대해 단일표본 t-검정과 동일한 방식으로 계산  
- 비모수 대안: 정규성 미충족 시 독립표본은 Mann-Whitney U검정, 대응표본은 Wilcoxon 부호순위검정 사용

**4. 기대효과 및 고려사항**  
- 기대효과: 데이터 구조에 맞는 검정 선택으로 검정력 및 결과 신뢰성 제고  
- 고려사항: 표본 간 연관성 오판 시 오류 발생, 표본크기 및 정규성 사전 검증(Shapiro-Wilk 등) 필수

### 100. GPUaaS(GPU as a Service)

**1. 개요**  
- 정의: 클라우드 사업자가 GPU 자원을 가상화 또는 물리적으로 제공하여 사용자가 필요 시점에 온디맨드 방식으로 임대·사용하는 클라우드 서비스 모델임  
- 등장배경: AI/딥러닝 학습·추론 수요 급증에 따른 고비용 GPU 인프라 자체 구축의 부담을 경감하고, 탄력적 자원활용 필요성에서 등장함

**2. 제공유형 및 구성요소**

| 유형 | 내용 |
|---|---|
| Bare-metal GPU | 물리 GPU 서버 전용 할당 |
| vGPU(가상화) | 하나의 물리GPU를 다중 사용자 분할 |
| MIG(Multi-Instance GPU) | GPU 내부 하드웨어 파티셔닝 |
| Serverless GPU | 함수 단위 초단기 GPU 과금 |

**3. 상세 설명**  
- 핵심기술: GPU 가상화(NVIDIA vGPU, MIG), 컨테이너 오케스트레이션(K8s+GPU Operator), 원격 GPU 풀링, 과금은 사용시간/자원단위(vCPU-GPU 결합) 기준  
- 서비스 형태: IaaS형(EC2 P/G시리즈 등 인스턴스 임대), PaaS형(관리형 학습 플랫폼), Serverless형(함수 단위 추론)으로 세분됨  
- 주요 사업자: AWS, Azure, GCP 외 특화 GPU 클라우드(CoreWeave, Lambda Labs 등)가 시장 확대 중

**4. 기대효과 및 고려사항**  
- 기대효과: 초기 CAPEX 절감, 필요시점 확장(Elasticity)으로 자원효율 극대화, 최신 GPU 신속 도입 가능  
- 고려사항: 데이터 반출에 따른 보안/규제 이슈, 벤더 종속(Lock-in), 사용량 급증 시 비용 최적화 필요, 멀티테넌시 환경의 자원격리 보안
