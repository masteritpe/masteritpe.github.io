## 1교시형 문제 풀이

## 1. WBS (Work Breakdown Structure)

<b>I. WBS의 개요</b>

* <b>정의:</b> 프로젝트의 목표 달성과 인도물 산출을 위해 프로젝트 팀이 실행해야 할 작업을 관리 가능한 단위(Work Package)로 분할한 계층적 작업 분할 구조도입니다.  
* <b>목적:</b> 일정, 원가, 자원 통제의 기준선(Baseline) 제공 및 이해관계자 간의 의사소통 도구로 활용됩니다.

<b>II. WBS의 핵심 구성요소</b>

| 구성요소 | 설명 |
| --- | --- |
| <b>Work Package</b> | WBS의 최하위 작업 단위로, 일정과 원가를 신뢰성 있게 추정하고 통제할 수 있는 기준점 |
| <b>Code of Accounts</b> | 각 WBS 구성요소를 유일하게 식별하기 위해 부여하는 식별 번호 체계 (비용 추적과 연계) |
| <b>WBS Dictionary</b> | 각 작업 패키지의 상세 내용, 책임자, 인수 기준, 필요 자원 등을 구체적으로 기술한 문서 |

---

## 2. IT-ROI 투자 성과평가 모델

<b>I. IT-ROI의 개요</b>

* <b>정의:</b> 기업이 IT에 투자한 자본(비용) 대비 창출되는 재무적/비재무적 가치(효과)를 정량적으로 평가하여 타당성을 검증하는 기법입니다.  
* <b>특징:</b> 단순 비용 절감뿐만 아니라 프로세스 개선, 의사결정 속도 향상 등 무형의 효과를 화폐 가치로 환산하는 것이 핵심입니다.

<b>II. IT-ROI 주요 평가 지표</b>

| 지표 | 설명 | 특징 |
| --- | --- | --- |
| <b>NPV (순현재가치)</b> | 투자로 발생하는 현금흐름의 현재가치 합 - 투자금액 | 0보다 크면 투자 타당성 확보 |
| <b>IRR (내부수익률)</b> | NPV를 0으로 만드는 할인율 | 자본비용(이자율)보다 높으면 타당 |
| <b>PP (투자회수기간)</b> | 누적 현금흐름이 투자금액과 같아지는 기간 | 짧을수록 유동성 및 위험 측면에서 유리 |

---

## 3. 소프트웨어 개발 프로젝트 품질비용(Q-Cost) 4가지

<b>I. 품질비용의 개요</b>

* 소프트웨어 품질을 확보하기 위해 예방 및 평가하는 데 드는 비용과, 품질 기준을 충족하지 못해 발생하는 실패 비용의 총합(PAF 모델)입니다.

<b>II. 품질비용 항목 4가지 및 사례</b>

| 구분 | 품질비용 항목 | 설명 | 사례 |
| --- | --- | --- | --- |
| <b>적합비용</b> | <b>1. 예방 비용 (Prevention)</b> | 결함 발생을 사전에 방지하기 위해 투입되는 비용 | 품질 교육, 방법론/도입, 요구사항 분석, 프로세스 개선 |
|  | <b>2. 평가 비용 (Appraisal)</b> | 산출물이 요구사항을 충족하는지 검사/측정하는 비용 | 코드 리뷰, 인스펙션, 통합/시스템 테스트, 감리 비용 |
| <b>부적합비용</b> | <b>3. 내부실패 비용 (Internal)</b> | 고객에게 인도되기 전, 테스트 과정에서 발견된 결함 해결 비용 | 재작업(Rework), 재테스트, 디버깅, 설계 변경 |
|  | <b>4. 외부실패 비용 (External)</b> | 고객에게 인도된 후, 운영 환경에서 발견된 결함 해결 비용 | 유지보수, 고객 보상/소송, 브랜드 이미지 실추, 리콜 |

## 4. CBAM (Cost Benefit Analysis Method)

<b>I. CBAM의 개요</b>

* <b>정의:</b> 소프트웨어 아키텍처 평가 기법인 ATAM(Architecture Trade-off Analysis Method)의 결과를 바탕으로, 아키텍처 전략의 '경제적 타당성(비용-편익)'을 평가하는 모델입니다.  
* <b>목적:</b> 한정된 자원 내에서 시스템 품질 속성(가용성, 성능 등)을 극대화하기 위해 최적의 아키텍처 전략을 선택합니다.

<b>II. CBAM 평가 절차</b>

1. <b>시나리오 및 효용(Utility) 평가:</b> ATAM에서 도출된 시나리오별 비즈니스 가치 할당  
2. <b>아키텍처 전략 도출:</b> 시나리오 달성을 위한 아키텍처 전략 구성  
3. <b>비용 및 편익 산정:</b> 전략 구현에 드는 비용과 예상되는 효용(편익) 계산  
4. <b>ROI 도출 및 전략 선택:</b> (편익 / 비용) 비율을 계산하여 ROI가 가장 높은 아키텍처 전략을 우선순위화

## 5. 빅데이터 분석에서 상관관계와 인과관계

<b>I. 개념 비교</b>

* <b>상관관계 (Correlation):</b> 두 변수가 서로 어떤 선형적/비선형적 패턴을 보이며 함께 변화하는지(동조성)를 나타내는 통계적 관계입니다.  
* <b>인과관계 (Causation):</b> 한 변수(원인)의 변화가 다른 변수(결과)의 변화를 직접적으로 초래하는 관계입니다.

<b>II. 상세 비교 및 빅데이터 관점의 차이</b>

| 구분 | 상관관계 (Correlation) | 인과관계 (Causation) |
| --- | --- | --- |
| <b>방향성</b> | 양방향성 (A ↔ B) | 단방향성 (A → B) |
| <b>제3의 변수</b> | 잠복변수(Lurking Variable) 통제 안 됨 | 외부 변인 통제 및 검증 필요 |
| <b>빅데이터 적용</b> | <b>예측 분석(Predictive):</b> 빠른 패턴 발견을 통한 추천 알고리즘 등에 주로 활용 | <b>처방 분석(Prescriptive):</b> 마케팅 효과 검증, 정책 수립 등 개입(Intervention)이 필요할 때 활용 |

## 6. 뉴로모픽 칩 (Neuromorphic Chip)

<b>I. 뉴로모픽 칩의 개요</b>

* <b>정의:</b> 인간 뇌의 신경 세포(Neuron)와 연결 고리(Synapse) 구조를 반도체 하드웨어로 모방하여, 정보를 병렬적으로 처리하는 차세대 인공지능 반도체입니다.

<b>II. 핵심 기술 및 특징</b>

| 구분 | 상세 내용 |
| --- | --- |
| <b>핵심 기술</b> | <b>SNN (Spiking Neural Network):</b> 특정 임계치(Threshold)를 넘는 신호(Spike)가 발생할 때만 정보를 전달하는 이벤트 기반 처리 기술<br><b>Memristor (멤리스터):</b> 전원 공급이 끊겨도 이전의 상태를 기억하는 소자로 시냅스 모방 |
| <b>주요 특징</b> | <b>초저전력:</b> 연산과 저장이 통합된 구조(In-Memory Computing)와 이벤트 구동 방식으로 전력 소모 극소화<br><b>대규모 병렬 처리:</b> 폰노이만 병목현상 극복, 실시간 비정형 데이터(이미지, 음성) 처리에 탁월 |

---

## 7. 개인정보의 가명/익명 처리 기술

<b>I. 가명 처리와 익명 처리의 개념</b>

* <b>가명 처리 (Pseudonymization):</b> 추가 정보(복호화 키 등)의 사용 없이는 특정 개인을 알아볼 수 없도록 개인정보의 일부를 삭제하거나 대체하는 조치입니다. (복원 가능)  
* <b>익명 처리 (Anonymization):</b> 시간, 비용, 기술 등을 합리적으로 고려할 때 다른 정보와 결합해도 더 이상 개인을 알아볼 수 없도록 하는 조치입니다. (복원 불가능)

<b>II. 주요 프라이버시 보호 모델 및 기술</b>

| 구분 | 주요 기술 | 설명 |
| --- | --- | --- |
| <b>가명 처리 기술</b> | <b>휴리스틱 가명화</b> | 규칙 기반으로 성명, 주민번호 등을 대체 (예: 홍길동 → 홍*동) |
|  | <b>암호화/토큰화</b> | 양방향 암호화 알고리즘을 이용해 식별자를 무의미한 값으로 변환 |
| <b>프라이버시 모델</b> | <b>K-익명성 (K-Anonymity)</b> | 동일한 속성값(준식별자)을 가진 레코드가 최소 K개 이상 존재하도록 일반화/삭제 |
|  | <b>L-다양성 (L-Diversity)</b> | K-익명성의 동질성 공격 방어를 위해 민감정보가 최소 L개의 서로 다른 값을 가짐 |
|  | <b>T-근접성 (T-Closeness)</b> | 특정 그룹의 민감정보 분포가 전체 데이터 분포와 T 이하의 차이를 보이도록 통제 |

## 8. 메모리 인터리빙 (Memory Interleaving)

<b>I. 메모리 인터리빙의 개요</b>

* <b>정의:</b> 주기억장치를 여러 개의 독립적인 뱅크(Bank)로 나누고, 연속적인 주소 접근 시 각 뱅크를 번갈아 가며 접근하여 메모리 접근 시간을 숨기는(Hiding) 병렬 처리 기법입니다.  
* <b>목적:</b> CPU의 빠른 처리 속도와 메모리의 느린 접근 속도 간의 병목 현상(Von Neumann Bottleneck)을 완화하여 메모리 대역폭을 향상시킵니다.

<b>II. 메모리 인터리빙 방식</b>

| 구분 | 상위 인터리빙 (High-order) | 하위 인터리빙 (Low-order) |
| --- | --- | --- |
| <b>구조</b> | 메모리 주소의 상위 비트로 뱅크 선택, 하위 비트로 뱅크 내 주소 선택 | 주소의 하위 비트로 뱅크 선택, 상위 비트로 뱅크 내 주소 선택 |
| <b>특징</b> | 뱅크별 독립적 모듈 구성 용이 (확장성 큼) | <b>연속된 주소에 대한 동시 접근 가능 (병렬성 극대화)</b> |
| <b>용도</b> | 다중 프로그래밍 환경의 메모리 보호, 결함 허용 | 파이프라인 처리, 캐시 메모리 라인 채우기 (성능 향상) |

## 9. 랜섬웨어(Ransomware)와 RaaS (Ransomware as a Service)

<b>I. 랜섬웨어의 개요</b>

* <b>정의:</b> 사용자의 시스템을 잠그거나 중요 데이터를 암호화하여 사용할 수 없게 만든 뒤, 이를 인질로 삼아 복호화의 대가(Ransom)로 금전을 요구하는 악성코드입니다.  
* <b>진화:</b> 단순 암호화에서 데이터 유출 후 공개하겠다고 협박하는 이중 협박(Double Extortion), 디도스 공격까지 결합한 삼중 협박(Triple Extortion)으로 진화 중입니다.

<b>II. RaaS (Ransomware as a Service)</b>

* <b>정의:</b> 랜섬웨어 개발자가 클라우드 서비스(SaaS) 형태로 악성코드, 유포 인프라, 결제 시스템을 패키지화하여 다른 범죄자(계열사, Affiliate)에게 임대하는 범죄 비즈니스 모델입니다.  
* <b>영향:</b> 프로그래밍 지식이 없는 일반인도 사이버 범죄에 쉽게 가담할 수 있어 랜섬웨어 공격의 대중화 및 규모 확대를 초래했습니다.

## 10. 큐비트 (Qubit)

<b>I. 큐비트의 개요</b>

* <b>정의:</b> 양자 컴퓨팅에서 정보를 표현하고 처리하는 기본 단위로, 고전 컴퓨터의 비트(Bit)가 0 또는 1의 확정된 상태를 갖는 것과 달리 <b>중첩(Superposition)</b> 상태를 갖는 양자 정보 단위입니다.

<b>II. 큐비트의 핵심 양자 역학적 특성</b>

| 특성 | 설명 | 파급 효과 |
| --- | --- | --- |
| <b>중첩 (Superposition)</b> | 0과 1의 상태가 동시에 확률적으로 존재하는 현상 | 다수의 큐비트로 다중 상태를 동시에 연산 가능 (기하급수적 성능 향상) |
| <b>얽힘 (Entanglement)</b> | 두 개 이상의 큐비트가 서로 강하게 연결되어, 하나의 상태가 결정되면 다른 큐비트의 상태도 즉각 결정되는 현상 | 양자 통신(양자 암호 키 분배), 초고속 병렬 정보 처리 및 상태 전송 |
| <b>관측/붕괴 (Measurement)</b> | 관측하는 순간 중첩 상태가 깨지고 0 또는 1의 고전적 비트 상태로 확정됨 | 연산 결과 도출 방식 결정, 양자 오류 정정(QEC)의 어려움 유발 |

## 1. 소프트웨어 모듈(Module)의 설계 원리

<b>I. 소프트웨어 모듈의 응집도(Cohesion)와 결합도(Coupling)</b>
소프트웨어 모듈화의 핵심 목표는 유지보수성과 재사용성을 높이는 것이며, 이를 위해 '응집도는 높이고 결합도는 낮추는(High Cohesion, Low Coupling)' 설계가 필수적입니다.

| 구분 | 설명 | 평가 기준 및 종류 (좋음 ↔ 나쁨 순) |
| --- | --- | --- |
| <b>응집도 (Cohesion)</b> | 모듈 <b>내부</b>의 구성 요소들이 하나의 목적을 위해 서로 얼마나 밀접하게 연관되어 있는가를 나타내는 척도 | <b>(강) 기 → 순 → 교 → 절 → 시 → 논 → 우 (약)</b><br>기능적, 순차적, 교환(통신)적, 절차적, 시간적, 논리적, 우연적 응집도 |
| <b>결합도 (Coupling)</b> | 모듈과 모듈 <b>외부(타 모듈)</b> 간의 의존성, 즉 상호작용 및 연결의 복잡도를 나타내는 척도 | <b>(약) 데 → 스 → 제 → 외 → 공 → 내 (강)</b><br>데이터, 스탬프, 제어, 외부, 공통, 내용 결합도 |

<b>II. 소프트웨어 모듈의 Fan-in과 Fan-out</b>
모듈의 호출 관계를 계층적 구조로 분석하여 시스템의 복잡도를 측정하고 최적화하는 지표입니다.

| 구분 | 개념 및 특징 | 설계 시 지향점 |
| --- | --- | --- |
| <b>Fan-in</b> | 특정 모듈을 제어(호출)하는 상위 모듈의 개수 | <b>높게 설계 (단, 관리 범위 내):</b> Fan-in이 높다는 것은 해당 모듈이 여러 곳에서 <b>재사용</b>되고 있음을 의미함. 단, 단일 장애점(SPOF)이 될 수 있으므로 철저한 테스트 필요. |
| <b>Fan-out</b> | 특정 모듈이 제어(호출)하는 하위 모듈의 개수 | <b>낮게 설계:</b> Fan-out이 높다는 것은 한 모듈이 너무 많은 타 모듈을 제어하여 <b>복잡도</b>가 높음을 의미함. 과도한 제어 로직을 분산시켜야 함. |

## 2. 안전 중심의 위험 분석 기법 (FMEA, HAZOP, STPA)

<b>I. 전통적 위험 분석 기법 (FMEA, HAZOP)의 특징 및 한계점</b>
기존 기법은 하드웨어 컴포넌트의 고장(Failure)이 사고로 이어진다는 선형적 인과관계에 기반합니다.

| 기법 | 특징 및 분석 방식 | 한계점 (현대 복잡 시스템 적용 시) |
| --- | --- | --- |
| <b>FMEA</b> (Failure Mode & Effects Analysis) | 상향식(Bottom-Up) 방식.<br>개별 부품의 고장 모드가 시스템 전체에 미치는 영향을 심각도, 발생도, 검출도로 평가(RPN 산출). | - 소프트웨어 오류 및 상호작용으로 인한 위험 도출 곤란<br>- 시스템 단위의 복합적 결함 원인 식별 한계 |
| <b>HAZOP</b> (Hazard & Operability Analysis) | 가이드워드(No, More, Less 등)와 공정 변수(온도, 압력 등)를 조합하여 공정상의 위험 요소를 브레인스토밍 방식으로 도출. | - 분석 대상과 가이드워드에 크게 의존하여 분석가의 주관 개입<br>- 순수 소프트웨어 시스템이나 비선형적 상호작용 분석에 취약 |

<b>II. STPA (System Theoretic Process Analysis) 개념 및 방법론</b>
STPA는 MIT의 레베슨 교수가 제안한 STAMP(System-Theoretic Accident Model and Processes) 이론에 기반하여, 사고를 '컴포넌트 고장'이 아닌 '부적절한 제어(Control)'의 문제로 바라보는 하향식(Top-Down) 시스템 안전 분석 기법입니다.

1. <b>사고(Accidents) 및 위험(Hazards) 식별:</b> 방지해야 할 최상위 수준의 시스템 사고 및 위험 정의  
2. <b>제어 구조(Control Structure) 모델링:</b> 시스템을 컨트롤러, 센서, 액추에이터, 제어 대상 프로세스의 피드백 루프로 모델링  
3. <b>불안전한 제어 행동(UCA, Unsafe Control Actions) 식별:</b> 제어 명령 제공 안 함, 잘못된 제어 명령 제공, 너무 빠르거나 늦게 제공, 너무 오래 지속 등 4가지 유형으로 UCA 도출  
4. <b>손실 시나리오(Causal Scenarios) 식별:</b> UCA가 발생하게 된 근본 원인(센서 오류, 피드백 지연, 잘못된 프로세스 모델 등)을 도출하여 안전 요구사항 수립

## 3. 데이터 통합 및 마이그레이션 품질 관리

<b>I. 데이터 무결성(Integrity)과 정합성(Consistency)의 차이</b>

| 구분 | 데이터 무결성 (Integrity) | 데이터 정합성 (Consistency) |
| --- | --- | --- |
| <b>정의</b> | 데이터베이스 내에 저장된 데이터 값이 현실 세계의 <b>정확한 실제 값을 유지</b>하는 성질 (정확성, 유효성) | 분산되거나 중복된 데이터가 <b>어느 시점, 어느 위치에서든 동일한 값을 유지</b>하는 성질 (일치성, 모순 없음) |
| <b>핵심 관점</b> | 데이터 자체의 규칙 준수 (도메인, 엔터티, 참조 무결성 제약조건) | 이기종/분산 DB 또는 마이그레이션 전/후의 데이터 값의 동기화 |
| <b>장애 원인</b> | 잘못된 입력, 제약조건 미설정, 악의적 변조 | 트랜잭션 오류, 비동기화, 마이그레이션 매핑 오류 |

<b>II. 데이터 값(Value) 진단 프로파일링의 중점 분석 관점</b>
데이터 값 프로파일링은 메타데이터가 아닌 실제 컬럼에 적재된 데이터를 분석하여 품질을 측정합니다.

* <b>결측값(Missing Value) 분석:</b> Null 값, 공백(' '), 의미 없는 기본값(예: 9999)의 존재 여부 및 비율  
* <b>유효값(Domain) 분석:</b> 데이터 타입, 길이, 정해진 코드 값(예: 남/여), 값의 범위(최대/최소) 준수 여부  
* <b>패턴 및 포맷 분석:</b> 주민등록번호, 전화번호, 이메일 등 특정 정규식(Regex) 형태와 일치하는지 분석  
* <b>유일성(Uniqueness) 및 중복 분석:</b> 식별자 컬럼에 중복된 값이 존재하는지, 업무 규칙상 유일해야 하는 값의 중복 여부 확인

<b>III. 데이터 마이그레이션 검증 테스트 방법</b>

| 단계 | 테스트 방법 | 주요 검증 내용 |
| --- | --- | --- |
| <b>사전 검증</b> (Pre-Migration) | <b>매핑 룰 검증</b> | AS-IS 데이터와 TO-BE 메타데이터 간의 데이터 매핑(Mapping) 정의서 정합성 및 변환 로직(ETL) 스크립트 검증 |
| <b>이행 중 검증</b> (In-Migration) | <b>건수 및 금액(Sum) 검증</b> | 원천 데이터와 타겟 데이터 간의 총 마이그레이션 건수(Count)와 핵심 숫자 데이터의 해시 합산 금액(Checksum) 일치 확인 |
| <b>사후 검증</b> (Post-Migration) | <b>병행 테스트 (Parallel Test)</b> | 신/구 시스템에 동일한 입력값을 주고 산출된 결과가 동일한지 대조 검증 (어플리케이션 연동 검증 포함) |

## 4. 연합학습 (Federated Learning)

<b>I. 연합학습의 동작 원리</b>
연합학습은 데이터 프라이버시를 보호하기 위해 원본 데이터를 중앙 서버로 집중시키지 않고, <b>각 로컬 디바이스(또는 엣지 노드)에서 모델을 학습시킨 후 도출된 가중치(Weight)나 기울기(Gradient)만을 중앙 서버로 전송하여 글로벌 모델을 갱신</b>하는 분산 AI 학습 기법입니다.

* (1) 중앙 서버가 초기 글로벌 모델을 디바이스에 배포 $\rightarrow$ (2) 디바이스는 로컬 데이터로 모델 학습 $\rightarrow$ (3) 학습된 파라미터(가중치)를 중앙 서버로 전송 $\rightarrow$ (4) 중앙 서버는 파라미터를 취합(Aggregation)하여 글로벌 모델 업데이트 $\rightarrow$ (1) 반복

<b>II. 연합학습의 주요 알고리즘</b>

| 알고리즘 | 특징 및 원리 |
| --- | --- |
| <b>FedAvg</b> (Federated Averaging) | 각 클라이언트가 로컬에서 SGD(Stochastic Gradient Descent)를 여러 번 반복하여 파라미터를 구한 뒤, 서버에서 데이터 크기에 비례하여 <b>가중 평균(Weighted Average)</b>을 내는 가장 표준적인 알고리즘 |
| <b>FedProx</b> | 비동질적인(Non-IID) 데이터 환경에서 클라이언트 간 데이터 편차로 인한 글로벌 모델의 발산을 방지하기 위해 로컬 최적화 과정에 근접성 항(Proximal Term)을 추가한 알고리즘 |
| <b>FedSGD</b> | 로컬 디바이스에서 단 한 번의 Gradient 연산만 수행 후 서버로 전송하는 방식으로, 통신 비용이 크나 수렴에 대한 이론적 보장이 강함 |

<b>III. 연합학습의 보안 및 프라이버시 보장형 기술</b>
가중치 전송 과정에서의 역추적(Inference Attack)을 방지하기 위해 다음 기술을 융합합니다.

* <b>동형암호 (Homomorphic Encryption):</b> 클라이언트가 전송하는 모델 파라미터를 암호화하고, 중앙 서버는 암호화된 상태 그대로 연산(평균값 산출)을 수행하여 데이터 유출을 원천 차단.  
* <b>차분 프라이버시 (Differential Privacy, DP):</b> 로컬에서 파라미터를 전송하기 전, 통계적 특성은 유지하면서 개별 데이터의 식별을 막기 위해 의도적인 노이즈(Noise)를 주입.  
* <b>SMPC (안전한 다자간 연산):</b> 여러 노드가 파라미터를 분할하여 암호학적 프로토콜에 따라 교환·연산함으로써, 개별 노드의 기여도를 서버가 역추적할 수 없도록 보호.

## 5. 6G SATIN (위성-상공-지상 통합 무선 네트워크)

<b>I. SATIN의 개념 및 네트워크 특징</b>

* <b>개념:</b> 6G 통신의 초공간(Hyper-Coverage) 목표를 달성하기 위해, 지상 기지국뿐만 아니라 위성(LEO/MEO/GEO), 상공의 무인기(UAV), 고고도 플랫폼(HAPS)을 다층적으로 연동하여 지구 전체를 3차원으로 덮는 통합 네트워크 망입니다.  
* <b>네트워크 특징:</b> 통신 음영 지역 해소 (100% 커버리지), 3D 동적 라우팅 및 빔포밍, 지상-위성 간 끊김 없는 핸드오버(Seamless Handover), 상공 엣지 컴퓨팅(Aerial MEC) 지원.

<b>II. SATIN의 영역별 활용 방법</b>

| 활용 분야 | 적용 방안 및 이점 |
| --- | --- |
| <b>1. 재난 대비</b> | 지상 통신 인프라(기지국, 광케이블)가 지진/태풍 등으로 파괴되었을 때, 상공의 UAV나 저궤도(LEO) 위성이 즉각적인 <b>백홀(Backhaul) 링크를 제공</b>하여 긴급 통신망 복구 및 구조대 통신 지원. |
| <b>2. UAV 활용</b> | 다수의 군집 드론이 공중 기지국 역할을 수행(Drone-as-a-Base-Station). 이동하는 스포츠 경기장, 야외 축제 등 트래픽이 일시적으로 폭증하는 핫스팟 지역에 동적으로 통신 용량을 제공. |
| <b>3. 낙후지역 지원</b> | 해양, 사막, 산간 오지 등 광케이블 매설 비용이 경제적으로 타당하지 않은 지역에 위성과 HAPS를 통해 초고속 광대역 인터넷 서비스(Broadband)를 제공하여 글로벌 디지털 정보 격차 해소. |

## 6. 양자암호통신 (Quantum Cryptography)

<b>I. 양자암호통신의 암호키 분배방식 (QKD, Quantum Key Distribution)</b>
양자 역학의 '복제 불가능성(No-cloning)'과 '관측 시 상태 붕괴' 특성을 이용하여, 송신자(Alice)와 수신자(Bob)가 안전하게 대칭키를 나누어 가지는 기술입니다.

* <b>BB84 프로토콜 원리:</b> 송신자가 광자의 편광 상태(수평/수직, 대각)를 이용해 큐비트를 전송하고, 수신자는 임의의 기저로 측정 후 서로 사용한 기저만 퍼블릭 채널로 비교하여 일치한 비트만을 최종 비밀키로 확정. 도청자(Eve)가 중간에 관측하면 양자 상태가 붕괴하여 오류율이 급증하므로 즉시 도청을 감지함.

<b>II. 양자암호통신의 주요 기술</b>

| 핵심 기술 | 설명 |
| --- | --- |
| <b>단일 광자 생성 및 검출 기술</b> | 펄스 당 정확히 하나의 광자만을 방출하는 광원(Source) 기술과, 미세한 단일 광자 신호를 포착하여 노이즈와 구분하는 SPD(Single Photon Detector) 기술 |
| <b>양자 채널 (Quantum Channel)</b> | 광자를 멀리까지 훼손 없이 전송하기 위한 매체 (저손실 광케이블, 자유공간(위성) 통신). 거리가 멀어짐에 따른 신호 감쇠를 극복하기 위한 <b>양자 중계기(Quantum Repeater)</b> 필수 |
| <b>후처리 (Post-Processing)</b> | 기저 비교 후 남은 키에서 전송 중 발생한 물리적 오류를 정정하는 <b>오류 정정(Error Correction)</b>과 도청자가 얻었을 최소한의 정보를 상쇄하는 <b>프라이버시 증폭(Privacy Amplification)</b> 기술 |

<b>III. 양자암호통신의 취약점</b>

* <b>광자 분리 공격 (PNS Attack):</b> 완벽한 단일 광자 생성기가 없어 가끔 2개 이상의 광자가 펄스에 섞여 나갈 때, 도청자가 하나를 탈취하여 보관했다가 기저 비교 후 분석하는 공격 (Decoy-state 기법으로 방어).  
* <b>트로이 목마 공격 (Trojan Horse):</b> 도청자가 송신자 장비로 빛을 쏘아보낸 후 반사되어 나오는 빛의 편광 상태를 분석하여 내부 변조기 상태를 알아내는 하드웨어 취약점.  
* <b>중간자 공격 (MITM):</b> 양자 채널의 도청은 막을 수 있으나, 퍼블릭 채널에서의 기저 통신 자체에 대한 상호 인증 체계가 없으면 앨리스와 밥 사이에서 각각 독립적인 QKD를 맺어 위장할 수 있음 (따라서 기존 암호체계를 이용한 사전 인증이 반드시 필요함).

## 7. 식별(Identification)과 인증(Authentication)

<b>I. 개인 식별과 사용자 인증의 정의 및 차이점</b>

| 구분 | 식별 (Identification) | 인증 (Authentication) |
| --- | --- | --- |
| <b>정의</b> | 자신이 누구인지를 시스템에 '주장(Claim)'하는 행위 | 주체(사용자)가 주장하는 신원이 '진짜인지 증명(Prove)'하고 시스템이 검증하는 과정 |
| <b>특징</b> | 고유해야 함, 공개된 정보 가능 (예: ID, 사번, 계좌번호) | 기밀성을 유지해야 함, 타인이 알 수 없는 정보 (예: 비밀번호, 생체정보, 공인인증서) |
| <b>비유</b> | "저는 홍길동입니다." | "내가 홍길동이라는 증거로 이 신분증(비밀번호)을 보여드립니다." |

<b>II. 사용자 인증 시 보안 요구 사항</b>

* <b>기밀성 및 무결성:</b> 인증 정보(예: 패스워드)는 전송 및 저장 과정에서 반드시 암호화(일방향 해시 등)되어 유출 및 변조를 방지해야 함.  
* <b>재전송 공격(Replay Attack) 방지:</b> 공격자가 과거의 정상적인 인증 트래픽을 가로채어 재사용하는 것을 막기 위해 난수(Nonce), 타임스탬프, 일회용 비밀번호(OTP)를 적용.  
* <b>스푸핑(Spoofing) 방지:</b> 타인의 신분으로 위장하는 것을 막기 위한 강력한 다중 요소 인증(MFA) 적용.  
* <b>상호 인증 (Mutual Authentication):</b> 클라이언트만 서버에게 인증받는 것이 아니라, 클라이언트도 자신이 접속한 서버가 피싱 사이트가 아닌 정상 서버임을 인증해야 함 (예: TLS 인증서).

<b>III. 인증 방식에 따른 4가지 유형 및 특징</b>

| 인증 유형 | 개념 (What you...) | 주요 수단 및 특징 |
| --- | --- | --- |
| <b>1. 지식 기반 인증</b> | <b>Know</b> (머릿속에 알고 있는 정보) | <b>비밀번호(Password), PIN, 질의응답 (ID/PW)</b><br>구현이 가장 쉽고 비용이 저렴하나, 망각의 우려가 있고 브루트포스, 사전 대입 공격에 취약함. |
| <b>2. 소유 기반 인증</b> | <b>Have</b> (물리적으로 소유하고 있는 매체) | <b>OTP 토큰, 스마트카드, 휴대전화 SMS 인증, 보안카드</b><br>지식 기반보다 안전하나, 분실 및 도난 시 즉시 타인이 도용할 수 있는 위험(단일 실패점)이 존재함. |
| <b>3. 생체 기반 인증</b> | <b>Are</b> (사용자의 신체적 고유 특징) | <b>지문, 홍채, 정맥, 안면 인식</b><br>위조 및 도난이 매우 어렵고 편리성이 높으나, 시스템 구축 비용이 높고 오탐(FRR) 및 프라이버시 침해(생체정보 유출 시 변경 불가) 이슈가 있음. |
| <b>4. 행위 기반 인증</b> | <b>Do</b> (사용자의 고유한 행동 패턴) | <b>서명(Signature), 키보드 타이핑 패턴, 마우스 움직임 궤적</b><br>사용자 거부감이 적고 지속적인 모니터링(Continuous Auth)에 유리하나, 환경에 따른 변화가 커서 인식률의 정확도 확보가 어려움. |
