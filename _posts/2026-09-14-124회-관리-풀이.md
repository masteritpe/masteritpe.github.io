## 1교시형 문제 풀이

## 1. 가치사슬(Value-chain) 관점에서 ERP, SCM, MES, CRM 비교

기업의 본원적 활동(Primary Activities)과 지원 활동(Support Activities)을 최적화하기 위해 각 정보시스템은 가치사슬의 서로 다른 영역을 담당하며 상호 연계됩니다.

| 시스템 | 가치사슬 상의 역할 | 주요 기능 및 대상 |
| --- | --- | --- |
| <b>SCM</b> (공급망 관리) | 본원적 활동 (Inbound/Outbound Logistics) | 외부 공급업체부터 고객까지의 물류/자재 흐름 최적화 |
| <b>MES</b> (제조실행시스템) | 본원적 활동 (Operations) | 공장 현장의 생산 공정 제어, 실시간 모니터링 및 품질 관리 |
| <b>CRM</b> (고객관계관리) | 본원적 활동 (Marketing & Sales, Service) | 고객 접점 관리, 마케팅, 영업 활동 및 사후 서비스 지원 |
| <b>ERP</b> (전사적 자원관리) | 지원 활동 (Firm Infrastructure, HR, Procurement) | 재무, 인사, 회계 등 전사적 자원을 통합 관리하여 주활동 지원 |

## 2. 통계학의 4가지 척도와 회귀분석 비교

데이터의 성격을 나타내는 4가지 척도에 따라 적용할 수 있는 통계 분석 기법이 달라집니다.

* <b>명목 척도(Nominal):</b> 단순 분류 목적 (예: 성별, 혈액형)  
* <b>서열 척도(Ordinal):</b> 순위나 계급 형태, 간격 불균등 (예: 학점, 만족도 순위)  
* <b>등간 척도(Interval):</b> 측정치 간 간격이 동일하나 절대 영점이 없음 (예: 온도)  
* <b>비율 척도(Ratio):</b> 측정치 간 간격이 동일하고 절대 영점이 존재함 (예: 키, 무게, 소득)

<b>다중회귀분석 vs 로지스틱회귀분석 비교</b>

| 구분 | 다중회귀분석 (Multiple Regression) | 로지스틱회귀분석 (Logistic Regression) |
| --- | --- | --- |
| <b>종속변수 척도</b> | <b>등간/비율 척도</b> (연속형 데이터) | <b>명목/서열 척도</b> (이산형/범주형 데이터) |
| <b>독립변수 척도</b> | 등간/비율 (명목은 더미변수화 가능) | 등간/비율/명목 |
| <b>목적</b> | 여러 독립변수가 종속변수의 <b>수치적 변화</b>에 미치는 영향 예측 | 여러 독립변수를 통해 특정 사건의 <b>발생 확률(분류)</b> 예측 |
| <b>결과값 형태</b> | 선형적인 실수 값 (예: 매출액 예측치) | 0과 1 사이의 확률 값 (예: 합격/불합격) |

## 3. 반응형 웹 디자인(RWD) 3가지 주요 패턴

다양한 디바이스 화면 크기에 맞춰 레이아웃을 유연하게 조정하는 패턴입니다(Luke Wroblewski가 제시한 대표 패턴 기준).

* <b>유동형 그리드 (Mostly Fluid):</b> 중간 크기 화면까지는 그리드 비율을 유지하며 크기만 줄어들다가, 스마트폰 등 작은 화면에 도달하면 각 컬럼이 수직으로 쌓이는(Stack) 패턴입니다.  
* <b>컬럼 드롭 (Column Drop):</b> 화면 폭이 좁아짐에 따라 다단(Multi-column) 레이아웃 중 중요도가 낮은 컬럼부터 아래로 떨어뜨려 수직 배치하는 방식입니다. 전체 요소의 크기 변화보다는 배치를 우선 조정합니다.  
* <b>레이아웃 시프터 (Layout Shifter):</b> 특정 중단점(Breakpoint)에서 단순히 컬럼을 떨어뜨리는 것을 넘어, 레이아웃 구조 자체를 완전히 재설계하여 새로운 형태로 이동시키는 복잡한 패턴입니다.

## 4. 의존성 주입(Dependency Injection)의 장점

객체 내부에서 사용할 의존 객체를 직접 생성하지 않고 외부(컨테이너 등)에서 주입받아 사용하는 디자인 패턴의 핵심 이점입니다.

* <b>결합도 감소 (Decoupling):</b> 객체 간의 강한 결합을 느슨하게(Loose Coupling) 만들어, 한 클래스의 수정이 다른 클래스에 미치는 영향을 최소화합니다.  
* <b>테스트 용이성 (Testability):</b> 실제 객체 대신 Mock 객체(가짜 객체)를 쉽게 주입할 수 있어 단위 테스트(Unit Test)가 매우 수월해집니다.  
* <b>코드 재사용성 및 유연성:</b> 객체 생성 로직이 분리되어 인터페이스 기반으로 다양한 구현체를 쉽게 교체 및 재사용할 수 있습니다.  
* <b>단일 책임 원칙 (SRP) 준수:</b> 비즈니스 로직과 객체 생성/관리 로직이 분리되어 코드가 간결해지고 유지보수성이 향상됩니다.

## 5. 데이터베이스 제5정규형 (5NF)

제5정규형은 조인 종속(Join Dependency, JD)을 해결하기 위한 정규화 단계로, PJ/NF(Projection-Join Normal Form)라고도 불립니다.

* <b>조건 1:</b> 릴레이션이 이미 제4정규형(4NF)을 만족해야 합니다.  
* <b>조건 2:</b> 릴레이션 내에 존재하는 모든 조인 종속이 릴레이션의 <b>후보키(Candidate Key)에 의해서만</b> 만족되어야 합니다.  
* <b>핵심 원리:</b> 어떤 릴레이션을 3개 이상의 릴레이션으로 무손실 분해(Lossless Decomposition)할 수 있고, 이를 다시 자연 조인했을 때 원래의 데이터와 일치한다면, 분해된 상태로 유지하여 데이터 중복 및 갱신 이상을 방지하는 구조입니다.

## 6. 다차원 색인구조(Multidimensional Index Structure) 3가지

공간 데이터(GIS), 멀티미디어 데이터 등 2개 이상의 속성을 동시에 조건으로 가지는 데이터를 빠르게 검색하기 위한 자료구조입니다.

* <b>R-Tree:</b> 데이터를 MBR(Minimum Bounding Rectangle, 최소 외곽 사각형)로 감싸고, 이 MBR들의 포함 관계를 이용해 계층적 트리 구조로 구성하는 방식입니다. (공간 데이터베이스 표준 구조)  
* <b>K-D Tree (K-Dimensional Tree):</b> 각 레벨에서 K개의 차원 중 하나를 선택하여 공간을 이분할(Binary Partitioning)하는 방식을 반복하여 구성하는 트리 구조입니다. 점(Point) 데이터 검색에 효율적입니다.  
* <b>Grid File:</b> 다차원 공간을 격자(Grid) 형태의 다차원 배열로 분할하고, 각 격자 셀에 데이터가 저장된 디스크 버킷의 포인터를 매핑하는 해싱 기반의 구조입니다.

## 7. 거리벡터 라우팅(Distance Vector Routing)

라우터가 목적지까지의 거리(Distance, Hop Count 등)와 <b>방향(Vector)</b> 정보만을 인접 라우터와 주기적으로 교환하여 라우팅 테이블을 갱신하는 동적 라우팅 프로토콜입니다.

* <b>동작 원리:</b> Bellman-Ford 알고리즘을 기반으로 하며, 인접 라우터가 전달해준 경로 정보를 전적으로 신뢰하여 자신의 라우팅 테이블을 업데이트합니다(Routing by Rumor).  
* <b>대표 프로토콜:</b> RIP (최대 Hop 15 제한), IGRP.  
* <b>주요 문제점 및 해결책:</b> 네트워크 토폴로지 변화 시 전체 네트워크에 정보가 퍼지는 데 시간이 걸려 무한 루프(Count-to-Infinity)가 발생할 수 있습니다. 이를 방지하기 위해 Split Horizon, Poison Reverse 등의 기법을 사용합니다.

## 8. 적대적 공격(Adversarial Attack)

인공지능(딥러닝) 모델의 취약점을 노려, 사람의 눈에는 보이지 않지만 모델의 결과를 의도적으로 왜곡시키는 미세한 노이즈(적대적 섭동, Adversarial Perturbation)를 입력 데이터에 추가하는 기법입니다.

* <b>화이트박스 공격 (White-box):</b> 공격자가 AI 모델의 구조, 파라미터, 가중치 등 모든 내부 정보를 알고 있는 상태에서 최적의 노이즈를 생성하는 공격 (예: FGSM, PGD 알고리즘).  
* <b>블랙박스 공격 (Black-box):</b> 모델의 내부 정보 없이, 입력에 대한 출력 결과값(Query)만을 바탕으로 대체 모델을 만들어 공격을 전이(Transferability)시키는 기법.

## 9. NAC(Network Access Control)

네트워크에 접속을 시도하는 모든 단말기(PC, 모바일, IoT 기기)의 보안 상태를 점검하고, 인가된 단말기만 접속을 허용하는 엔드포인트 보안 통제 시스템입니다.

| 주요 기능 | 설명 |
| --- | --- |
| <b>단말 인증 (Authentication)</b> | 802.1x, MAC 주소 기반 등으로 접속하려는 사용자 및 단말기의 식별과 인가 검증 |
| <b>무결성 검사 (Posture Assessment)</b> | 백신 설치/업데이트 여부, OS 패치 상태, 필수 보안 에이전트 실행 여부 검사 |
| <b>네트워크 격리 (Quarantine)</b> | 정책에 위배되거나 취약점이 있는 단말을 사내망과 차단하고 치료망(격리망)으로 이동 |
| <b>지속 모니터링 및 치료</b> | 접속 이후에도 보안 상태를 지속 감시하며, 필수 패치 설치 등을 유도하여 안전한 상태 복귀 시 망 접근 재허용 |


## 2교시형 문제 풀이

## 1. 사용자 요구사항 도출 기법과 유의사항

<b>사용자 요구사항 도출 기법 4가지</b>

* <b>인터뷰(Interview):</b> 이해관계자와 1:1 또는 다대다 대화를 통해 직접적으로 니즈를 파악하는 가장 기본적인 기법. 깊이 있는 정보 획득이 가능합니다.  
* <b>설문조사(Survey/Questionnaire):</b> 다수의 사용자로부터 정형화된 질문을 통해 짧은 시간에 정량적 데이터를 수집하는 기법. 지리적으로 분산된 사용자에게 유용합니다.  
* <b>프로토타이핑(Prototyping):</b> 초기 화면이나 모형을 제공하여 사용자가 직접 시연해 보게 함으로써 숨겨진(Implicit) 요구사항을 시각적으로 구체화하는 기법.  
* <b>관찰(Observation) 및 섀도잉(Shadowing):</b> 사용자의 실제 업무 환경에 들어가 행동을 직접 관찰하여, 인터뷰나 문서로 파악하기 힘든 실질적 제약사항과 병목구간을 도출하는 기법.

<b>요구사항 도출 시 유의사항</b>

* <b>이해관계자 식별 및 참여 유도:</b> 프로젝트에 영향을 미치는 모든 이해관계자를 누락 없이 식별하고, 명확한 권한과 책임을 부여하여 갈등을 방지해야 합니다.  
* <b>비기능적 요구사항(NFR) 명확화:</b> 성능, 보안, 가용성 등 사용자가 명시적으로 요구하지 않더라도 시스템 성공에 필수적인 비기능적 요소를 선제적으로 도출해야 합니다.  
* <b>요구사항 추적성(Traceability) 확보:</b> 도출된 요구사항이 설계-구현-테스트까지 일관되게 적용될 수 있도록 고유 식별자를 부여하고 추적 매트릭스를 구성해야 합니다.

## 2. 디자인 싱킹에서 공감(Empathize)의 중요성

디자인 싱킹은 '사람'에 대한 깊은 이해를 바탕으로 창의적인 문제 해결책을 찾는 방법론이며, 첫 번째 단계인 공감(Empathize)은 전체 프로세스의 성패를 좌우합니다.

* <b>잠재적 니즈(Latent Needs) 발굴:</b> 사용자가 명시적으로 말하지 않거나 스스로도 인지하지 못하는 근본적인 불편함과 문제점을 관찰과 몰입을 통해 찾아낼 수 있습니다.  
* <b>정확한 문제 정의(Define)의 기반:</b> 개발자나 기획자의 편견(Bias)을 배제하고, 철저히 사용자 관점에서 '해결할 가치가 있는 진짜 문제'를 재정의하게 해줍니다.  
* <b>솔루션의 수용성 향상:</b> 기술적 우수성보다 사용자 경험(UX)과 정서적 만족도를 우선시하므로, 최종 산출물이 시장과 사용자에게 거부감 없이 수용될 확률을 극대화합니다.

## 3. DA(Data Architect)와 DBA(Database Administrator) 역할 비교

데이터의 생명주기를 관리하지만, 관점과 주 책임 영역에서 뚜렷한 차이를 가집니다.

| 구분 | DA (Data Architect) | DBA (Database Administrator) |
| --- | --- | --- |
| <b>관점</b> | 비즈니스 및 전사적 아키텍처 관점 (논리적) | 시스템 및 IT 인프라 관점 (물리적) |
| <b>주요 역할</b> | 전사 데이터 표준화, 데이터 모델링(개념/논리), 데이터 거버넌스 수립, 데이터 흐름 설계 | 물리적 DB 설계 및 생성, 쿼리 성능 튜닝, 백업 및 복구, DB 접근 제어 및 보안 구성 |
| <b>핵심 산출물</b> | 데이터 표준 지침서, ERD(논리/개념), 데이터 사전 | DB 생성 스크립트, 성능 분석 보고서, 백업/복구 절차서 |
| <b>필요 역량</b> | 비즈니스 프로세스 이해, 모델링 툴 활용, 커뮤니케이션 | DBMS 아키텍처 지식, SQL 튜닝, OS 및 네트워크 기본 지식 |

## 4. OWASP 인젝션(Injection) 개념과 대응 방안

<b>개념</b>
인젝션은 신뢰할 수 없는 데이터(사용자 입력값)가 프로그램의 명령어 체계나 쿼리의 일부분으로 인터프리터에 전달되어, 공격자가 의도한 악의적인 명령이 실행되게 하는 보안 취약점입니다. (예: SQL Injection, OS Command Injection, LDAP Injection 등)

<b>대응 방안</b>

* <b>Prepared Statement (바인딩 변수) 사용:</b> 쿼리의 논리적 구조를 미리 컴파일하고, 사용자 입력값은 실행 시 단순히 매개변수(Parameter)로만 처리하여 입력값이 명령어로 해석되는 것을 원천 차단합니다.  
* <b>입력값 검증 (White-List 방식):</b> 사용자 입력값에 대해 사전에 정의된 안전한 문자열, 길이, 형식만 허용하도록 서버 측에서 철저히 검증합니다.  
* <b>최소 권한의 원칙 적용:</b> 애플리케이션이 DB나 OS 명령어에 접근할 때, 해당 작업을 수행하는 데 필요한 최소한의 권한(Read, Write 등)만을 가진 계정을 사용합니다.  
* <b>오류 메시지 노출 최소화:</b> DB 오류나 시스템 에러 메시지가 사용자에게 그대로 노출되지 않도록 사용자 정의 에러 페이지로 리다이렉트하여 내부 구조를 숨깁니다.

## 5. 자료구조 Heap의 Max-heap과 Min-heap

힙(Heap)은 완전 이진 트리(Complete Binary Tree)를 기반으로 하여 우선순위 큐를 구현하거나 최댓값/최솟값을 빠르게 찾아내기 위해 고안된 자료구조입니다. 삽입과 삭제의 시간 복잡도는 $O(\log n)$입니다.

| 구분 | Max-heap (최대 힙) | Min-heap (최소 힙) |
| --- | --- | --- |
| <b>정의</b> | 부모 노드의 키 값이 자식 노드의 키 값보다 <b>크거나 같은</b> 완전 이진 트리 | 부모 노드의 키 값이 자식 노드의 키 값보다 <b>작거나 같은</b> 완전 이진 트리 |
| <b>루트(Root) 노드</b> | 트리의 노드 중 <b>최댓값</b>이 항상 위치함 | 트리의 노드 중 <b>최솟값</b>이 항상 위치함 |
| <b>활용 예시</b> | 최대 우선순위 큐, 힙 정렬(오름차순) | 최소 우선순위 큐, 다익스트라(Dijkstra) 최단 경로 탐색 |
| <b>조건식</b> | $Key(Parent) \ge Key(Child)$ | $Key(Parent) \le Key(Child)$ |

## 6. NoSQL 모델링 패턴 3가지 및 모델링 절차

관계형 데이터베이스(RDBMS)의 정규화와 달리, NoSQL은 애플리케이션의 쿼리 특성에 맞춰 데이터를 비정규화하고 접근 성능을 최적화하는 패턴을 사용합니다.

<b>NoSQL 모델링 패턴 3가지</b>

* <b>비정규화 (Denormalization):</b> 쿼리 수행 시 Join 비용을 없애기 위해 여러 테이블에 흩어질 데이터를 하나의 데이터 셋(Document 등) 안에 중복 저장하는 기법.  
* <b>집계 (Aggregation):</b> 유연한 스키마를 활용하여 복잡한 관계의 엔티티들을 하나의 복합 구조체(Nested Object, Array 등)로 묶어 단일 I/O로 처리하는 기법.  
* <b>애플리케이션 조인 (Application Side Join):</b> NoSQL 자체적으로 Join을 지원하지 않으므로, 애플리케이션 코드 단에서 여러 번의 NoSQL 쿼리를 통해 데이터를 가져와 조합하는 패턴.

<b>NoSQL 데이터 모델링 절차</b>

1. <b>도메인 모델 파악:</b> 비즈니스 요구사항을 바탕으로 엔티티와 관계를 파악하여 기본 개념 모델(ERD 등)을 생성.  
2. <b>쿼리 결과(Query Result) 디자인:</b> 애플리케이션에서 도메인 모델을 어떤 형태의 쿼리로 접근하고 결과를 어떻게 화면에 뿌려줄 것인지 중심 쿼리 경로를 도출.  
3. <b>패턴을 이용한 논리적 모델링:</b> 비정규화, 집계 등의 NoSQL 패턴을 적용하여, 읽기(Read)/쓰기(Write) 비율과 I/O 성능을 고려한 데이터 구조(Key-Value, Document 등) 설계.  
4. <b>물리적 모델링 적용:</b> 선택한 특정 NoSQL 솔루션(MongoDB, Cassandra, Redis 등)의 아키텍처 특성과 한계를 반영하여 최종 스키마와 인덱스, 파티셔닝 전략을 확정.

## 7. 교착상태(Dead Lock)와 은행가 알고리즘

<b>교착상태(Dead Lock) 개념</b>
두 개 이상의 프로세스가 서로가 점유하고 있는 자원을 요구하며 무한정 기다리는 상태를 말합니다. 발생을 위해서는 상호배제, 점유대기, 비선점, 환형대기 4가지 조건이 동시에 충족되어야 합니다.

<b>은행가 알고리즘 (Banker's Algorithm)</b>
다익스트라(Dijkstra)가 제안한 교착상태 <b>회피(Avoidance)</b> 기법입니다. 운영체제를 은행에, 프로세스를 고객에 비유하여, 시스템이 프로세스에게 자원을 할당하기 전에 자원 할당 후의 상태가 안전 상태(Safe State)인지 불안전 상태(Unsafe State)인지를 사전에 검사하여 안전한 경우에만 자원을 승인합니다.

<b>은행가 알고리즘의 4가지 주요 자료구조</b>

* <b>Available (가용 자원):</b> 각 자원 유형별로 시스템에 현재 사용 가능한 자원의 수를 나타내는 1차원 배열.  
* <b>Max (최대 요구량):</b> 각 프로세스가 실행을 완료하기 위해 필요로 하는 자원 유형별 최대 개수를 나타내는 2차원 행렬.  
* <b>Allocation (현재 할당량):</b> 현재 각 프로세스에 할당되어 점유 중인 자원 유형별 개수를 나타내는 2차원 행렬.  
* <b>Need (추가 요구량):</b> 각 프로세스가 작업을 완료하기 위해 앞으로 추가로 더 요청할 수 있는 자원의 수를 나타내는 2차원 행렬 (`Need = Max - Allocation`).

## 8. OSI 7 Layer 계층과 특징

네트워크 통신 과정을 7개의 논리적 계층으로 표준화하여, 이기종 기기 간의 상호 호환성을 보장하고 장애 발생 시 원인 파악을 용이하게 합니다.

| 계층 | 명칭 | 핵심 역할 및 특징 | 주요 프로토콜/장비 |
| --- | --- | --- | --- |
| <b>7</b> | 응용 (Application) | 사용자 인터페이스 제공, 네트워크 서비스 애플리케이션 접근 | HTTP, FTP, SMTP, DNS |
| <b>6</b> | 표현 (Presentation) | 데이터의 변환, 압축, 암호화/복호화 (문맥 형성) | JPEG, MPEG, SSL/TLS |
| <b>5</b> | 세션 (Session) | 양 종단간 응용 프로세스의 통신 세션 수립, 유지, 동기화, 종료 | RPC, NetBIOS, SSH |
| <b>4</b> | 전송 (Transport) | 종단 간(End-to-End) 신뢰성 있는 데이터 전송 보장, 오류/흐름 제어 (Segment 단위) | TCP, UDP / L4 스위치 |
| <b>3</b> | 네트워크 (Network) | IP 주소 기반의 최적 경로 선택(Routing) 및 논리적 주소 지정 (Packet 단위) | IP, ICMP, ARP / 라우터, L3 |
| <b>2</b> | 데이터링크 (Data Link) | 물리적 링크를 통한 신뢰성 있는 노드 간 데이터 전송 (MAC 주소, Frame 단위) | Ethernet / 스위치, 브릿지 |
| <b>1</b> | 물리 (Physical) | 디지털 데이터를 전기적, 기계적 신호로 변환하여 매체를 통해 전송 (Bit 단위) | 케이블, 허브, 리피터 |

## 9. IDS와 IPS 개념 비교

네트워크 공격을 탐지하고 방어하는 보안 솔루션으로, 대응 방식과 네트워크 구성상의 위치에서 차이가 있습니다.

| 구분 | IDS (Intrusion Detection System, 침입 탐지) | IPS (Intrusion Prevention System, 침입 방지) |
| --- | --- | --- |
| <b>개념/목적</b> | 네트워크 트래픽을 모니터링하여 인가되지 않은 접근이나 악의적 공격을 <b>탐지하고 경고</b> | 비정상 트래픽 탐지뿐만 아니라, 해당 트래픽을 실시간으로 <b>차단하여 네트워크를 보호</b> |
| <b>네트워크 배치</b> | <b>Out-of-Path (Promiscuous/Mirroring 모드):</b> 실제 트래픽 흐름 밖에서 패킷을 복사받아 분석 (포트 미러링) | <b>In-Line (인라인 모드):</b> 트래픽이 통과하는 물리적 경로 상에 직접 위치 (브릿지 역할) |
| <b>대응 방식</b> | 수동적(Passive) 방어 (탐지, 로그 기록, 관리자 알림) | 능동적(Active) 방어 (패킷 드롭, 세션 차단, 탐지 후 즉각 대응) |
| <b>성능 영향</b> | 트래픽을 복사해서 처리하므로 실제 네트워크 서비스 속도나 가용성에 영향을 주지 않음 | 장비 장애나 병목 발생 시 전체 네트워크 서비스가 중단(Single Point of Failure)될 수 있어 Fail-Open 기술 필수 |

## 10. 인공지능 자연어 처리 임베딩(Embedding) 기술

<b>임베딩(Embedding) 개념</b>
자연어(단어, 문장)를 기계가 이해하고 연산할 수 있도록 다차원 공간의 밀집 벡터(Dense Vector)로 변환하는 기술입니다. 단어 간의 의미적, 구문적 유사도를 벡터 공간 상의 거리로 표현하여(예: '왕' - '남자' + '여자' = '여왕') 자연어 처리 모델의 성능을 극대화합니다.

<b>발전 과정 및 주요 기술</b>

* <b>통계 빈도 기반 (희소 벡터):</b> TF-IDF 등 문서 내 단어의 출현 빈도를 수치화. 차원이 매우 크고 단어의 의미적 유사성을 담지 못하는 한계(희소성)가 있습니다.  
* <b>추론/신경망 기반 워드 임베딩:</b>  
* <b>Word2Vec:</b> 주변 단어를 통해 중심 단어를 예측(CBOW)하거나 중심 단어로 주변 단어를 예측(Skip-Gram)하여 의미를 학습합니다.  
* <b>FastText:</b> Word2Vec의 발전형으로, 단어를 n-gram 기반의 부분 단어(Sub-word)로 쪼개어 학습함으로써 OOV(Out-of-Vocabulary, 사전에 없는 단어) 문제에 강합니다.

* <b>문맥 기반 사전학습 모델 (Contextual Embedding):</b>  
* <b>ELMo, BERT, GPT:</b> 기존 임베딩은 '배(Boat)'와 '배(Pear)'를 같은 벡터로 처리하는 동음이의어의 한계가 있었습니다. 이를 극복하여 문장 전체의 문맥(Context)을 양방향(또는 단방향)으로 파악한 후 동적으로 벡터 값을 부여하는 현대 LLM의 핵심 기반 기술입니다.
