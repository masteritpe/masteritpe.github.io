# 정보관리기술사 140회 예상문제 40선 - 풀이

### 1. 다크 팩토리 (Dark Factory)

**1. 개요**

**가. 정의**  
다크 팩토리(Dark Factory)는 조명, 냉난방, 통로 등 인간 작업자를 위한 편의 설비를 배제하고, 산업용 로봇·AI·IoT·디지털트윈이 결합되어 생산계획부터 품질검사, 물류까지 전 공정을 무인·완전자율로 운영하는 차세대 스마트팩토리 형태이다. 조명이 없어도 공정이 가능하다는 의미에서 "어둠 속 공장"이라 명명되었으며, Lights-out Manufacturing으로도 불린다.

**나. 등장배경**  
① 저출산·고령화에 따른 생산인력 부족 심화, ② 인건비 상승 및 근로시간 단축에 따른 원가경쟁력 저하, ③ 5G·AI·디지털트윈·산업용 IoT 등 4차산업혁명 기술의 성숙, ④ 글로벌 공급망 불안정에 따른 리쇼어링(Reshoring) 및 소품종 대량생산에서 다품종 소량생산으로의 패러다임 전환이 배경이다.

**다. 필요성/목적**  
생산성 극대화, 24시간 무중단 운영, 인적오류(Human Error) 제거, 유해·위험공정에서의 안전성 확보, 에너지·공간 최적화를 목적으로 한다.

**2. 특징 및 구성도**

```
[센서/IoT] → [엣지컴퓨팅] → [AI 판단/추론] → [로봇/AGV 제어] → [디지털트윈 시뮬레이션]
     ↑                                                                    │
     └────────────────── 실시간 피드백(자율 재조정) ──────────────────────┘
```

| 구분 | 특징 |
|---|---|
| 무인성 | 조명·공조 등 인간편의설비 불필요, 완전 자율운영 |
| 자율성 | AI 기반 이상감지·자율의사결정, 인간 개입 최소화 |
| 연결성 | 5G/OT-IT 융합, 전 설비 실시간 데이터 연동 |
| 유연성 | 디지털트윈 기반 공정 시뮬레이션 후 즉시 실환경 반영 |

**3. 상세 설명**

**(1) 핵심 아키텍처**  
센서(Vision/Force/온습도)→엣지 게이트웨이(실시간 전처리)→클라우드/AI서버(학습·추론)→MES/APS(생산계획 최적화)→로봇제어기(협동로봇, AGV/AMR) 순으로 데이터가 흐르며, 디지털트윈이 실제 설비와 1:1 매핑되어 사전 시뮬레이션 후 실행함으로써 무인 상태에서도 이상상황 대응이 가능하다.

**(2) 동작 프로세스**  
① 수요예측 기반 생산계획 자동수립 → ② 자재 자동입고·AGV 이송 → ③ 로봇 가공·조립 → ④ 머신비전 기반 자율 품질검사(AVI) → ⑤ 이상 발생시 디지털트윈 시뮬레이션 후 자율 복구 → ⑥ 자동 포장·출고의 폐루프(Closed-loop) 구조로 동작한다.

**(3) 적용기술 및 표준**  
산업용 로봇(Cobot), AGV/AMR, 5G URLLC, 디지털트윈(ISO 23247), OPC-UA, TSN(Time Sensitive Networking), AI 비전검사, RPA, Predictive Maintenance(예지보전) 등이 융합 적용되며, IEC 62443 기반 OT 보안이 필수 결합된다.

**(4) 기존 스마트팩토리와의 비교**  
기존 스마트팩토리는 사람+자동화 협업(Human-in-the-loop) 구조로 관리자 상시 상주가 필요하나, 다크팩토리는 완전 무인 자율운영으로 인간 개입이 예외상황에만 국한되는 Human-out-of-the-loop 구조라는 점에서 차별화된다.

**4. 활용분야/사례**

전자부품(스마트폰 부품) 조립라인, 반도체 후공정, 자동차 부품 정밀가공, 물류센터(무인창고), 식품 자동화라인 등에 적용되고 있으며, 중국 샤오미, 일본 화낙(FANUC)의 로봇이 로봇을 만드는 무인공장, 국내 일부 반도체·2차전지 공장의 완전자동 라인이 대표적 사례이다.

**5. 기대효과 및 고려사항/전망**

**기대효과**: 생산성 30~50% 향상, 불량률 감소, 24시간 무중단 가동, 안전사고 제로화, 에너지 비용 절감.  
**고려사항**: 초기 투자비 과다, 사이버보안(OT망 침투) 위협 증가, 급격한 고장시 완전복구 어려움, 일자리 대체에 따른 사회적 갈등, 유지보수 전문인력 부재 문제.  
**전망**: 생성형 AI 결합을 통한 자율판단 고도화, 디지털트윈 정밀도 향상, 인간-로봇 협업의 하이브리드 모델과 완전 무인 모델이 산업특성별로 공존하는 형태로 발전할 것으로 전망된다.

### 2. 소버린(Sovereign) AI

**1. 개요**  
- 정의: 특정 국가·조직이 자국의 데이터, 인프라, 인력을 기반으로 자체 개발·운영하여 AI 기술에 대한 독립적 주권을 확보하는 전략 및 AI 시스템  
- 배경: 글로벌 빅테크 AI 종속 심화, 데이터 주권·안보·문화적 정체성 보호 필요성, 각국의 AI 자립 정책(반도체·에너지 포함) 추진에 따라 부상

**2. 핵심 구성요소**

| 구성요소 | 내용 |
|---|---|
| 자국어/문화 특화 LLM | 자국어 코퍼스 기반 파운데이션모델 구축 |
| 자체 컴퓨팅 인프라 | 국가 GPU팜, 자국 데이터센터 운영 |
| 데이터 거주성(Data Residency) | 국내 법제(개인정보보호법 등) 준수 데이터 보관 |
| 규제·거버넌스 체계 | AI 안전성·윤리 자체 규율 |

**3. 추진 방식**  
- 자체 파운데이션 모델 개발(Full Sovereign) 또는 오픈소스 모델 파인튜닝·현지화(Hybrid Sovereign) 방식으로 구분  
- 국가 차원 GPU 인프라 확보(AI 반도체 자립) 및 산·학·연 협력 기반 데이터 생태계 구축  
- 예: 국가별 초거대AI 프로젝트, 공공부문 On-premise/Private Cloud AI 전환

**4. 기대효과 및 고려사항**  
- 효과: 국가 안보·데이터주권 확보, 자국어 서비스 품질 향상, AI 산업 생태계 자립 및 경제효과 창출  
- 고려사항: 글로벌 모델 대비 성능·비용 격차, 막대한 컴퓨팅 투자비, 국제 협력과 폐쇄적 자립 간 균형전략 필요

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 3. 기밀 컴퓨팅(Confidential Computing, CC)

**1. 개요**

**가. 정의**  
기밀 컴퓨팅(Confidential Computing)은 TEE(Trusted Execution Environment, 신뢰실행환경) 기반 하드웨어 격리 기술을 활용하여, 데이터가 저장(At Rest)·전송(In Transit) 상태뿐 아니라 처리 중(In Use) 상태에서도 메모리 상에서 암호화된 채 연산이 수행되도록 보호하는 보안 컴퓨팅 기술이다.

**나. 등장배경**  
클라우드 이용 확산에 따라 데이터가 제3자(클라우드사업자) 인프라에서 처리되는 구조상, 관리자 권한을 가진 클라우드 사업자·하이퍼바이저·OS조차 데이터를 열람할 수 없도록 하는 "Zero Trust to Infrastructure" 요구가 증가하였고, Meltdown/Spectre 등 하드웨어 취약점, 개인정보보호법 강화, 멀티테넌트 클라우드 환경의 데이터 유출 우려가 배경이 되었다.

**다. 필요성/목적**  
클라우드 이전(Cloud Migration) 시 데이터 주권 확보, 민감정보(금융·의료·개인정보) 처리의 신뢰성 확보, 멀티파티 데이터 협업(연합학습) 시 데이터 비공개 연산 지원을 목적으로 한다.

**2. 특징 및 구성도**

```
[일반 컴퓨팅]                    [기밀 컴퓨팅]
 App 실행중 메모리 평문 노출  →   Enclave(TEE) 내부 암호화 실행
 OS/Hypervisor 관리자 열람 가능 →  OS/Hypervisor도 내부 열람 불가
                                  ↓
                        [원격 검증(Remote Attestation)]
                        신뢰 여부를 외부에서 암호학적으로 증명
```

| 구성요소 | 설명 |
|---|---|
| TEE(Enclave) | CPU 내 격리된 보안 실행영역 (Intel SGX/TDX, AMD SEV, ARM TrustZone/CCA) |
| 메모리 암호화 | Enclave 내 데이터/코드는 하드웨어 키로 자동 암복호화 |
| Remote Attestation | Enclave의 무결성·신뢰성을 원격에서 암호학적으로 검증 |
| Sealing | Enclave 종료 후에도 데이터 재봉인·보호 |

**3. 상세 설명**

**(1) 핵심 원리(아키텍처)**  
CPU 내부에 물리적으로 격리된 Enclave를 생성하고, 해당 영역에 로드된 코드와 데이터는 하드웨어 수준의 메모리 암호화 엔진(MEE)을 통해 암호화 상태로 유지된다. 루트권한을 가진 OS·하이퍼바이저·타 프로세스도 Enclave 내부 메모리를 직접 열람할 수 없으며, CPU만이 복호화 키를 보유한다.

**(2) 동작 절차**  
① Enclave 생성 및 코드 로드 → ② 원격 검증기관에 Attestation 요청(Quote 생성) → ③ 검증기관이 서명·측정값(Measurement) 확인 후 신뢰 승인 → ④ 승인 후 암호화된 채널로 민감데이터 전달 → ⑤ Enclave 내부에서 암호화 상태로 연산 수행 → ⑥ 결과만 암호화하여 반환, Enclave 종료시 데이터 자동 소멸.

**(3) 적용기술 및 표준**  
Intel SGX/TDX, AMD SEV-SNP, ARM CCA/TrustZone, AWS Nitro Enclaves, Azure Confidential VM, Google Confidential Computing이 대표 구현체이며, Confidential Computing Consortium(CCC, Linux Foundation 산하)이 표준화를 주도한다.

**(4) 기존 암호화 기술과의 비교**  
기존 암호화는 저장/전송 구간만 보호하고 처리 시점에는 반드시 평문 복호화가 필요했으나, 기밀컴퓨팅은 동형암호(Homomorphic Encryption)처럼 연산 오버헤드가 크지 않으면서도 처리중 데이터까지 하드웨어 수준에서 보호하여 성능과 보안의 균형을 확보한다는 차이가 있다.

**4. 활용분야/사례**

금융권 다자간 신용평가 연합학습, 의료기관간 임상데이터 비공개 공동분석, 정부기관 민감데이터 클라우드 이전, 블록체인 프라이버시 트랜잭션(오라클 데이터 보호), 멀티클라우드 환경의 키관리시스템(KMS) 보호 등에 활용되고 있다.

**5. 기대효과 및 고려사항/전망**

**기대효과**: 클라우드 신뢰성 확보로 민감데이터 클라우드 전환 가속화, 내부자 위협 및 관리자 권한 오남용 방지, 데이터 협업 활성화.  
**고려사항**: TEE 자체의 사이드채널 공격 취약점(캐시 타이밍 공격 등), Enclave 메모리 용량 제약에 따른 성능저하, 벤더별 구현 상이로 인한 이식성 부족, 검증기관 신뢰성 문제.  
**전망**: 동형암호·연합학습과의 결합을 통한 Privacy-Enhancing Technology(PET) 통합 플랫폼으로 발전, 클라우드 네이티브 기본 보안요소로 표준화될 전망이다.

### 4. 디지털 포용법

**1. 개요**  
디지털 포용법은 디지털 전환 과정에서 발생하는 정보격차·디지털 소외 문제를 해소하기 위해 고령자, 장애인, 저소득층 등 디지털 취약계층의 디지털 접근성·역량·활용 기회를 보장하는 법적 근거를 마련한 법률임. 키오스크·모바일 뱅킹 등 비대면 서비스 확산에 따른 소외 심화가 입법 배경임.

**2. 주요 구성 요소**

| 구분 | 내용 |
|---|---|
| 디지털포용위원회 | 정책 심의·조정 기구(국무총리 소속) |
| 실태조사 | 디지털정보격차 실태조사 정기 실시 |
| 디지털배움터 | 취약계층 대상 디지털 역량 교육 |
| 접근성 기준 | 키오스크, 앱·웹 접근성 의무화 |
| 지원기관 지정 | 디지털포용센터, 전담기관 지정 |

**3. 상세 설명**  
법 적용 대상은 고령자, 장애인, 농어민, 저소득층, 북한이탈주민 등이며, 정부·지자체·공공기관에 디지털포용 시행계획 수립 의무를 부과함. 키오스크 등 무인정보단말기는 접근성 준수 설계(음성안내, 휠체어 접근 높이 등)를 의무화하고, 민간 사업자 대상 인증·지원 제도를 병행함. 기존 「지능정보화 기본법」상 정보격차해소 조항을 확대·독립 법제화한 성격을 가짐.

**4. 기대효과 및 고려사항**  
디지털 소외계층의 사회·경제적 활동 참여 기회 확대, 비대면 서비스 이용률 제고가 기대됨. 다만 실효성 확보를 위해 예산·인력 확충, 민간 서비스 접근성 강제력 강화, 지역 간 인프라 격차 해소 방안이 병행 검토되어야 함.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 5. CMMI v3.0(Capability Maturity Model Integration 3.0)

**1. 개요**

**가. 정의**  
CMMI v3.0은 ISACA(舊 CMMI Institute)가 2023년 발표한 프로세스 개선 성숙도 모델의 최신 버전으로, 기존 프로세스 준수 여부 중심 심사에서 벗어나 조직의 실제 성과(Performance) 및 사업목표 달성 여부를 중심으로 프로세스 역량을 평가하는 성과중심(Performance-based) 모델로 전환되었다.

**나. 등장배경**  
기존 CMMI(1.3, 2.0)가 프로세스 문서화·절차준수 여부에 치중하여 "인증을 위한 인증"이라는 형식주의 비판을 받았고, Agile·DevOps·클라우드 등 신기술 개발방식과의 정합성 부족, 성숙도 등급 취득 후 실질적 성과 개선이 미흡하다는 지적이 지속되어, 실질적 비즈니스 가치 창출을 검증하는 방향으로 개정되었다.

**다. 목적**  
프로세스 성숙도와 조직의 실제 성과지표(품질, 일정, 원가, 고객만족)를 연계하여 지속적 성과개선을 견인하고, Agile/Safety/Data Management 등 다양한 개발환경에 유연하게 적용 가능한 통합모델을 제공하는 것을 목적으로 한다.

**2. 특징 및 구성도**

```
Level 1(초기) → Level 2(관리) → Level 3(정의) → Level 4(정량관리) → Level 5(최적화)
     └────────────── 성과지표(Performance Data) 연계 심사 ──────────────┘
```

| 구성 | v2.0 이전 | v3.0 변경 |
|---|---|---|
| 심사 초점 | 프로세스 준수(Compliance) | 사업성과(Business Performance) 연계 |
| 모델 구조 | Practice Area 중심 고정 | Category-Capability Area-Practice Area 유연 구조 |
| 적용범위 | 개발/서비스/공급자관리 개별 | 통합모델+Agile/Safety/데이터 뷰 확장 |
| 인증유지 | 정기 재심사만 | Sustainment 평가로 등급 유지 간소화 |

**3. 상세 설명**

**(1) 모델 구조(아키텍처)**  
CMMI v3.0은 4개 Category(도어웨이-Doing, 관리-Managing, 실행-Enabling, 개선-Improving)와 그 하위 Capability Area, Practice Area로 재구성되며, 조직 특성에 맞게 필요한 Practice Area만 선택 적용하는 모듈형 구조를 채택하였다.

**(2) 심사(Appraisal) 프로세스**  
① 사업목표 및 성과지표(KPI) 정의 → ② 프로세스 실행 증거 및 성과데이터 수집 → ③ 고성숙도 심사원(Lead Appraiser)의 성과연계 검증 → ④ ML(Maturity Level)/CL(Capability Level) 등급 부여 → ⑤ 인증 후 Sustainment Appraisal을 통한 등급 유지 절차로 진행된다.

**(3) 적용 확장영역**  
기존 CMMI-DEV, SVC, SPM을 통합한 단일모델에 더해 Agile 개발방식 대응 뷰, Safety(기능안전) 뷰, Data Management(데이터 관리) 뷰, Virtual/원격근무 환경 뷰가 신설되어 다양한 산업·개발방식에 적용 가능하도록 확장되었다.

**(4) 기존 CMMI 2.0과의 비교**  
CMMI 2.0은 프로세스영역별 실행여부 확인에 집중했으나, v3.0은 동일 프로세스 활동이라도 실제 성과(품질개선율, 결함감소율, 고객만족도)와의 인과관계를 심사기준에 명시적으로 포함시켰으며, 심사 부담 완화를 위한 Sustainment 절차를 신설한 점이 핵심 차별점이다.

**4. 활용분야/사례**

방위산업·항공우주 등 대규모 시스템 개발조직의 공급업체 선정기준, 국방 SW 획득사업의 CMMI 등급 요구, 금융권 IT 아웃소싱 업체 평가, 글로벌 SI/ITO 기업의 프로세스 역량 대외 입증 수단으로 활용된다.

**5. 기대효과 및 고려사항/전망**

**기대효과**: 실질적 성과개선 견인, 형식적 인증 취득 관행 개선, Agile 조직의 CMMI 적용 장벽 완화, 인증유지 비용·시간 절감.  
**고려사항**: 성과데이터 수집·분석 역량이 부족한 중소조직의 적용부담 증가, 심사원의 성과연계 판단 주관성 문제, 국내 심사원 풀 부족.  
**전망**: DevOps/AI 개발 파이프라인과의 통합 심사모델로 진화하고, 데이터 기반 실시간 성과 모니터링과 결합한 지속적 인증(Continuous Certification) 형태로 발전할 전망이다.

### 6. 지오패트리에이션(Geopatriation)

**1. 개요**  
지오패트리에이션은 해외 클라우드·데이터센터에 위치한 자국 데이터 및 IT 워크로드를 데이터 주권(Data Sovereignty) 확보를 위해 자국 영토 내로 회수·재배치하는 전략을 의미함. 글로벌 클라우드 종속 심화, 개인정보보호법·GDPR 등 데이터 지역화(Data Localization) 규제 강화가 등장 배경임.

**2. 주요 유형**

| 유형 | 내용 |
|---|---|
| 물리적 재배치 | 데이터센터 자국 이전 |
| 논리적 격리 | 자국 리전 내 저장·처리 강제 |
| 하이브리드 전략 | 민감 데이터만 국내 보관, 나머지 해외 유지 |
| 주권형 클라우드 | 자국법 적용 독립 클라우드 구축 |

**3. 상세 설명**  
공공·금융 등 민감 데이터를 보유한 기관은 해외 사업자의 법적 관할권(예: 미국 클라우드법)에 자국 데이터가 노출되는 위험을 회피하기 위해 자국 내 리전·주권형 클라우드로 이전함. 이는 데이터 현지화(Localization)에서 한 단계 나아가 기존 해외 배치 데이터를 실제 국내로 "귀환"시키는 능동적 조치라는 점에서 구분됨. EU의 Gaia-X, 국내 공공기관 클라우드 보안인증(CSAP) 정책이 유사한 맥락임.

**4. 기대효과 및 고려사항**  
데이터 주권 확보, 법적 리스크 완화, 국내 클라우드 산업 활성화 효과가 기대됨. 다만 이전 비용, 글로벌 서비스 성능 저하, 국내 인프라 확충 필요성 등이 고려되어야 하며, 국제 규제와의 상충 여부 검토가 필요함.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 7. AI-RAN(Artificial Intelligence in Radio Access Network)

**1. 개요**  
AI-RAN은 무선접속망(RAN)에 인공지능 기술을 결합하여 네트워크 자원을 지능적으로 운용하고, 나아가 RAN 인프라 자체를 AI 연산 플랫폼으로 활용하는 개념임. 5G/6G 트래픽 증가와 기지국 전력·운영 효율 문제, AI 추론 수요 급증이 등장 배경이며, Nvidia·SoftBank·T-Mobile 등이 참여하는 AI-RAN Alliance가 표준화를 주도함.

**2. 주요 유형**

| 유형 | 내용 |
|---|---|
| AI-for-RAN | AI로 RAN 성능 최적화(빔포밍, 스케줄링) |
| AI-and-RAN | 기지국 유휴 자원에 AI 워크로드 동시 처리 |
| AI-on-RAN | RAN 하드웨어(GPU 기반) 위에서 AI 서비스 제공 |

**3. 상세 설명**  
기존 RAN은 통신 전용 ASIC 기반이었으나, AI-RAN은 GPU·가속기 기반 범용 서버로 RAN 기능(vRAN)을 소프트웨어화하고, 트래픽이 적은 시간대 유휴 컴퓨팅 자원을 엣지 AI 추론(RAG, 실시간 비전 분석 등)에 활용함. 이를 통해 네트워크 슬라이싱, 실시간 채널 예측, 에너지 절감형 기지국 제어 등이 가능해짐.

**4. 기대효과 및 고려사항**  
기지국 자원 활용률 제고, 엣지 AI 서비스 신규 수익 창출, 네트워크 운영비 절감이 기대됨. 다만 통신 QoS와 AI 워크로드 간 자원 경쟁 관리, 실시간성 보장, 표준 인터페이스 정립이 향후 과제임.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 8. ISO/IEC 25010:2023

**1. 개요**  
ISO/IEC 25010은 소프트웨어 및 시스템 품질 요구사항·평가(SQuaRE) 시리즈의 품질모델 표준으로, 2023년 개정판은 기존 2011년판의 품질특성을 재구조화하고 안전성(Safety)을 신규 특성으로 추가하여 AI·자율시스템 등 최신 소프트웨어 환경을 반영함.

**2. 품질모델 구성**

| 모델 | 품질특성(주요) |
|---|---|
| Product Quality Model | 기능적합성, 성능효율성, 호환성, 상호작용역량, 신뢰성, 보안성, 유지보수성, 이식성, 안전성(신규) |
| Quality in Use Model | 효과성, 효율성, 만족도, 위험회피성, 활용범위 |

**3. 상세 설명**  
기존 "사용성(Usability)"을 "상호작용역량(Interaction Capability)"으로 명칭·범위를 확장하여 사용자·시스템 간 상호작용 전반(접근성, 사용자 오류 방지 등)을 포괄함. 신설된 안전성은 인명·재산·환경에 대한 위해 방지 능력을 평가 항목으로 명시하여 자율주행·의료기기 등 고위험 SW에 대응함. 각 특성은 하위 부특성으로 세분화되며 정량적 측정지표(25023 등)와 연계되어 평가됨.

**4. 기대효과 및 고려사항**  
품질 요구사항 명세·평가의 국제 정합성 확보, 안전 필수 시스템 품질보증 체계 강화가 기대됨. 국내 SW 품질인증(GS인증 등) 및 발주 시 품질기준 개정 반영이 필요하며, 조직은 기존 품질모델 매핑·전환 작업이 요구됨.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 9. 마이데이터 2.0

**1. 개요**  
마이데이터 2.0은 개인이 자신의 정보를 능동적으로 관리·활용하도록 지원하는 마이데이터 제도의 고도화 버전으로, 기존 금융분야 중심 서비스의 한계를 극복하고 全산업 데이터 전송요구권 확대를 통해 개인정보 자기결정권을 강화한 정책 체계임.

**2. 주요 특징**

| 구분 | 1.0 | 2.0 |
|---|---|---|
| 적용범위 | 금융권 중심 | 통신·공공·의료 등 전산업 확대 |

**3. 상세 설명**

### 10. OWASP Top 10 : 2025

**1. 개요**

**가. 정의**  
OWASP Top 10:2025는 개방형 웹 애플리케이션 보안 프로젝트(OWASP)가 발표하는 웹 애플리케이션 최대 위협 취약점 10선의 최신 개정판으로, 실제 침해사례·CVE 통계·업계 설문을 기반으로 4년 만에(2021년판 이후) 개정되어 공급망 보안 및 예외처리 오류 항목이 신설되었다.

**나. 등장배경**  
SolarWinds, Log4Shell 등 오픈소스·서드파티 라이브러리를 이용한 공급망 공격 급증, 클라우드 네이티브·마이크로서비스 확산에 따른 새로운 공격표면 등장, 기존 "Vulnerable and Outdated Components" 항목으로는 공급망 전체 위협을 포괄하지 못한다는 문제의식이 배경이다.

**다. 목적**  
개발자·보안담당자에게 최신 위협 우선순위를 제시하여 시큐어코딩·보안설계·보안테스트 활동의 가이드라인으로 활용하고, SDLC 전 단계에 보안을 내재화(Shift Left)하는 것을 목적으로 한다.

**2. 특징 및 구성표**

| 순위 | 항목 | 2021 대비 변화 |
|---|---|---|
| A01 | Broken Access Control | 1위 유지 |
| A02 | Security Misconfiguration | 순위 상승 |
| A03 | Software Supply Chain Failures | 신설(구성요소 취약점 확대개편) |
| A04 | Cryptographic Failures | 순위 조정 |
| A05 | Injection | 순위 하락(자동화 방어 개선) |
| A06 | Insecure Design | 유지 |
| A07 | Authentication Failures | 명칭 조정 |
| A08 | Software or Data Integrity Failures | 유지 |
| A09 | Logging & Alerting Failures | 명칭 확대(Alerting 추가) |
| A10 | Mishandling of Exceptional Conditions | 신설 |

**3. 상세 설명**

**(1) 핵심 변화 - 공급망 실패(A03)**  
오픈소스 라이브러리, CI/CD 파이프라인, 서드파티 API, 컨테이너 이미지 등 SW 공급망 전 구간의 무결성 훼손을 포괄하는 항목으로 확대 개편되었다. SBOM(Software Bill of Materials) 미관리, 검증되지 않은 업데이트 자동적용, 오픈소스 라이선스·유지보수 중단 컴포넌트 사용 등이 세부 위협으로 포함된다.

**(2) 신설 항목 - 예외처리 오류(A10)**  
예외(Exception) 발생시 부적절한 오류처리로 인한 정보노출, 서비스 중단, 인증 우회, 무결성 훼손 등을 포괄한다. 예를 들어 상세 스택트레이스 노출, 오류시 기본값(Fail-open) 처리로 인한 인가 우회 등이 대표 사례이다.

**(3) 대응 방안**  
공급망 대응 - SBOM 작성·자동관리, 서명된 아티팩트만 배포, 취약점 스캐너(SCA) CI/CD 통합. 예외처리 대응 - Fail-secure 원칙 적용, 표준화된 오류응답, 상세오류정보 로깅 후 사용자에게는 일반화된 메시지만 제공.

**(4) 2021년판과의 비교**  
2021년판은 "Vulnerable and Outdated Components"로 컴포넌트 자체 취약점에 국한되었으나 2025년판은 공급망 전체(빌드·배포·유지보수 프로세스)로 위협범위를 확장하였고, 로깅 항목도 탐지(Logging) 중심에서 실시간 경보(Alerting)까지 포함하여 사고대응 체계와의 연계를 강화하였다.

**4. 활용분야/사례**

시큐어코딩 가이드 제정 기준, SW개발보안 진단(정보시스템 구축·운영 지침) 점검항목 매핑, DevSecOps 파이프라인의 SAST/DAST/SCA 룰셋 기준, ISMS-P·정보보호 사전점검 항목 기준으로 국내외 광범위하게 활용된다.

**5. 기대효과 및 고려사항/전망**

**기대효과**: 최신 위협 트렌드 반영을 통한 실효적 취약점 관리, 개발단계 보안내재화 촉진, 공급망 리스크에 대한 조직적 인식 제고.  
**고려사항**: RC(Release Candidate) 단계로 최종본 확정 전 변동 가능성, 중소기업의 SBOM 관리체계 구축 부담, 예외처리 오류의 자동탐지 도구 미성숙.  
**전망**: AI 기반 코드생성 확산에 따른 "AI 생성코드 취약점" 관련 항목 추가 논의, SBOM·VEX 기반 공급망 보안 자동화 표준과의 결합이 가속화될 전망이다.

### 11. LLMOps(Large Language Model Operations)

**1. 개요**

**가. 정의**  
LLMOps는 대규모 언어모델(LLM)의 데이터 준비, 파인튜닝/프롬프트엔지니어링, 배포, 모니터링, 재학습에 이르는 전 생명주기를 체계적으로 관리하는 방법론 및 플랫폼 체계로, 기존 MLOps에 LLM 고유 특성(프롬프트 관리, 토큰 비용, 환각 등)을 반영하여 확장된 개념이다.

**나. 등장배경**  
GPT 계열 등 파운데이션 모델의 폭발적 확산에 따라 기업의 LLM 도입이 급증하였으나, 기존 MLOps 체계로는 프롬프트 버전관리, RAG 파이프라인, 벡터DB 운영, 환각(Hallucination) 관리, 막대한 추론비용 관리가 불가능하여 별도 운영체계의 필요성이 대두되었다.

**다. 목적**  
LLM 기반 서비스의 안정적 운영, 품질(정확성·안전성) 보증, 비용 최적화, 규제 대응(AI 거버넌스)을 목적으로 한다.

**2. 특징 및 구성도**

```
[데이터/프롬프트 관리] → [파인튜닝/RAG구성] → [평가(Eval)] → [배포(Serving)] → [모니터링/피드백]
        ↑                                                                      │
        └──────────────────── 지속적 개선(Continuous Improvement) ─────────────┘
```

| 구성요소 | 설명 |
|---|---|
| Prompt Registry | 프롬프트 버전관리·A/B테스트 |
| Vector DB/RAG Pipeline | 임베딩·검색증강생성 관리 |
| Evaluation Framework | 정확성·독성·환각률 자동평가 |
| Model Gateway | 다중 LLM 라우팅, 비용/토큰 관리 |
| Observability | 응답품질·지연시간·비용 모니터링 |

**3. 상세 설명**

**(1) 핵심 아키텍처**  
사용자 요청→프롬프트 템플릿 조합→RAG(검색증강)로 컨텍스트 보강→LLM Gateway를 통한 모델 라우팅(비용/성능 기준)→응답 생성→가드레일(Guardrail) 필터링→모니터링 시스템으로 로그·피드백 수집의 파이프라인 구조를 가진다.

**(2) 운영 프로세스**  
① 요구사항 정의 및 프롬프트/RAG 설계 → ② 오프라인 평가(Benchmark, Golden Set) → ③ 스테이징 배포 및 A/B테스트 → ④ 프로덕션 배포(Canary/Shadow) → ⑤ 실시간 모니터링(환각률, 응답지연, 비용) → ⑤ 피드백 기반 프롬프트/모델 재조정의 반복 루프로 운영된다.

**(3) 적용기술**  
LangChain/LangSmith, LlamaIndex, MLflow, Weights & Biases, 벡터DB(Pinecone, Milvus, Weaviate), Guardrails AI, Kubernetes 기반 모델서빙(vLLM, TGI), 프롬프트 캐싱, RAG 평가지표(RAGAS) 등이 활용된다.

**(4) 기존 MLOps와의 비교**  
MLOps는 정형데이터 기반 모델의 학습-배포-모니터링에 초점을 두어 정확도·재현율 등 정량지표 중심이었으나, LLMOps는 비정형 텍스트 출력의 품질(사실성, 유해성, 일관성)을 정성·정량 혼합평가해야 하고, 프롬프트 자체가 핵심 관리자산이 되며, 토큰단위 비용관리가 추가된다는 점에서 차별화된다.

**4. 활용분야/사례**

기업 내부 지식검색 챗봇(RAG 기반), 고객상담 자동화, 코드생성 어시스턴트 운영, 문서 자동요약/생성 서비스, 금융권 규제준수 문서 검토 자동화 등에 적용되며, 국내외 기업들이 사내 LLM Gateway를 구축하여 다중 모델(GPT, Claude, 자체 파인튜닝 모델)을 통합 운영하는 사례가 확산되고 있다.

**5. 기대효과 및 고려사항/전망**

**기대효과**: LLM 서비스 품질 표준화, 운영비용 가시화 및 최적화, 안전성·규제대응력 강화, 신속한 모델 교체·업그레이드 대응력 확보.  
**고려사항**: 환각현상의 완전제거 불가, 평가지표의 주관성, 벡터DB·GPU 인프라 운영비용 부담, 개인정보·저작권 등 데이터 거버넌스 이슈.  
**전망**: 에이전틱(Agentic) AI 확산에 따라 멀티에이전트 오케스트레이션 관리, 온디바이스 LLM 운영, AI 거버넌스 규제(EU AI Act 등) 대응 기능이 LLMOps의 핵심영역으로 확장될 전망이다.

### 12. 벡터 데이터베이스(Vector Database)

**1. 개요**  
벡터 데이터베이스는 텍스트·이미지 등 비정형데이터를 임베딩(Embedding) 기법으로 고차원 벡터화하여 저장하고, 벡터 간 유사도 기반 검색을 지원하는 데이터베이스로, 최근 LLM·RAG 확산에 따라 핵심 인프라로 부상함.

**2. 주요 특징**

| 구분 | 내용 |
|---|---|
| 저장대상 | 임베딩 벡터(수백~수천 차원) |
| 검색방식 | ANN(근사 최근접 탐색), 코사인/유클리드 유사도 |
| 핵심 인덱스 | HNSW, IVF, LSH, PQ |
| 대표 제품 | Pinecone, Milvus, Weaviate, pgvector, Chroma |

**3. 상세 설명**  
(1)임베딩모델(예: 문장 임베딩)로 데이터를 벡터로 변환, (2)ANN 인덱스로 대규모 벡터 중 유사벡터를 고속 검색(정확도-속도 트레이드오프), (3)RAG 아키텍처에서 사용자 질의 임베딩과 문서벡터 유사도 검색을 통해 LLM 프롬프트에 관련 컨텍스트를 주입하여 환각 완화 및 최신정보 반영 가능.

**4. 기대효과 및 고려사항**  
시맨틱 검색·추천·이상탐지 등 활용범위 확대, LLM 답변 신뢰도 향상이 기대됨. 다만 대규모 벡터 저장에 따른 메모리·비용 부담, 임베딩모델 버전관리, 인덱스 재구축 비용, 데이터 최신성 유지가 고려사항임.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 13. 정보보호 공시제도

**1. 개요**  
정보보호 공시제도(ISDS, Information Security Disclosure System)는 기업의 정보보호 투자·인력·활동 현황을 매년 공개하도록 의무화하여 정보보호 수준을 대외적으로 공시하고 자율적 투자를 유도하는 제도로, 정보통신망법에 근거함.

**2. 주요 내용**

| 구분 | 내용 |
|---|---|
| 근거법 | 정보통신망 이용촉진 및 정보보호 등에 관한 법률 |
| 대상기업 | 일정 규모 이상 정보통신서비스제공자, 상장사 등(의무/자율) |
| 공시항목 | 정보보호 투자금액·비율, 전담인력 수, 인증취득 현황 |
| 공시방법 | 공시포털(전자공시) 등록, 매년 6월 공시 |
| 관리기관 | 과학기술정보통신부, KISA |

**3. 상세 설명**  
기업은 직전년도 정보보호 투자현황(정보보호 예산/IT예산 비율), 정보보호 전담인력 현황, ISMS-P 등 인증취득 여부를 공시서식에 따라 작성·제출. 미공시·거짓공시 시 과태료 부과 등 제재규정 존재. 공시정보는 투자자·이용자의 기업 신뢰도 평가 지표로 활용됨.

**4. 기대효과 및 고려사항**  
기업의 자발적 정보보호 투자 확대 유도, 정보보호 산업 활성화, 투자자 의사결정 지원이 기대됨. 다만 형식적 공시(숫자 나열)에 그치지 않도록 실질 지표(침해대응 역량 등) 보완, 중소기업 공시부담 완화방안 검토가 필요함.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 14. 도메인 특화 언어 모델(Domain-Specific Language Models)

**1. 개요**  
도메인 특화 언어 모델은 범용 대규모 언어모델(LLM)을 특정 산업(의료, 법률, 금융 등) 도메인의 전문지식과 용어체계에 맞게 추가학습(Fine-tuning) 또는 재구성한 모델임. 범용 LLM의 전문영역 정확도 및 환각(Hallucination) 문제 한계를 보완하기 위해 등장함.

**2. 특징 및 구성요소**

| 구축방식 | 특징 |
|---|---|
| 도메인 사전학습 | 도메인 코퍼스로 처음부터 학습, 고비용·고정밀 |
| 파인튜닝(Fine-tuning) | 범용모델에 도메인 데이터로 추가학습 |
| RAG 결합 | 외부 도메인 지식베이스 검색 후 생성에 반영 |
| 어댑터/LoRA | 경량 파라미터만 학습하여 효율적 특화 |

**3. 상세 설명**  
구축절차는 도메인 데이터 수집·정제 → 전문용어 토크나이저 보강 → 사전학습/파인튜닝 → 도메인 벤치마크 평가 → 배포 순으로 진행됨. 의료(BioGPT, Med-PaLM), 법률, 금융 분야에서 전문용어 이해도와 규제 준수성 향상에 활용되며, 데이터 부족 및 프라이버시 이슈 해결을 위해 합성데이터 생성, 연합학습(Federated Learning)과 결합하는 사례가 증가함.

**4. 기대효과 및 고려사항**  
전문영역 응답 정확도 향상, 환각 감소, 업무 자동화 효율성 제고가 기대됨. 다만 도메인 데이터 확보의 어려움, 지속적 갱신 비용, 범용성 저하(Catastrophic Forgetting) 방지를 위한 지속학습 전략 및 검증체계 마련이 병행되어야 함.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 15. VLM(Vision-Language Models)

**1. 개요**  
VLM은 이미지·비디오 등 시각정보와 텍스트 정보를 동시에 이해하고 상호 연관지어 처리하는 멀티모달 딥러닝 모델임. 단일 모달(텍스트 또는 이미지) 처리 모델의 한계를 넘어 인간처럼 시각과 언어를 통합적으로 인지할 필요성에서 발전함.

**2. 특징 및 구성요소**

| 구성요소 | 역할 |
|---|---|
| 비전 인코더 | 이미지 특징 추출(CNN, ViT) |
| 언어 인코더/디코더 | 텍스트 임베딩 및 생성(Transformer) |
| 정렬모듈(Cross-Modal Alignment) | 시각-텍스트 임베딩 공간 정합 |
| 대표모델 | CLIP, BLIP, GPT-4V, LLaVA |

**3. 상세 설명**  
사전학습단계에서 대규모 이미지-텍스트 페어 데이터로 대조학습(Contrastive Learning, 예: CLIP)을 통해 두 모달의 임베딩 공간을 정합하고, 이후 이미지 캡셔닝, VQA(Visual Question Answering), 이미지 기반 추론 등 다운스트림 태스크로 파인튜닝함. Cross-Attention 메커니즘을 통해 시각 특징과 언어 토큰 간 상호참조를 수행하여 통합적 의미 이해를 구현함.

**4. 기대효과 및 고려사항**  
이미지 검색, 자율주행 상황인지, 의료영상 판독 보조, 시각장애인 보조기술 등 다양한 산업에 적용되어 활용범위 확대가 기대됨. 다만 대규모 이미지-텍스트 데이터 확보 비용, 시각적 환각(Visual Hallucination) 문제, 편향된 학습데이터로 인한 공정성 이슈에 대한 지속적 검증이 필요함.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 16. 소프트웨어 프로세스(SP, Software Process) 품질인증

**1. 개요**

**가. 정의**  
소프트웨어 프로세스(SP) 품질인증 제도는 소프트웨어산업진흥법에 근거하여 과학기술정보통신부·NIPA(정보통신산업진흥원)가 국내 SW 개발조직의 프로세스 성숙도를 심사하여 인증등급(1~5레벨)을 부여하는 국가 공인 인증제도로, CMMI를 국내 SW산업 환경에 맞게 경량화·현지화한 모델이다.

**나. 등장배경**  
글로벌 CMMI 인증은 심사비용·기간이 과도하여 국내 중소 SW기업의 접근성이 낮았고, 공공 SW사업 발주시 프로세스 역량을 객관적으로 입증할 국내 표준 인증체계가 필요하여 도입되었다.

**다. 목적**  
국내 SW기업의 개발 프로세스 역량을 표준화된 기준으로 평가·인증함으로써 SW품질 향상, 공공/민간 SW사업 수행역량 대외 신뢰성 확보, 중소기업의 프로세스 개선 유도를 목적으로 한다.

**2. 특징 및 구성도**

```
Level 1(수행) → Level 2(관리) → Level 3(정의) → Level 4(정량관리) → Level 5(최적화)
      └──────────── 프로세스영역(PA)별 심사 및 등급 부여 ────────────┘
```

| 등급 | 특징 |
|---|---|
| Level 1 | 프로젝트별 개별 수행, 표준프로세스 부재 |
| Level 2 | 프로젝트 단위 계획·관리 프로세스 존재 |
| Level 3 | 조직 표준프로세스 정의 및 전사 적용 |
| Level 4 | 정량적 지표 기반 프로세스 관리 |
| Level 5 | 지속적 프로세스 최적화 및 혁신 |

**3. 상세 설명**

**(1) 인증체계(아키텍처)**  
심사기준은 CMMI의 Process Area를 국내 실정에 맞게 재구성한 프로세스영역(요구사항관리, 프로젝트계획, 형상관리, 품질보증 등)으로 구성되며, NIPA 산하 인증기관과 공인 심사원(Lead Appraiser)에 의해 심사가 수행된다.

**(2) 인증 절차**  
① 인증신청 및 사전 준비도 진단(Gap Analysis) → ② 프로세스 개선활동 수행 및 문서화 → ③ 예비심사(Pre-Assessment) → ④ 본심사(현장심사, 인터뷰, 문서검증) → ⑤ 심사결과 심의위원회 승인 → ⑥ 인증서 발급(유효기간 통상 3년) 순으로 진행된다.

**(3) 적용기준 및 관련 제도**  
ISO/IEC 15504(SPICE), CMMI 프레임워크를 기반으로 하며, 국가정보화 기본법, SW산업진흥법과 연계되어 공공 SW사업 발주시 SP인증등급을 입찰 가산점·참가자격 요건으로 활용하는 조달정책과 결합되어 있다.

**(4) 글로벌 CMMI 인증과의 비교**  
CMMI는 국제 공인 심사기관을 통해 고비용·장기간 심사가 진행되며 글로벌 발주처 대상 신뢰도가 높은 반면, SP인증은 국내 공공조달 특화 인증으로 심사비용·기간이 상대적으로 짧고 국내 중소 SW기업 접근성이 높으나 국제적 통용성은 CMMI에 미치지 못한다는 차이가 있다.

**4. 활용분야/사례**

공공기관 SW개발 사업자 선정시 가산점 부여, 조달청 나라장터 SW사업 참가자격 요건, 대기업 SI사의 협력사 평가기준, 국방·공공 프로젝트의 사업수행능력 평가지표로 활용되며, 다수의 국내 SW개발기업이 Level 2~3 인증을 획득하여 공공사업 수주에 활용하고 있다.

**5. 기대효과 및 고려사항/전망**

**기대효과**: 국내 SW기업의 프로세스 역량 표준화 및 품질경쟁력 강화, 공공SW 품질사고 예방, 중소기업의 체계적 프로젝트관리 역량 확보.  
**고려사항**: 인증취득 자체가 목적화되는 형식주의 우려, 인증 후 실질적 프로세스 이행 여부에 대한 사후관리 미흡, 심사원 풀 부족에 따른 심사기간 지연.  
**전망**: CMMI v3.0의 성과중심 심사 트렌드를 반영하여 문서 준수여부에서 실질적 SW품질·성과지표 연계 심사로 개편이 예상되며, DevOps/애자일 조직에 적합한 경량 평가모델과 AI 기반 자동심사 도구 도입이 확대될 전망이다.

### 17. AES(Advanced Encryption Standard)

**1. 개요**

**가. 정의**  
AES는 미국 NIST가 2001년 FIPS-197로 표준화한 대칭키 블록암호 알고리즘으로, 128비트 고정 블록 크기와 128/192/256비트 가변 키 길이를 지원하며 SPN(Substitution-Permutation Network) 구조 기반의 라운드 함수를 반복 수행하여 평문을 암호화하는 기법이다.

**나. 등장배경**  
1977년 표준화된 DES(Data Encryption Standard)는 56비트 키 길이의 한계로 1990년대 후반 무차별 대입공격(Brute Force)에 취약점이 노출되었고, 3DES는 3배의 연산으로 성능 저하가 심각하였다. 이에 NIST는 1997년 AES 공모를 시작하여 15개 후보 중 벨기에 연구진의 Rijndael 알고리즘을 2000년 최종 채택, 2001년 FIPS-197로 공표하였다.

**다. 필요성 및 목적**  
- 양자컴퓨팅 이전 시대 충분한 키 공간 확보를 통한 전사적 데이터 기밀성 보장  
- 소프트웨어/하드웨어 양쪽에서 고속 구현 가능한 효율성 확보  
- 국제 표준화를 통한 상호운용성 및 검증체계(CMVP, KCMVP) 연계

**2. 특징 및 구성요소**

| 구분 | 내용 |
|---|---|
| 블록크기 | 128비트(16바이트) 고정 |
| 키길이 | 128/192/256비트 |
| 라운드수 | 10/12/14 라운드(키길이에 비례) |
| 구조 | SPN 구조(Feistel 구조 아님) |
| 연산단위 | 4×4 바이트 State 행렬(128비트) |
| 주요연산 | SubBytes, ShiftRows, MixColumns, AddRoundKey |

```
[구성 요소 흐름도]
평문(128bit)
   │
   ▼
State Matrix(4x4 Byte) 생성
   │
   ▼
Initial AddRoundKey
   │
   ▼
┌─────────────────────────────┐
│ Round 1 ~ N-1 반복           │
│  SubBytes → ShiftRows →     │
│  MixColumns → AddRoundKey   │
└─────────────────────────────┘
   │
   ▼
Final Round(MixColumns 생략)
  SubBytes → ShiftRows → AddRoundKey
   │
   ▼
암호문(128bit)
```

**3. 상세 설명**

**(1) 핵심 원리 - 라운드 연산**  
- SubBytes: S-Box(비선형 치환표)를 이용한 바이트 단위 치환으로 혼돈(Confusion) 특성 제공, 갈루아체 GF(2^8) 상의 역원 연산 기반  
- ShiftRows: State 행렬의 각 행을 좌측으로 순환 이동(0,1,2,3바이트)시켜 열 간 확산(Diffusion) 유도  
- MixColumns: State의 각 열을 GF(2^8) 상의 고정 다항식과 행렬곱하여 바이트 간 상호 확산 극대화(최종 라운드 제외)  
- AddRoundKey: 라운드 키와 State를 XOR 연산, 키 스케줄(Key Expansion) 알고리즘으로 라운드별 서브키 생성

**(2) 동작 절차**  
① 128비트 평문을 4×4 State 행렬로 배치 → ② 초기 라운드키 XOR → ③ (N-1)회 표준 라운드 반복 → ④ 최종 라운드(MixColumns 제외) 수행 → ⑤ State를 암호문으로 출력. 복호화는 역S-Box, InvShiftRows, InvMixColumns를 역순 적용.

**(3) 적용 기술/표준 및 운영모드**  
AES 자체는 블록 단위 암호화만 정의하므로 실사용시 운영모드(Mode of Operation)와 결합: ECB(패턴노출 취약, 비권장), CBC(IV 필요, 순차처리), CTR(병렬처리 가능, 스트림형), GCM(AEAD, 기밀성+인증 동시제공, TLS1.3/IPSec 표준 채택). 하드웨어 가속을 위해 Intel AES-NI, ARM Cryptography Extension 명령어셋 지원.

**(4) 기존기술(DES/3DES)과의 비교**

| 구분 | DES | 3DES | AES |
|---|---|---|---|
| 키길이 | 56bit | 168bit(실효112) | 128/192/256bit |
| 구조 | Feistel | Feistel | SPN |
| 처리속도 | 빠름 | 느림(3배연산) | 빠름(HW가속) |
| 안전성 | 취약(폐기) | 제한적(단계적폐기) | 현재 안전 |

**4. 활용분야 및 사례**  
- 네트워크 보안: TLS/SSL(HTTPS), IPSec VPN의 대칭키 암호화 엔진  
- 저장매체 암호화: BitLocker, FileVault, 전자여권(ePassport) 칩 데이터 보호  
- 무선통신: WPA2/WPA3(Wi-Fi), 5G 단말-기지국 구간 암호화  
- 클라우드/DB: TDE(Transparent Data Encryption), 블록체인 지갑 개인키 보호  
- 국내: KCMVP 검증 대상 알고리즘으로 공공기관 정보시스템 필수 적용

**5. 기대효과 및 고려사항/전망**  
**기대효과**: 표준화된 검증 알고리즘 사용으로 상호운용성 확보, 하드웨어 가속 지원으로 성능-보안 균형 달성, 글로벌 신뢰성 기반 산업 전반 채택.  
**고려사항**: 키 관리(HSM, KMS 연계) 부재 시 알고리즘 안전성이 무력화되며, Side-Channel 공격(전력분석, 캐시타이밍) 대비 마스킹 기법 필요, ECB 모드 등 부적절한 운영모드 사용시 패턴 노출 위험.  
**향후전망**: 양자컴퓨터 Grover 알고리즘 대비 AES-256 채택 권고 확산, PQC(Post-Quantum Cryptography)와의 하이브리드 운용 전환, 경량 IoT 환경을 위한 AES 경량화 구현체 및 화이트박스 암호 기술 발전이 예상된다.

### 18. 가디언 에이전트(Guardian Agent)

**1. 개요**  
- 정의: 가디언 에이전트는 자율적으로 동작하는 AI 에이전트(작업 수행 에이전트)의 행위를 실시간 감시·검증·제어하는 감독형 AI 에이전트를 의미함  
- 등장배경: 생성형 AI 기반 자율 에이전트의 업무 자동화 확산에 따라 오작동, 편향된 판단, 권한 오남용 등 위험 통제 필요성 증대

**2. 주요 기능 및 구성요소**

| 구성요소 | 역할 |
|---|---|
| 정책엔진 | 허용 행위 범위(가드레일) 정의 |
| 모니터링 모듈 | 에이전트 행위·출력 실시간 추적 |
| 검증 모듈 | 결과물의 사실성·안전성 검증 |
| 개입 제어 | 이상행위 탐지 시 차단·롤백·승인요청 |

**3. 상세 설명**  
- 동작원리: 작업 에이전트의 입출력 및 도구 호출(Tool Call)을 인터셉트하여 사전 정의된 정책과 대조, 위반 시 실행 차단 또는 인간 승인(Human-in-the-loop) 요청  
- 적용기법: 프롬프트 인젝션 탐지, 행위 로그 기반 이상행위 탐지(Anomaly Detection), 다중 에이전트 간 상호검증(Multi-agent Cross-check)  
- 유사개념과 차이: 단순 로깅·모니터링과 달리 실시간 개입 및 자율적 판단 능력을 보유함이 특징

**4. 기대효과 및 고려사항**  
- 기대효과: 자율 에이전트 도입에 따른 신뢰성·안전성 확보, 규제 준수(책임소재 명확화), 오작동 조기 차단으로 피해 최소화  
- 고려사항: 가디언 에이전트 자체의 오판·과잉차단(False Positive) 문제, 에이전트 간 권한 위임 체계 및 책임 범위 명확화 필요

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 19. 지속적인 위협 노출 관리(CTEM)

**1. 개요**  
- 정의: CTEM(Continuous Threat Exposure Management)은 조직의 공격표면과 노출된 취약점을 지속적·반복적으로 식별·검증·우선순위화하여 실질적 위험을 관리하는 프로그램으로, Gartner가 제시함  
- 등장배경: 클라우드·SaaS 확산으로 공격표면이 급증하고 정기 취약점 스캔만으로는 실시간 위협 대응 한계 발생

**2. 5단계 구성**

| 단계 | 내용 |
|---|---|
| Scoping | 관리대상 자산·비즈니스 우선순위 정의 |
| Discovery | 자산·취약점·오설정 식별 |
| Prioritization | 악용 가능성·영향도 기반 우선순위화 |
| Validation | 실제 공격 시나리오 기반 검증(모의공격) |
| Mobilization | 대응조치 실행 및 이해관계자 협업 |

**3. 상세 설명**  
- 핵심원리: 단발성 진단이 아닌 지속적 순환(Cycle) 프로세스로 운영, BAS(Breach and Attack Simulation)·ASM(Attack Surface Management) 도구와 연계  
- 기존 취약점관리와 차이: CVSS 점수 중심이 아닌 실제 악용 가능성·비즈니스 영향 기반 우선순위화(Risk-based) 수행  
- 적용기술: 자동화된 자산탐색, 위협인텔리전스 연계, 공격경로 시뮬레이션

**4. 기대효과 및 고려사항**  
- 기대효과: 실질적 위험 노출 최소화, 보안조치 자원의 효율적 배분, 규제 대응력 강화  
- 고려사항: 조직 전반의 프로세스·거버넌스 정착 필요, 자동화 도구와 인적 검증(Validation)의 균형 필요

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 20. 패스키(Passkey)

**1. 개요**  
- 정의: 패스키는 FIDO Alliance와 W3C가 제정한 FIDO2/WebAuthn 표준 기반의 비밀번호 없는(Passwordless) 인증 수단으로, 공개키 암호 방식을 활용함  
- 등장배경: 비밀번호 유출·재사용·피싱에 의한 계정탈취 문제 해결 및 사용자 편의성 제고 필요성 증대

**2. 구성요소**

| 구성요소 | 역할 |
|---|---|
| 개인키 | 사용자 기기 내 보안영역(TPM/Secure Enclave) 저장, 외부 미노출 |
| 공개키 | 서비스 서버에 등록 |
| 인증장치 | 생체인증(지문·안면) 또는 PIN으로 개인키 사용 승인 |
| 동기화 | 클라우드 계정(iCloud, Google 등) 통해 다중기기 공유 |

**3. 상세 설명**  
- 동작원리: 등록 시 기기에서 키쌍 생성 후 공개키만 서버 전송, 로그인 시 서버가 challenge 전송 → 기기가 생체인증 후 개인키로 서명 → 서버가 공개키로 검증  
- 기존 방식과 차이: 비밀번호를 서버에 저장하지 않아 서버 유출 시에도 인증정보 탈취 불가, 피싱 사이트에서는 도메인 불일치로 서명 자체가 불가능(피싱 원천 차단)  
- 표준기술: WebAuthn API, CTAP2 프로토콜, 공개키 기반구조(PKI) 원리 활용

**4. 기대효과 및 고려사항**  
- 기대효과: 비밀번호 관리 부담 해소, 피싱·크리덴셜스터핑 공격 원천 차단, 사용자 편의성 및 로그인 성공률 향상  
- 고려사항: 기기 분실 시 복구절차 마련 필요, 플랫폼 간(iOS/Android/Windows) 상호운용성 및 레거시 시스템과의 병행 전환 전략 필요

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 21. WAAP(Web Application and API Protection)

**1. 개요**

**가. 정의**  
WAAP는 전통적 WAF(Web Application Firewall)의 웹 애플리케이션 보호 기능에 API 보안, DDoS 방어, 봇 관리(Bot Management)를 통합하여 클라우드 기반으로 제공하는 차세대 애플리케이션 보안 플랫폼이다. Gartner가 2019년 이후 명명한 개념으로 단일 정책·단일 대시보드 기반 통합 방어체계를 지향한다.

**나. 등장배경**  
마이크로서비스/컨테이너 아키텍처 확산으로 API 트래픽이 전체 웹 트래픽의 80% 이상을 점유하게 되었으나, 기존 WAF는 시그니처 기반 웹 공격(SQLi, XSS) 방어에 특화되어 API 고유 취약점(OWASP API Top10 - BOLA, 과도한 데이터 노출 등)과 자동화된 봇 공격에 대응이 미흡하였다. 또한 개별 보안 솔루션(WAF, Anti-DDoS, Bot Mitigation) 분리 운영으로 정책 불일치 및 관제 복잡성이 증가하였다.

**다. 필요성 및 목적**  
- API 우선(API-First) 아키텍처 환경에서의 통합 가시성 확보  
- 지능형 봇(Headless Browser, AI기반 크레덴셜 스터핑) 대응  
- 클라우드 네이티브 확산에 따른 SaaS형 신속 배포 및 자동 확장

**2. 특징 및 구성요소**

```
[WAAP 통합 구성도]
                ┌─────────────────────────┐
   Client ───▶  │   Edge/CDN Layer        │
   (User/Bot/   │  ┌─────┬─────┬────────┐ │
    Attacker)   │  │ DDoS│ Bot │ WAF    │ │ ──▶ Origin Server
                │  │방어  │관리 │(OWASP  │ │      (Web/App)
                │  │      │     │Top10)  │ │
                │  ├─────┴─────┴────────┤ │
                │  │  API Security       │ │ ──▶ API Gateway/
                │  │ (스키마검증,인증,   │ │      Microservice
                │  │  Rate Limiting)     │ │
                │  └─────────────────────┘ │
                │  통합 정책관리/가시성    │
                └─────────────────────────┘
```

| 구성요소 | 기능 |
|---|---|
| WAF | SQLi, XSS, CSRF 등 OWASP Top10 시그니처/행위기반 차단 |
| API보안 | API 스키마(OpenAPI) 검증, 인증/인가, BOLA 등 API전용 취약점 방어 |
| DDoS방어 | L3/L4/L7 대용량 트래픽 탐지 및 분산 완화 |
| 봇관리 | 디바이스 핑거프린팅, 행위분석 기반 정상/악성 봇 구분 |
| 통합관제 | 단일 대시보드, 통합 로그/정책, API기반 자동화 연동 |

**3. 상세 설명**

**(1) 핵심 아키텍처**  
WAAP는 CDN/Edge POP(Point of Presence)에 배포되어 클라이언트 요청이 오리진 서버에 도달하기 전 다단계 필터링을 수행한다. 계층은 네트워크단(L3/4 DDoS 방어) → 애플리케이션단(L7 WAF, 시그니처+머신러닝 이상탐지) → API단(스키마 기반 검증, 인증토큰 검사) → 봇관리단(행위/생체 신호 분석)으로 구성되며, 각 계층의 탐지결과가 통합 정책엔진에 반영되어 동적 룰 업데이트가 이루어진다.

**(2) 동작 절차**  
① 요청 수신 및 TLS 종단(Termination) → ② DDoS 탐지(트래픽 패턴/임계치 분석) → ③ 봇 여부 판별(JS Challenge, CAPTCHA, 디바이스 핑거프린팅) → ④ WAF 룰셋 매칭(정규식/ML 기반 이상탐지) → ⑤ API 요청시 OpenAPI 스키마 대비 파라미터/타입 검증 및 인증 확인 → ⑥ 정상 트래픽만 오리진 전달, 위협 트래픽은 차단/챌린지/모니터링 중 정책에 따라 처리.

**(3) 적용 기술/표준**  
OWASP API Security Top10(2023) 대응 룰셋, OpenAPI/Swagger 스키마 자동 학습(Positive Security Model), mTLS 및 OAuth2/JWT 토큰 검증, ML/UEBA 기반 이상행위탐지, RASP(Runtime Application Self-Protection)와의 연계, Zero Trust 아키텍처의 마이크로세그먼테이션 원칙 적용.

**(4) 기존 WAF/개별솔루션과의 비교**

| 구분 | 기존 WAF | 개별 Anti-DDoS/Bot | WAAP |
|---|---|---|---|
| 보호대상 | 웹 애플리케이션 위주 | 네트워크/봇 개별 | 웹+API+네트워크+봇 통합 |
| 배포방식 | On-prem/단일 어플라이언스 | 개별 솔루션 | 클라우드/Edge SaaS |
| API보안 | 미흡(시그니처 한계) | 미지원 | 스키마기반 정밀검증 |
| 운영복잡성 | 정책 분산 | 정책 분산 | 단일 통합관제 |

**4. 활용분야 및 사례**  
- 금융권 오픈뱅킹 API 게이트웨이 전단 보호(BOLA, 과다호출 방어)  
- 이커머스 플랫폼의 크리덴셜 스터핑, 가격 스크래핑 봇 차단  
- 공공기관 마이데이터/공공API 개방 포털의 인증 우회 공격 방어  
- 글로벌 CDN 사업자(Cloudflare, Akamai, AWS)의 WAAP 서비스형 제공  
- 컨테이너/K8s 기반 마이크로서비스 API Gateway와의 연동 방어

**5. 기대효과 및 고려사항/전망**  
**기대효과**: 분산된 보안 솔루션의 통합 운영으로 관제 효율성 증대, API 특화 위협 가시성 확보, 클라우드 자동확장을 통한 대규모 DDoS 대응력 강화, 정책 일원화로 보안사고 대응시간(MTTD/MTTR) 단축.  
**고려사항**: 클라우드 경유에 따른 지연시간(Latency) 및 데이터 주권 이슈, 오탐(False Positive)으로 인한 정상 API 호출 차단 가능성, 벤더 종속(Lock-in) 리스크, 암호화된 트래픽(mTLS) 가시성 확보의 어려움.  
**향후전망**: AI/LLM 기반 API 위협 예측 고도화, Zero Trust와 결합한 컨텍스트 기반 동적 접근제어 확산, 생성형AI 기반 봇(에이전틱 AI 크롤러) 대응을 위한 봇관리 정교화, SASE(Secure Access Service Edge) 아키텍처로의 통합 진화가 전망된다.

### 22. React2Shell

**개요**: React2Shell 유형의 공격은 React 기반 SSR(Server-Side Rendering) 프레임워크(Next.js 등)나 관련 서버 컴포넌트의 취약점을 악용하여 공격자가 원격으로 임의 코드를 실행, 웹쉘을 업로드하여 서버 셸 권한을 획득하는 원격 코드 실행(RCE) 공격임. 프론트엔드 프레임워크의 서버측 렌더링 확대와 npm 생태계 의존성 급증에 따라 공급망 취약점 노출 위험이 커지며 등장함.

**공격 유형 및 취약점**

| 구분 | 내용 |
|---|---|
| 취약점 원인 | SSR 미들웨어 역직렬화 결함, 서버 액션(Server Action) 입력 검증 미비, 의존 패키지 공급망 오염 |
| 공격 경로 | 악성 페이로드 전송→서버측 코드 실행→웹쉘 업로드→권한 상승 |
| 유사사례 | Log4Shell, npm 패키지 하이재킹형 공급망 공격 |

**상세설명**: 공격자는 취약한 API 라우트나 서버 액션에 조작된 요청을 전송하여 서버 프로세스 권한으로 명령을 실행시키고, 이를 통해 웹쉘을 심어 지속적 백도어를 확보함. 이후 내부망 이동(Lateral Movement) 및 데이터 유출로 이어짐.

**대응방안**: 입력값 화이트리스트 검증 및 역직렬화 제한, 의존성 SBOM 관리 및 정기 취약점 스캐닝(SCA), WAF/RASP 도입, 최소권한 컨테이너 실행, 정기 패치 및 웹쉘 탐지용 파일 무결성 모니터링(FIM) 적용이 필요함.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 23. 시계열 데이터베이스

**개요**: 시계열 데이터베이스(Time Series Database, TSDB)는 시간 순서에 따라 연속적으로 생성되는 데이터(타임스탬프+값)를 고속 수집·저장·조회하는 데 특화된 데이터베이스임. IoT 센서, 인프라 모니터링, 금융 틱데이터 등 초당 대량의 시계열 데이터 발생에 따라 기존 RDBMS의 쓰기 성능·저장효율 한계를 극복하기 위해 등장함.

**특징 및 대표 제품**

| 구분 | 내용 |
|---|---|
| 데이터 모델 | 타임스탬프+메트릭+태그(레이블) 구조 |
| 대표제품 | InfluxDB, Prometheus, TimescaleDB, OpenTSDB |
| 주요 연산 | 다운샘플링, 이동평균, 구간 집계(Rollup) |

**상세설명**: 시간 순 정렬 저장구조(LSM-Tree 기반)로 순차 쓰기 성능을 최적화하고, 컬럼 지향 압축(Delta/Delta-of-delta, Run-length 인코딩)으로 저장공간을 절감함. 데이터 보존정책(Retention Policy)에 따라 오래된 데이터를 자동 삭제하거나 다운샘플링하며, Continuous Query로 실시간 집계 뷰를 생성함. 태그 기반 인덱싱으로 다차원 필터링 조회를 지원함.

**기대효과 및 고려사항**: 대량 시계열 데이터의 고속 적재 및 실시간 분석(모니터링·알림) 가능하나, 고카디널리티(태그 조합 폭증) 시 성능 저하 우려가 있어 태그 설계 최적화 및 보존정책 수립이 중요함.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 24. SDP(Software Defined Perimeter, 소프트웨어 정의 경계)

**개요**: SDP는 네트워크 경계를 물리적 위치가 아닌 소프트웨어 기반의 논리적 경계로 정의하여, 인증·인가된 사용자와 디바이스에게만 필요한 리소스로의 접근을 동적으로 허용하는 보안 아키텍처임. 클라우드·재택근무 확산으로 전통적 경계(방화벽/VPN) 기반 보안모델의 한계가 드러나며 제로트러스트(Zero Trust) 구현 기술로 부상함.

**핵심 구성요소**

| 구성요소 | 역할 |
|---|---|
| SDP Controller | 인증·정책 관리, 접속 승인 결정 |
| Initiating Host(Client) | 접속 요청 및 인증 수행 |
| Accepting Host(Gateway) | 승인된 연결만 리소스 노출 |

**상세설명**: 핵심 동작원리는 "Need-to-know" 모델과 단일패킷인가(SPA: Single Packet Authorization)로, 인증 전에는 서버 존재 자체를 숨겨 사전 접근 시도를 차단함(Dark Cloud 효과). 접속 절차는 ①디바이스/사용자 인증 →②Controller가 정책 기반 접근권한 검증→③암호화된 마이크로 터널을 동적 생성→④승인된 리소스에만 1:1 연결하는 순서로 진행됨. 기존 VPN이 네트워크 전체 접근을 허용하는 것과 달리 자원 단위로 세분화(마이크로세그멘테이션)된 접근제어를 제공함.

**기대효과 및 고려사항**: 공격표면 최소화, 내부망 측면이동(Lateral Movement) 차단 효과가 크나, 기존 인프라와의 연계 통합, 엔드포인트 에이전트 배포·관리 부담을 고려해야 함.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 25. 울트라 이더넷 (Ultra Ethernet)

**1. 개요**  
- 정의: AI/HPC 클러스터의 대규모 병렬 연산에 최적화된 차세대 이더넷 통신 표준으로, UEC(Ultra Ethernet Consortium)가 주도 개발함  
- 배경: 생성형 AI 학습에 GPU 수만 개가 참여하며 기존 InfiniBand·전통 이더넷의 지연·확장성 한계 극복 필요성 증대에 따라 등장함

**2. 특징 및 구성요소**  
| 구분 | 내용 |
|---|---|
| 전송계층 | UET(Ultra Ethernet Transport), RDMA 기반 |
| 혼잡제어 | 다중경로 기반 패킷 스프레이(Packet Spray) |
| 신뢰성 | 선택적 재전송, 순서 무관 전달 |
| 보안 | 라인레이트 암호화 지원 |

**3. 상세 설명**  
- 기존 RoCEv2의 단일경로 한계를 극복하기 위해 패킷 단위 다중경로 분산 전송(Packet Spray) 적용, 링크 활용률 극대화함  
- 순서 보장 없는 전달(Out-of-order delivery) 허용으로 헤드오브라인 블로킹 제거함  
- 혼잡 발생 시 실시간 신호 기반 능동 혼잡제어(Congestion Control) 수행하여 마이크로버스트 완화함  
- 표준 이더넷 스위치·NIC 생태계 활용으로 InfiniBand 대비 비용·상호운용성 개선함

**4. 기대효과 및 고려사항**  
- 기대효과: GPU 클러스터 확장성 확보, TCO 절감, 개방형 생태계 조성  
- 고려사항: 초기 상용 스위치/NIC 지원 미성숙, 기존 인프라 전환 비용, 표준 버전 호환성 검증 필요함

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 26. 스테이블 코인(Stable Coin)

**1. 개요**  
- 정의: 법정화폐, 실물자산 또는 알고리즘을 기반으로 가치를 특정 자산에 고정시켜 가격 변동성을 최소화한 암호자산임  
- 배경: 비트코인 등 암호화폐의 극심한 가격 변동성으로 인한 결제·거래 수단 활용 제약을 해소하기 위해 등장함

**2. 유형 및 구성요소**  
| 유형 | 담보방식 | 예시 |
|---|---|---|
| 법정화폐 담보형 | 은행예치·국채 | USDT, USDC |
| 암호자산 담보형 | 초과담보 암호화폐 | DAI |
| 알고리즘형 | 수요공급 알고리즘 조절 | (구)UST |

**3. 상세 설명**  
- 발행사가 담보자산을 예치하고 1:1 페깅(Peg)된 토큰을 발행, 상환 시 소각(Burn)하는 구조로 운영됨  
- 지급결제, DeFi 담보, 국경간 송금 등에 활용되며 블록체인 상 스마트컨트랙트로 발행·유통 자동화됨  
- 리스크: 디페깅(Depegging), 담보 투명성 부족에 따른 뱅크런, 알고리즘형의 구조적 붕괴 위험 존재함  
- 규제 동향: 미국 GENIUS Act, EU MiCA, 국내 가상자산이용자보호법 2단계 입법 추진 중임

**4. 기대효과 및 고려사항**  
- 기대효과: 결제 효율화, 크로스보더 금융 혁신, 디지털 자산 생태계 확장  
- 고려사항: 담보자산 실시간 감사체계, 발행사 건전성 규제, 통화주권·금융안정 영향 검토 필요함

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 28. 합성 데이터(Synthetic Data)

**1. 개요**

**가. 정의**  
합성 데이터는 실제 원본 데이터를 직접 사용하지 않고, 원본 데이터의 통계적 분포·패턴·상관관계를 알고리즘(GAN, VAE, Diffusion Model 등)이나 시뮬레이션을 통해 학습·모사하여 인위적으로 생성한 인공 데이터를 의미하며, 개인식별정보(PII)를 포함하지 않으면서 원본과 유사한 분석적 유용성(Utility)을 제공한다.

**나. 등장배경**  
개인정보보호법·GDPR 등 데이터 규제 강화로 실데이터 활용이 제약되었으며, 특히 의료·금융 등 민감정보 분야에서 AI 학습용 데이터 확보가 어려웠다. 또한 이상탐지(사기, 희귀질환)와 같이 실제 데이터가 절대적으로 부족한 클래스 불균형 문제, 라벨링 비용 문제가 심화되면서 데이터 부족(Data Scarcity)을 해소할 대안 기술로 부상하였다.

**다. 필요성 및 목적**  
- 개인정보 노출 없는 안전한 데이터 공유·2차 활용 환경 조성(프라이버시 보호)  
- AI 모델 학습을 위한 대규모·균형 데이터셋 확보(데이터 증강)  
- 규제 샌드박스 내 데이터 실험 및 희소 시나리오(사고, 이상거래) 데이터 생성

**2. 특징 및 구성요소**

```
[합성데이터 생성 파이프라인]
원본 데이터(Real Data, PII 포함)
        │
        ▼
데이터 전처리/프로파일링(분포, 상관관계 분석)
        │
        ▼
┌───────────────────────────────┐
│ 생성 모델 학습                 │
│  GAN(생성자↔판별자 적대학습)   │
│  VAE(인코더-잠재공간-디코더)    │
│  Diffusion(노이즈 제거 역과정) │
└───────────────────────────────┘
        │
        ▼
합성데이터 샘플링/생성
        │
        ▼
품질평가(Fidelity/Utility) + 프라이버시 평가(재식별위험)
        │
        ▼
합성 데이터셋(외부공개/AI학습용)
```

| 생성기법 | 원리 | 특징 |
|---|---|---|
| GAN | 생성자-판별자 적대적 경쟁학습 | 고품질 이미지/정형데이터 생성, 학습 불안정 가능 |
| VAE | 인코더로 잠재공간 매핑 후 디코더 복원 | 안정적 학습, 다소 흐린(blur) 품질 |
| Diffusion Model | 노이즈 추가 후 역과정으로 복원 학습 | 최고품질 생성, 연산비용 높음 |
| Rule/Simulation | 통계모델·물리모델 기반 규칙 생성 | 해석 용이, 복잡 패턴 표현 한계 |

**3. 상세 설명**

**(1) 핵심 원리**  
GAN은 생성자(Generator)가 노이즈로부터 가짜 데이터를 생성하고 판별자(Discriminator)가 실제/가짜를 구분하도록 경쟁시켜, 두 네트워크가 균형(Nash Equilibrium)에 도달할 때 실제와 통계적으로 구분 불가능한 데이터를 생성한다. VAE는 인코더가 데이터를 저차원 잠재공간의 확률분포로 압축하고 디코더가 이를 복원하는 과정에서 잠재공간 샘플링을 통해 신규 데이터를 생성한다. Diffusion Model은 원본에 점진적으로 가우시안 노이즈를 추가하는 정방향 과정과, 신경망이 노이즈를 단계적으로 제거하는 역방향 과정을 학습하여 고품질 샘플을 생성한다.

**(2) 동작 절차/프로세스**  
① 원본 데이터 수집 및 스키마·분포 프로파일링 → ② 민감속성 식별 및 전처리(정규화, 결측치 처리) → ③ 생성모델 선정 및 학습(정형데이터는 CTGAN/TVAE, 이미지는 StyleGAN/Diffusion) → ④ 합성데이터 샘플 생성 → ⑤ 충실도(Fidelity, 통계적 유사성) 및 유용성(Utility, 다운스트림 모델 성능) 평가 → ⑥ 재식별 위험도(Privacy Risk, 멤버십추론공격 저항성) 평가 → ⑦ 배포 및 모니터링(Drift 관리).

**(3) 적용 기술/표준**  
차분 프라이버시(Differential Privacy)를 생성모델에 결합한 DP-GAN 기법으로 프라이버시 보장 수준 정량화(ε값), Synthetic Data Vault(SDV) 등 오픈소스 프레임워크 활용, ISO/IEC 및 국내 개인정보보호위원회의 가명·합성데이터 활용 가이드라인, NIST의 합성데이터 품질평가 지표(SDMetrics) 적용.

**(4) 기존 비식별화(가명처리/익명화) 기술과의 비교**

| 구분 | 가명처리/익명화 | 합성데이터 |
|---|---|---|
| 원본연관성 | 원본 데이터 변형(연결 가능) | 원본과 직접 매핑 없음(신규 생성) |
| 재식별위험 | 결합/추론공격 위험 존재 | 상대적으로 낮음(모델 설계에 따라 상이) |
| 데이터 유용성 | 변형에 따른 정보손실 | 통계적 특성 보존율 높음 |
| 데이터량 확장 | 불가(원본 수량 고정) | 무제한 확장 생성 가능 |

**4. 활용분야 및 사례**  
- 금융권: 이상거래(사기) 탐지 모델 학습용 희소 사기 패턴 데이터 증강  
- 의료: 희귀질환 영상데이터 합성을 통한 진단 AI 모델 학습(환자정보 노출 없이)  
- 자율주행: 시뮬레이션 기반 극한 주행 시나리오(사고 직전 상황) 합성데이터 생성  
- 공공: 통계청 등의 마이크로데이터 합성데이터 공개(연구목적 2차활용)  
- 제조: 결함 이미지 부족 문제 해결을 위한 불량품 합성 이미지 생성

**5. 기대효과 및 고려사항/전망**  
**기대효과**: 개인정보 노출 없는 데이터 공유·거래 활성화, AI 학습 데이터 확보 비용·시간 단축, 데이터 불균형 해소를 통한 모델 성능 개선, 규제 준수와 데이터 활용의 균형 달성.  
**고려사항**: 생성모델의 편향(Bias)이 합성데이터에 그대로 반영·증폭될 위험, 완전한 프라이버시를 보장하지 않으며 멤버십 추론 공격 등 재식별 가능성 존재, 원본 데이터의 이상치(Outlier)·희귀패턴이 소실되는 충실도 저하 문제, 생성모델 학습 자체에 상당한 컴퓨팅 자원 소요.  
**향후전망**: 차분 프라이버시와 결합한 정량적 프라이버시 보장 기법 고도화, 멀티모달(텍스트-이미지-정형데이터 통합) 합성데이터 생성 확산, Foundation Model 기반 범용 합성데이터 생성 플랫폼 등장, 데이터 마켓플레이스에서 합성데이터 거래 표준화가 예상된다.

### 29. 가상융합산업 진흥법

**개요**: 가상융합산업 진흥법은 메타버스 등 가상융합기술·서비스의 육성과 이용자 보호를 위해 제정된 법률로, XR·메타버스 산업 생태계 조성 및 신뢰기반 확산을 목적으로 함. 국내 메타버스 산업 활성화와 글로벌 경쟁력 확보 필요성에 따라 추진됨.

**주요 내용**  
| 구분 | 내용 |
|---|---|
| 정의 | 가상융합기술(VR·AR·MR·XR 등 실감기술), 가상융합산업 개념 법제화 |
| 진흥계획 | 정부의 기본계획 수립·시행, 실태조사 실시 |
| 산업지원 | 기술개발, 표준화, 창업·중소기업 지원, 융합인재 양성 |
| 이용자보호 | 부작용(중독, 저작권 침해, 사생활 침해) 방지 시책 마련 |
| 클러스터 | 가상융합산업 진흥시설·클러스터 지정 지원 |

**상세**: 과기정통부 주관으로 메타버스 윤리원칙, 안전한 가상융합서비스 확산기반 마련을 병행하며, 기존 정보통신융합법·콘텐츠산업진흥법 등과의 정합성을 고려해 제정 추진됨.

**기대효과 및 고려사항**: 메타버스 산업 투자활성화, 실감콘텐츠 경쟁력 강화 기대되나, 가상자산·아이템 거래의 법적성격 불명확, 메타버스 내 범죄행위 규율체계 미비 등 후속 법제 정비가 병행되어야 함.

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 30. HNDL(Harvest Now, Decrypt Later) 공격

**1. 개요**  
- 정의: 현재는 해독 불가한 암호화 데이터를 대량 수집·저장한 후, 향후 양자컴퓨터 등 해독역량 확보시점에 사후 복호화하는 공격 기법  
- 배경: RSA·ECC 등 공개키 암호는 Shor 알고리즘 기반 양자컴퓨터로 다항시간 해독 가능하다는 이론적 취약성 존재, 장기보관 필요 민감정보(국방·의료·금융)에 실질적 위협으로 부상

**2. 특징**  
| 구분 | 내용 |
|---|---|
| 공격시점 이원화 | 수집(현재)-해독(미래)이 시간적으로 분리 |
| 대상 데이터 | 장기 기밀성 요구 데이터(국가기밀, 개인정보, 지재권) |
| 위협원천 | CRQC(Cryptographically Relevant Quantum Computer) 출현 |
| 탐지 어려움 | 수집행위 자체는 정상 네트워크 트래픽과 구분 어려움 |

**3. 상세 설명**  
- 공격절차: ①암호화 트래픽/저장데이터 무차별 수집 및 아카이빙 → ②양자컴퓨터 상용화 대기 → ③Shor알고리즘 등으로 RSA/ECC 개인키 역산 → ④과거 수집 데이터 일괄 복호화  
- 위험성: 데이터의 유효기간(비밀유지 필요기간)이 양자컴퓨터 실현시점보다 길 경우 실질적 피해로 직결(예: 30년 보관 국가기밀)  
- 근본 취약점: 현행 PKI가 소인수분해·이산대수 문제의 계산적 난이도에 기반, 양자 알고리즘 앞에서 안전성 붕괴

**4. 기대효과 및 고려사항(대응방안)**  
- PQC(Post-Quantum Cryptography) 전환: NIST 표준화(CRYSTALS-Kyber/Dilithium 등) 알고리즘 조기 도입  
- 하이브리드 암호화: 기존 암호+PQC 병행 적용으로 전환 리스크 완화  
- 암호이전 로드맵(Cryptographic Agility) 수립, 장기보관 데이터 우선 재암호화 및 양자내성 키관리체계 구축 필요

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 31. 피지컬AI(Physical AI)

**1. 개요**  
- 정의: 디지털 공간의 인지·추론 능력을 갖춘 AI가 로봇·자율기기 등 물리적 실체(Embodiment)에 결합되어 현실세계를 인지·판단·행동하는 AI 패러다임  
- 배경: 기존 생성형AI가 텍스트·이미지 등 디지털 영역에 국한된 한계를 넘어, 센서·액추에이터를 통해 실세계와 상호작용하는 Embodied AI로 진화 요구 증대됨

**2. 특징 및 구성요소**  
| 구성요소 | 내용 |
|---|---|
| 인지(Perception) | 카메라·라이다·센서로 환경정보 수집 |
| 판단(Reasoning) | Foundation Model 기반 상황이해·계획수립 |
| 행동(Action) | 로봇팔·모빌리티 등 액추에이터로 물리적 실행 |
| 학습 | 시뮬레이션(디지털트윈) 기반 강화학습 및 Sim-to-Real 전이 |

**3. 상세 설명**  
- 핵심원리: 인지-판단-행동 루프(Perception-Cognition-Action Loop)를 실시간 폐루프로 구성, 멀티모달 파운데이션 모델이 상황판단 담당  
- 학습방식: 실물학습의 비용·위험 한계를 극복하기 위해 가상시뮬레이터(Omniverse 등)에서 대량 학습 후 실제 로봇에 전이(Sim-to-Real)  
- 적용분야: 자율주행, 산업용 협동로봇, 물류자동화, 휴머노이드 등  
- 기존AI와 차이: 디지털AI는 정보처리에 국한되나, 피지컬AI는 물리법칙·불확실성이 존재하는 실세계에서 즉시 행동결과가 발생

**4. 기대효과 및 고려사항**  
- 효과: 제조·물류·돌봄 등 노동집약산업의 자동화 고도화, 위험작업 대체  
- 고려사항: 실세계 오작동시 안전사고 직결되므로 Safety Layer 및 인간개입(HITL) 체계 필수, 대규모 실물데이터 수집·표준화 과제 존재

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 32. OT 환경의 제로트러스트의 필요성 및 핵심원칙

**1. 개요**  
- 정의: OT(Operational Technology, 산업제어시스템) 환경에 "암묵적 신뢰 배제, 모든 접근을 지속적으로 검증"하는 제로트러스트 원칙을 적용하는 보안모델  
- 필요성: IT-OT 융합(스마트팩토리) 확대로 폐쇄망 전제가 붕괴되었고, 랜섬웨어의 OT 침투·경계기반 보안의 한계가 노출되어 최소권한·지속검증 기반 보안체계 전환 필요

**2. OT-IT 환경 차이 및 적용 난제**  
| 구분 | IT 환경 | OT 환경 |
|---|---|---|
| 우선순위 | 기밀성(C) | 가용성(A)·안전성 |
| 시스템수명 | 3~5년 | 15~20년(legacy 다수) |
| 패치/인증 | 상시 가능 | 실시간성 저해로 제약 |
| 프로토콜 | 표준(TCP/IP) | Modbus 등 인증기능 부재 프로토콜 |

**3. 핵심원칙**  
- 명시적 검증(Verify Explicitly): 모든 사용자·디바이스·엔지니어링 워크스테이션 접근시 신원·상태 지속 인증  
- 최소권한 접근(Least Privilege): 운전원·정비자별 세분화된 권한부여, Just-In-Time 접근 적용  
- 마이크로세그멘테이션: PLC·HMI·SCADA 등 자산군을 네트워크 존(Zone)/컨듀잇(Conduit)으로 분리, 측방이동(Lateral Movement) 차단(IEC 62443 연계)  
- 위반가정(Assume Breach): 침해를 전제로 지속적 트래픽 모니터링·이상행위 탐지 및 자동격리 체계 구축  
- 가시성 확보: 자산 전수조사(Asset Inventory) 및 OT전용 이상탐지솔루션 연계

**4. 기대효과 및 고려사항**  
- 효과: 랜섬웨어 등 IT발 위협의 OT 확산 차단, 공급망·원격유지보수 접근 리스크 최소화  
- 고려사항: 가용성 저해 없는 인증체계 설계, 레거시 장비의 인증기능 부재 보완(게이트웨이 기반 프록시 인증), 단계적 도입 로드맵 필요

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 33. GPUaaS(GPU as a Service)

**1. 개요**  
- 정의: 클라우드 사업자가 GPU 자원을 가상화 또는 물리적으로 제공하여 사용자가 필요 시점에 온디맨드 방식으로 임대·사용하는 클라우드 서비스 모델임  
- 등장배경: AI/딥러닝 학습·추론 수요 급증에 따른 고비용 GPU 인프라 자체 구축의 부담을 경감하고, 탄력적 자원활용 필요성에서 등장함

**2. 제공유형 및 구성요소**

| 유형 | 내용 |
|---|---|
| Bare-metal GPU | 물리 GPU 서버 전용 할당 |
| vGPU(가상화) | 하나의 물리GPU를 다중 사용자 분할 |
| MIG(Multi-Instance GPU) | GPU 내부 하드웨어 파티셔닝 |
| Serverless GPU | 함수 단위 초단기 GPU 과금 |

**3. 상세 설명**  
- 핵심기술: GPU 가상화(NVIDIA vGPU, MIG), 컨테이너 오케스트레이션(K8s+GPU Operator), 원격 GPU 풀링, 과금은 사용시간/자원단위(vCPU-GPU 결합) 기준  
- 서비스 형태: IaaS형(EC2 P/G시리즈 등 인스턴스 임대), PaaS형(관리형 학습 플랫폼), Serverless형(함수 단위 추론)으로 세분됨  
- 주요 사업자: AWS, Azure, GCP 외 특화 GPU 클라우드(CoreWeave, Lambda Labs 등)가 시장 확대 중

**4. 기대효과 및 고려사항**  
- 기대효과: 초기 CAPEX 절감, 필요시점 확장(Elasticity)으로 자원효율 극대화, 최신 GPU 신속 도입 가능  
- 고려사항: 데이터 반출에 따른 보안/규제 이슈, 벤더 종속(Lock-in), 사용량 급증 시 비용 최적화 필요, 멀티테넌시 환경의 자원격리 보안

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 34. KCMVP(Korea Cryptographic Module Validation Program)

**1. 개요**

**가. 정의**  
KCMVP는 국가정보원이 주관하고 국가보안기술연구소(NSR)가 시험을 수행하는 국내 암호모듈 검증제도로서, 공공기관 및 국가·군사기밀을 취급하는 정보통신시스템에 사용되는 암호모듈이 국가가 정한 안전성 기준(암호알고리즘 구현의 정확성, 키관리, 물리적 보안 등)을 충족하는지 검증·인증하는 제도이다.

**나. 등장배경**  
전자정부법, 국가정보화기본법 등에 따라 공공기관의 정보시스템 보안 요구가 강화되면서, 해외 암호모듈(미국 FIPS 140-2/3, CMVP)에 대한 검증 없이 도입될 경우 백도어·취약점 삽입 등 보안 통제가 불가능한 문제가 제기되었다. 이에 국가차원의 자체 암호 검증체계 필요성이 대두되어, 국정원이 2005년부터 국내 자체 개발 암호알고리즘(SEED, ARIA, HIGHT 등) 및 국제표준 알고리즘의 구현물을 대상으로 KCMVP를 운영하기 시작하였다.

**다. 필요성 및 목적**  
- 공공기관 및 국가기밀 취급시스템에 사용되는 암호모듈의 무결성·신뢰성 확보  
- 국산 암호알고리즘(SEED, ARIA, LEA 등) 생태계 육성 및 자립적 암호기술 주권 확보  
- 암호모듈 구현 오류, 부채널 공격 취약점 등 사전 검증을 통한 보안사고 예방

**2. 특징 및 구성요소**

```
[KCMVP 검증 체계도]
   신청기관(암호모듈 개발사)
        │ 검증신청
        ▼
┌───────────────────────────┐
│  국가정보원(NIS) - 주관/인증│
├───────────────────────────┤
│  국가보안기술연구소(NSR)    │
│  - 시험수행기관(시험실)     │
├───────────────────────────┤
│  시험항목                  │
│  ①알고리즘 정확성 시험      │
│  ②키관리 시험              │
│  ③물리적보안 시험          │
│  ④부채널공격 대응성 시험    │
└───────────────────────────┘
        │ 검증완료
        ▼
   검증필 암호모듈 목록 등재
        │
        ▼
   공공기관/국가기밀시스템 도입 의무화
```

| 구성요소 | 내용 |
|---|---|
| 검증대상 | 소프트웨어/하드웨어/펌웨어 형태의 암호모듈 |
| 적용 알고리즘 | SEED, ARIA, LEA, HIGHT(국산) 및 AES, RSA, ECC 등(국제표준) |
| 검증항목 | 알고리즘구현, 키생성/관리, 물리적보안, 자가시험, 부채널대응 |
| 검증등급 | 등급 미분류(적합/부적합 판정, 미국 FIPS과 달리 Level 구분 없음) |
| 유효기간 | 검증 유효기간 존재, 알고리즘 취약점 발견시 재검증/폐지 |

**3. 상세 설명**

**(1) 핵심 원리/체계**  
KCMVP는 "국가정보원(정책/인증 주관)-국가보안기술연구소(기술시험 수행)"의 이원 체계로 운영되며, 암호모듈이 미리 정의된 시험기준(암호알고리즘 명세 준수여부, 키 관리 생명주기의 안전성, 하드웨어의 물리적 침해 방지, 오류주입/전력분석 등 부채널 공격 저항성)을 통과해야 최종 검증필 목록에 등재된다. 이는 국가 표준 암호기술의 실제 구현물에 대한 사후 신뢰성 보증체계로 기능한다.

**(2) 동작 절차/검증 프로세스**  
① 개발사가 암호모듈 및 관련 문서(설계서, 소스코드, 보안정책서) 제출하여 검증 신청 → ② NSR이 알고리즘 구현 정확성 시험(테스트 벡터 기반 검증) 수행 → ③ 키 생성·분배·저장·파기 등 키관리 전 생명주기 안전성 시험 → ④ 물리적 보안시험(하드웨어 모듈의 경우 탬퍼 방지 설계 확인) → ⑤ 부채널 공격(전력분석, 타이밍공격) 대응성 시험 → ⑥ 시험결과를 국정원에 제출, 최종 검증 및 인증서 발급 → ⑦ 검증필 암호모듈 목록에 등재, 이후 취약점 발견시 재검증 또는 등재 취소.

**(3) 적용 기술/표준**  
국산 표준 알고리즘(대칭키: SEED, HIGHT, LEA / 공개키: KCDSA / 해시: HAS-160, LSH)의 KS 및 TTA 표준 연계, 국제표준(AES, RSA, ECC, SHA-2) 구현체에 대한 검증도 포함, 국가정보보안기본지침 및 암호모듈 시험기준(국정원 고시)에 근거, 미국 FIPS 140-2/3 CMVP와 유사한 취지이나 국내 독자 운영체계로서 상호인정협정은 미체결.

**(4) 미국 CMVP(FIPS 140-3)와의 비교**

| 구분 | KCMVP(한국) | CMVP(미국, FIPS 140-3) |
|---|---|---|
| 주관기관 | 국가정보원/국가보안기술연구소 | NIST/CSE(미국-캐나다 공동) |
| 검증등급 | 적합/부적합(등급 비구분) | Level 1~4 등급 구분 |
| 적용알고리즘 | SEED, ARIA, LEA 등 국산 포함 | AES, RSA 등 국제표준 중심 |
| 적용대상 | 국내 공공기관/국가기밀시스템 | 미국 연방기관 정보시스템 |
| 국제상호인정 | 제한적(단독운영) | 일부 동맹국과 상호인정 |

**4. 활용분야 및 사례**  
- 전자정부시스템: 행정전자서명(GPKI), 온나라시스템 등 공공정보시스템의 데이터 암호화 모듈  
- 국방/군사통신: 국방망 보안장비, 군용 암호통신장비의 검증필 암호모듈 탑재  
- 금융/공공 인증서: 공동인증서(구 공인인증서) 발급체계의 암호모듈  
- 네트워크 보안장비: VPN, 방화벽 등 공공기관 도입 보안장비의 KCMVP 검증필 모듈 채택  
- 국가기밀 취급시스템: 대북/외교 등 특수 목적 시스템의 자체 개발 암호모듈

**5. 기대효과 및 고려사항/전망**  
**기대효과**: 공공부문 암호기술의 신뢰성·안전성 확보를 통한 국가 사이버보안 강화, 국산 암호알고리즘 생태계 활성화로 암호기술 자주권 확보, 검증 실패 사례를 통한 국내 암호모듈 개발사의 보안 구현 역량 향상.  
**고려사항**: 국제 CMVP와의 상호인정 부재로 해외 진출시 이중 검증 부담 발생, 등급 미분류 체계로 인해 미국 FIPS 대비 세분화된 보안수준 요구가 어려운 한계, 검증 절차의 소요기간(통상 수개월~1년) 및 비용으로 중소기업 부담 가중, 최신 경량암호(IoT용)·PQC 알고리즘에 대한 검증기준 정비 필요성.  
**향후전망**: 양자내성암호(PQC) 표준화(국내 KpqC 공모전 진행)에 따른 검증 대상 확대 및 관련 시험기준 마련, 클라우드·컨테이너 환경의 소프트웨어 암호모듈 검증체계 고도화, 국제 상호인정 협정 확대를 통한 글로벌 호환성 개선, IoT·경량기기 대상 경량암호 검증 트랙 신설이 예상된다.

### 35. 소버린 클라우드(Sovereign Cloud)

**1. 개요**

**가. 정의**  
소버린 클라우드는 특정 국가 또는 조직이 데이터의 저장·처리·이동에 대한 완전한 통제권(데이터 주권, Data Sovereignty)을 확보하기 위하여 자국의 법률·규제 체계와 독립적인 인프라(데이터센터, 운영인력, 관제체계)를 기반으로 외부(특히 역외 정부·기업)의 관할권 개입 없이 자체 운영하는 클라우드 서비스 모델이다.

**나. 등장배경**  
미국의 CLOUD Act(2018)는 미국 클라우드 사업자가 데이터 저장 위치와 무관하게 미 정부의 데이터 제출 요구에 응해야 함을 규정하여, 글로벌 하이퍼스케일러(AWS, Azure, GCP)를 이용하는 타국 정부·기업의 데이터가 역외 정부에 노출될 법적 위험이 부각되었다. 이에 EU의 GDPR 및 Gaia-X 프로젝트, 프랑스의 SecNumCloud, 국내 클라우드컴퓨팅법 등 데이터 지역화(Data Localization) 규제가 강화되며 소버린 클라우드 수요가 확산되었다.

**다. 필요성 및 목적**  
- 국가기밀·공공데이터·주요정보통신기반시설의 역외 유출 및 외국 정부 접근 차단  
- 자국 법률(개인정보보호법 등) 준수 및 규제 관할권 확보  
- 특정 벤더/국가 의존(Lock-in)에서 벗어난 기술·전략적 자주성 확보

**2. 특징 및 구성요소**

```
[소버린 클라우드 구성 계층도]
┌─────────────────────────────────────┐
│  법률/거버넌스 계층                   │
│  (자국법 적용, 역외이전 금지, 감독기구)│
├─────────────────────────────────────┤
│  운영/인력 계층                       │
│  (내국인 운영, 자국내 보안관제(SOC))  │
├─────────────────────────────────────┤
│  인프라 계층                          │
│  (자국내 IDC, 독립망, 자국산 HW/SW)   │
├─────────────────────────────────────┤
│  보안/암호 계층                       │
│  (국가검증 암호모듈, 자체 KMS/HSM)    │
└─────────────────────────────────────┘
```

| 구성요소 | 세부내용 |
|---|---|
| 데이터 거주성 | 자국 내 데이터센터에 저장·처리(Data Residency) |
| 법적 관할권 | 역외법(CLOUD Act 등) 배제, 자국법 우선 적용 |
| 운영주권 | 자국 인력에 의한 운영·유지보수·관제 |
| 기술주권 | 자국산 하드웨어/소프트웨어, 국산 암호모듈 사용 |
| 접근통제 | 외국 정부·기업의 접근 원천 차단(Zero Foreign Access) |

**3. 상세 설명**

**(1) 핵심 아키텍처/원리**  
소버린 클라우드는 물리적 인프라 격리(자국 내 IDC), 논리적 격리(자국 관할 법인이 운영하는 별도 리전/계정체계), 운영적 격리(외국인 접근 통제, 내국인 전담 운영팀)의 3단계 격리모델로 구성된다. 글로벌 CSP와 협력하는 경우에도 현지 파트너사가 별도 법인을 설립하여 운영권·소유권을 분리하는 "로컬 파트너 운영형(Local Partner Model)"과, 순수 자국 기업이 독자 구축하는 "완전 자립형(Independent Model)"으로 구분된다.

**(2) 동작 절차/구축 프로세스**  
① 데이터 분류 및 주권 요구수준 정의(공공/민간, 등급별) → ② 법적 요건 분석(개인정보보호법, 클라우드보안인증(CSAP) 등) → ③ 자국 내 데이터센터 및 독립 네트워크 구축 → ④ 자국 검증 암호모듈(KCMVP 등) 및 KMS 적용 → ⑤ 접근통제 정책(외국인 접근 승인절차, 감사로그) 수립 → ⑥ 제3자 인증·감사(CSAP, SecNumCloud 등) 획득 → ⑦ 지속적 관제 및 규제 준수 모니터링.

**(3) 적용 기술/표준**  
암호화(자국 검증 알고리즘 기반 저장/전송 암호화), 기밀컴퓨팅(Confidential Computing, 처리 중 데이터 암호화), 자국 인증체계(국내 CSAP - 클라우드서비스 보안인증, 프랑스 SecNumCloud, 독일 C5), EU Gaia-X의 연방형 데이터 인프라 표준, 망분리 및 물리적 접근통제 기준(국내 공공기관 클라우드 전환 가이드라인).

**(4) 일반(퍼블릭) 클라우드와의 비교**

| 구분 | 퍼블릭 클라우드 | 소버린 클라우드 |
|---|---|---|
| 관할권 | 본사 소재국 법률 적용(역외법 노출) | 자국법 우선 적용 |
| 운영주체 | 글로벌 CSP 및 해외인력 관제 가능 | 자국 인력 전담 운영 |
| 데이터위치 | 글로벌 리전 자유 이동 | 자국 내 고정(Data Residency) |
| 비용/확장성 | 글로벌 규모의 경제로 저렴 | 상대적 고비용, 확장성 제한 |
| 적용대상 | 일반 상용 서비스 | 공공, 국방, 금융 등 민감분야 |

**4. 활용분야 및 사례**  
- 국내: 정부 공공부문 클라우드 전환(행정전자서명, 나라장터 등)의 CSAP 인증 클라우드 활용  
- EU: Gaia-X 프로젝트 기반 유럽 통합 데이터 인프라 및 프랑스 Bleu(MS-Orange/Capgemini 합작), S3NS(Google-Thales 합작)  
- 독일: T-Systems·SAP 등의 자국 데이터센터 기반 소버린 클라우드 서비스  
- 국방/안보: 국가기밀 취급 시스템, 국방통합데이터센터의 망분리 폐쇄형 클라우드  
- 금융: 금융권 클라우드 이용 가이드라인에 따른 국내 리전 한정 서비스 이용

**5. 기대효과 및 고려사항/전망**  
**기대효과**: 데이터 역외 유출 및 외국 정부 강제 접근 위험 원천 차단, 자국 규제 준수를 통한 법적 리스크 해소, 자국 클라우드 산업 및 IDC 생태계 육성, 국가 안보·공공 신뢰성 제고.  
**고려사항**: 글로벌 CSP 대비 규모의 경제 부족으로 비용 상승 및 최신 기술(AI/GPU) 도입 지연 가능성, 상호운용성 저하로 글로벌 서비스 연계 제약, 완전한 기술자립을 위한 초기 투자비용 부담, "주권"의 실질적 수준(단순 데이터거주 vs 완전운영자립)에 대한 국가별 상이한 기준.  
**향후전망**: 글로벌 CSP의 현지 파트너십 기반 하이브리드형 소버린 서비스 확대(MS·Google의 프랑스 합작 사례), AI 주권(Sovereign AI)까지 확장된 개념으로 진화, 국내 K-클라우드 정책 및 SaaS 생태계와 연계한 공공·금융 특화 소버린 클라우드 고도화가 전망된다.

### 36. DPU(Data Processing Unit)

**1. 개요**  
- 정의: CPU/GPU와 별도로 네트워킹·스토리지·보안 등 데이터센터 인프라 처리 작업을 오프로드하여 전담 처리하는 전용 프로세서임  
- 배경: 클라우드·AI 워크로드 증가로 CPU가 인프라 오버헤드(패킷처리, 암복호화 등) 처리에 과부하 발생, 코어 자원의 애플리케이션 집중 필요성 증대에 따라 등장함

**2. 구성요소 및 비교**  
| 구분 | CPU | GPU | DPU |
|---|---|---|---|
| 역할 | 범용연산/제어 | 병렬연산(AI/그래픽) | 인프라 오프로드 전담 |
| 핵심요소 | 범용코어 | 다수 SIMD코어 | ARM코어+SmartNIC+가속엔진 |
| 처리대상 | OS/App | 행렬연산 | 네트워킹,스토리지,보안 |

- 주요구성: ①프로그래머블 네트워크 인터페이스(SmartNIC) ②멀티코어 ARM 프로세서 ③암복호화/압축 가속엔진 ④가상스위치(vSwitch) 오프로드 엔진

**3. 상세 설명**  
- 동작원리: 호스트 CPU 개입 없이 패킷 파싱, TCP/IP 처리, 스토리지 I/O(NVMe-oF), TLS/IPsec 암복호화를 하드웨어 가속으로 직접 처리(East-West 트래픽 오프로드)  
- 대표사례: NVIDIA BlueField, Intel IPU(Infrastructure Processing Unit), AMD Pensando  
- SmartNIC과 차이: SmartNIC은 네트워크 기능 위주, DPU는 독립 OS 구동 가능한 완전한 인프라 컨트롤 플레인 보유

**4. 기대효과 및 고려사항**  
- 기대효과: CPU 자원 애플리케이션 전용화, 데이터센터 성능/전력효율 향상, 제로트러스트 보안 강화, TCO 절감  
- 고려사항: 표준화된 프로그래밍 모델(DOCA 등) 부재, 초기 도입비용, 기존 인프라와의 호환성 검증 필요

### 37. 멀티 에이전트 시스템(Multi Agent System)

**1. 개요**  
- (정의) MAS는 자율적으로 판단·행동하는 다수의 AI 에이전트가 상호 통신·협업하여 복잡한 업무를 분업 수행하는 시스템임  
- (배경) 생성형 AI·LLM 고도화로 단일 에이전트의 처리범위·정확도 한계를 극복하고, 반복적·정형화된 업무 자동화를 넘어 판단이 필요한 복합업무 자동화 요구 증대에 따라 확산됨

**2. 구성요소**  
- Orchestrator(작업분배·조정), Worker Agent(역할별 전문 에이전트), 통신프로토콜(MCP, A2A 등), 공유메모리·컨텍스트, 외부 Tool/API 연동모듈

**3. 상세설명**  
- (협업구조 유형) 계층형(Supervisor-Sub agent), 수평형(Peer-to-Peer), 파이프라인형(순차처리)으로 구분  
- (동작원리) 목표수신→작업분해(Task Decomposition)→역할별 에이전트 할당→병렬/순차 수행→결과통합 및 검증  
- (기존 방식과의 차이) RPA·단일 챗봇은 사전정의 규칙 기반 처리에 한정되나, MAS는 동적 상황판단과 에이전트간 자율적 협업·재조정이 가능함

**4. 기대효과 및 고려사항**  
- (기대효과) 부서간 경계 완화 및 업무 프로세스 재설계, 의사결정 자동화를 통한 생산성·처리속도 향상, 인적자원의 고부가가치 업무 전환  
- (고려사항) 에이전트간 오류 전파(Hallucination 확산) 방지, 보안·거버넌스 체계 마련, 핵심 의사결정에 대한 Human-in-the-loop 적용, 책임소재 명확화 필요

*(학습토픽 100선 답안 재사용 - 1교시 단답형 수준)*

### 38. 양자AI(Quantum AI)

**1. 개요**  
- 정의: 양자컴퓨팅의 중첩(Superposition)·얽힘(Entanglement)·양자병렬성을 AI/머신러닝에 결합하여 연산을 가속화하거나 새로운 알고리즘을 구현하는 융합기술 분야임(양자머신러닝(QML)을 포괄하는 상위개념)  
- 배경: 빅데이터·고차원 모델 학습의 연산량 폭증으로 고전컴퓨팅의 물리적 한계 도달, NISQ(Noisy Intermediate-Scale Quantum) 시대 도래에 따라 융합 필요성 증대

**2. 유형 및 구성요소**  
| 유형 | 내용 |
|---|---|
| 양자머신러닝(QML) | 변분양자회로(VQC) 기반 분류/회귀 |
| 양자강화학습(QRL) | 양자 상태공간 탐색 기반 정책학습 |
| 양자최적화 | QAOA, 조합최적화 문제 해결 |
| 양자신경망(QNN) | 큐비트 게이트 기반 신경망 구조 |
| 양자생성모델 | 양자 GAN, 양자 볼츠만머신 |

**3. 상세 설명**  
- 핵심원리: 큐비트의 중첩으로 지수적 상태공간 동시 표현, 얽힘으로 상관관계 내재적 인코딩, 양자병렬성으로 다중 연산 동시수행  
- 핵심 알고리즘: HHL(선형방정식 가속), Grover(탐색가속), VQE/QAOA(변분최적화)  
- 구현방식: 하이브리드(고전-양자) 구조로 양자프로세서는 특정 서브루틴만 처리, 고전컴퓨터가 파라미터 최적화 담당

**4. 기대효과 및 고려사항**  
- 기대효과: 신약개발·소재설계·금융최적화 등 조합폭발 문제 해결, 학습속도 지수적 가속 가능성  
- 고려사항: 큐비트 디코히런스(결함), 오류보정 비용, 실용적 양자우위(Quantum Advantage) 미입증 사례 다수, 하이브리드 아키텍처 설계역량 필요

### 39. 지식 그래프(Knowledge Graph)

**1. 개요**  
- 정의: 개체(Entity)와 개체 간 관계(Relation)를 노드와 엣지로 표현하여 지식을 구조화한 그래프형 데이터베이스로, 온톨로지 기반 추론이 가능함  
- 배경: 비정형데이터 급증과 LLM의 환각(Hallucination) 문제 심화로, 사실기반 구조화 지식을 통한 검증가능한 추론 및 최신정보 보강 필요성 증대

**2. 구성요소**  
| 구성요소 | 내용 |
|---|---|
| 노드(Node) | 개체(인물, 사물, 개념) |
| 엣지(Edge) | 개체 간 관계(속성) |
| 트리플 | (주어-서술어-목적어) 구조 |
| 온톨로지 | 개체/관계 스키마 정의(RDF, OWL) |
| 질의언어 | SPARQL, Cypher |

**3. 상세 설명**  
- 구축절차: 엔티티 추출→관계 추출(NER/RE)→온톨로지 매핑→중복제거/정제→그래프 저장(Neo4j 등)  
- LLM 결합(GraphRAG): 질의 시 벡터검색(Dense Retrieval) 대신/병행하여 KG 서브그래프를 탐색, 관련 트리플을 컨텍스트로 프롬프트에 주입하여 응답 생성 → 근거기반 답변 및 멀티홉 추론 가능  
- 기존 RAG(단순 문서청크 검색) 대비 개체간 관계 추론 및 최신성 갱신 용이

**4. 기대효과 및 고려사항**  
- 기대효과: LLM 환각 완화, 설명가능성(Explainability) 확보, 도메인 지식 최신화 용이, 멀티홉 복합추론 지원  
- 고려사항: 초기 구축비용/전문인력 필요, 온톨로지 스키마 설계 복잡성, 데이터 품질 및 일관성 관리, 그래프 규모확장 시 질의성능 저하

### 40. 머신 언러닝(Machine Unlearning)

**1. 개요**  
- 정의: 이미 학습이 완료된 모델에서 특정 학습데이터의 영향을 선택적으로 제거하는 기술임  
- 배경: GDPR 등 개인정보보호 규제상 "잊혀질 권리(Right to be Forgotten)" 요구 확산, 저작권 침해 데이터·유해/편향 데이터 제거 필요성 증대, 매회 전체 재학습의 비용/시간적 비효율 해소 필요

**2. 유형**  
| 유형 | 방식 | 특징 |
|---|---|---|
| 완전 언러닝(Exact) | 대상 제외 후 재학습 | 정확하나 비용 高 |
| 근사 언러닝(Approximate) | 파라미터 근사 조정 | 효율적, 검증 어려움 |
| SISA 기반 | 데이터 샤딩/슬라이싱 | 부분 재학습으로 효율화 |

**3. 상세 설명**  
- 핵심기법: ①SISA(Sharded, Isolated, Sliced, Aggregated) - 데이터 분할학습 후 대상 샤드만 재학습 ②영향함수(Influence Function) 기반 파라미터 역보정 ③그래디언트 역전(Gradient Ascent)으로 특정 데이터 기여도 상쇄  
- 수행절차: 삭제요청 접수→대상데이터 식별/매핑→언러닝 알고리즘 수행→모델 성능 및 삭제효과 검증(Membership Inference Attack 등으로 잔존여부 확인)  
- 검증 어려움: 완전삭제 여부를 수학적으로 증명하기 어려워 확률적/통계적 검증에 의존

**4. 기대효과 및 고려사항**  
- 기대효과: 개인정보보호 규제 준수, 유해/편향 데이터 신속 제거로 모델 안전성 확보, 재학습 비용 절감  
- 고려사항: 삭제검증 표준방법론 부재, 삭제 시 전체 모델성능 저하(Catastrophic Forgetting) 트레이드오프, 대규모 LLM 적용시 확장성 한계
